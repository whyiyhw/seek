## 1. 论题

LLM 是 core，seek 是适配 core、让它干活顺手的壳。v8 押两件事：

- **core 变强，壳变薄。** 内核只留 core 不该自己决定的东西和它离不开的几样；其余全部外置成外围，由 core 按需选用。
- **形态由数据筛出来。** 壳的每个零件都要能度量、能拆掉对照；core 用得顺而且结果好的留下，其余外移或删除。

v0–v6 的骨架多数是补 Claude Code 的差距移植来的（`v7.md` 开头）。真正从 core 长出来的只有前缀缓存纪律和工具描述调优（`eval/README.md` 调优表）。v8 要把后一类变成常规做法。

## 2. 现状证据（2026-11-17）

- **产能远超验证**：近 30 天 279 个 commit；butler 巡检的验证存疑率 24.3%（45/222）；看板堵点在人侧。
- **没有一次过率**：`autopilot.Outcome` 没有成本和 diff 摘要，`Report` 只有 done/failed 计数（`internal/autopilot/autopilot.go:41`）。
- **没有摩擦数据**：stats 只有缓存命中率和成本（`internal/rpc/methods/stats.go`）。
- **外围是全量挂载**：MCP 工具在启动时全部注册（`internal/tools/mcptool/bridge.go:75`）。
- **体量**：非测试 Go 约 6.9 万行；按包名粗估，内核约 1.1 万行。

## 3. 不变量

- **I1 边界、记录、裁判、缓存拼装留在内核。** 不交给 core 选，也不放在 core 改得到的地方。
- **I2 agent 进程是一次性的。** 状态全在 transcript，任意时刻可杀可续；常驻进程只做监听、路由、拉起（`seek serve` 现状）。这是对"零 daemon"的精确化，见 §6 D2。
- **I3 外围按"索引 + 按需"暴露。** 会话开头冻结一份短索引，正文经工具结果追加在对话末尾；会话中途不改工具集。
- **I4 自动化不越过人审闸。** 试验田里 core 可以改壳，晋升进 main 由人决定。
- **I5 继承**：前缀缓存字节确定性、单二进制、编译期注册、`pkg/deepseek` 零依赖、每版一刀减法。

**内核清单（2026-11-19 修订，2026-11-20 复检补收 budget——「U1 出数后修订」占位已兑现，逐条定性见 §9.6）**：`pkg/deepseek`、`pkg/agent`、`pkg/llm`（**只收接口层**；`pkg/llm/provider/*` 实现留外围）、`internal/{session,permission,sandbox,worktree,cache,pricing,budget,modelcap,config,paths,bgjob,childenv,diff,fsobserve}`、`internal/tools` 根包及 `read/edit/write/bash/grep`。机器可读副本 = `scripts/kernel-packages.txt`（23 包，`scripts/kernel-deps.sh` 的唯一输入）；清单与本文必须同步改。

**准入规则（本卡新立，防违例清单再涨成噪声）**：一个包进内核，须同时满足 (a) 内核缺了它就**不正确或契约不完整**（不是"用着方便"）；(b) 收它**不新增**内核→外围边——即该包 in-module 依赖为零，或其邻居已在内核。会拖进外围的（`internal/hooks` → `hooksconfig` → `BurntSushi/toml`）一律**用内核侧窄接口倒置**，不收。

### 9.1 eval 车道的 key 与沙盒纪律（2026-11-18，card c_clip4i）

**规矩：无人值守（批量跑卡、常驻循环、steward 保底）一律假 key + 沙盒；真 key 仅两种合法情形——人工 `--only` 指名单跑，或卡面明示授权（写明哪张卡、谁批）。**

为什么：无人值守车道没有人看输出。真 key 是无预算上限的静默烧钱；真实 HOME 是双向泄漏——跑机器上的用户态（skills / memory / mcp.json / config.json 里的 key）混进测量样本，eval 的会话与 cadence 状态反过来污染真实用户态。实测（2026-11-18）：一次被假 key 在第一回合就 401 秒败的 seek 调用，仍向 `~/.seek` 写四处（dream-state.json、`projects/<id>/manifest.json`、`sessions/`、`cron/tick.lock`）——"跑失败了总不至于落下什么"不成立。

机制兜底（不靠自觉）：`eval/run.sh` 开头把 `SEEK_HOME` 钉进沙盒 `eval/tmp/seek-home`（gitignored；调用方自带非空值则原样尊重），并剥掉继承的 `SEEK_SESSIONS_DIR`（它在 `internal/session` `NewStore` 的解析阶梯里排在 SEEK_HOME 之上，残留值会绕过沙盒）。seek 全部用户态写入都经 `internal/paths.Home()` 解析，因此 eval 侧写真实 `~/.seek` 结构性不可能；ablate 双跑等一切经 run.sh 的车道自动继承。API key 走 env（`DEEPSEEK_API_KEY`，优先级高于 `$SEEK_HOME/config.json`）不受沙盒影响。机制与"真 HOME 零写入"由 `scripts/eval-home-isolation-test.sh` 钉死（selftest lane `eval-home-isolation-test`：假二进制机制断言 + 真二进制金丝雀 HOME 对照，对照组先证明金丝雀抓得到写入，隔离组再证明经 run.sh 后分毫不动）。附带收益：eval 测量默认 hermetic——不继承跑机器上的用户 skills / memory，跨机器可比。

### 9.5 R2 落地记录（2026-11-19，card c_cjewsn）

**实现**：`internal/verifier` 新包 + autopilot 咬合。verifier = 确定性证据层（跑测试、读 deliverable diff、主树隔离检查）→ 全新上下文裁判会话（单次 chat 调用，system prompt 为编译期常量 `prompt.go`）→ 钳制合成。verdict 三值 **pass/fail/doubt**：与 butler 四值分诊不对齐是有意的——ask_human 是跨系统治理层动作（seek 内环以 doubt+reason 表达），车道能力外类别在单进程内无意义。doubt 是诚实吸收态（裁判失败/测试跑不成/无断言任务全落 doubt），§9.1 存疑率按 Outcome/Report 的 verdict 计数复测。

**反欺骗是机械的**（过关标准的根据）：历史事故「worktree 隔离子代理把编辑写进主树、报告指向 worktree、测试全绿」已 fixture 化为 `TestRegression_MainTreePollutionWithGreenTestsIsFail`（素材=docs/pitfalls.md「Worktree-isolated subagent edited the MAIN tree」条 + 修复提交 c21167d，2026-05-31；butler 台账建账晚于事故故无记录）。机械不变量：①fleet 在任务 spawn 前拍主树快照（porcelain+numstat），verifier 结束时对照，漂移=fail——「绿色测试证明不了改动落在了哪」；②测试命令非零退出=fail、跑不成=doubt；③裁判 pass 必须引用 bundle 里真实存在的证据 id，否则降级 doubt；④任何机械 fail 钳制总判，裁判说什么都翻不动。回归用例里裁判被故意写成「全 pass 只引绿色测试」，verifier 仍判 fail 且证据点名 README.md——不能被测试全绿骗过是被测性质，不是巧合。

**配置位置（§8 ❌ 条款）**：裁判提示词是编译期常量，包内无任何文件/env/config 读取路径能改它；`TestPrompt_NotOverridableByCoreWritablePaths` 在 SEEK_HOME 与工作树各处埋诱饵文件（含 config.json/env 旁路）后断言线上 system 字节与常量逐字相等。选编译期常量而非独立路径的理由：core 会话的写达面覆盖仓库树与 SEEK_HOME，运行时读盘的配置都在其内；常量唯一改法是重编译，重编译本身就是人审动作。

**落位**：`autopilot.Outcome.Verdict`（逐断言行+不变量行+证据+时间戳+裁判 token 计）+ `Report.Verified{Pass,Doubt,Fail}` 计数 + Body 行尾 `verdict=<v>` 与头部计数；decomposer 任务 schema 加 `done_when`（1-6 条，缺省容忍→该任务 verdict 落 doubt）。verdict 只观察不翻 Status——晨审合并闸不动。触发面=每次任务完成按需（fleet.Run 内，非常驻），成本=每任务一次裁判 chat + 一次真实测试命令执行（cwd 钉 worktree、超时可杀、环境继承与 worker bash 同面）；无人值守假 key 下裁判 401 → doubt 不假 pass（`TestVerify_UnattendedFakeKeyIsDoubt`）。verifier 零磁盘写入——eval/run.sh 的 SEEK_HOME 沙盒契约（§9.1，`scripts/eval-home-isolation-test.sh` 口径）原样继承，结构性无新写入点。不退役旧机制：verifier 是 R1 证据字段面上的新列，晨审报告/合并闸/但书均不变。

#### 误报类判定理由（防将来反复——这是本卡唯一长期的产出）

- **违例数不是质量指标，是清单健康度指标。** 内核包 import 一个零依赖小工具包，通常说明**清单漏登了那个包**，而不是内核长歪了。看到违例先问"这个包该不该在内核"，再问"这条 import 该不该在"。
- **"零 in-module 依赖"是分水岭**：收它只加一行、不连锁；有 in-module 依赖的要顺着链走完（`hooks` 就这样被否掉），走不完就不收。
- **安全/裁判类依赖一律收编**（`childenv` 凭证闸、`fsobserve` 覆盖闸、`diff` 人审显示、`modelcap` 能力权威）——它们的定义就是"内核不能向外围问要不要守规矩"。**接口层与实现层分开判**：`pkg/llm` 接口是契约（收），`provider/*` 适配器是装配（留外围）。
