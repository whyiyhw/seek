### Windows Terminal forwards the IME-commit Enter — the 50ms paste guard turned Chinese messages into newlines
- **Saw**: on Windows Terminal, pressing Enter to send a Chinese message inserted a newline instead of submitting; sending needed two Enters.
- **Why**: `enterInsertsNewlineDuringPaste()` treats ANY Enter within 50ms of the last KeyRunes as a paste newline, but Windows Terminal delivers an IME-commit as the committed text AND the Enter that ended the composition in the same dispatch; second path: `lastInputRunesAt` is stamped at event-PROCESSING time, so a busy loop processes runes + Enter in microseconds.
- **Fix**: the guard now fires ONLY on legacy conhost: `m.legacyConhostInput`, detected in `tui.New()` via `paste.go:detectLegacyConhostInput` — `GOOS==windows` AND no terminal-emulator env var (`WT_SESSION`, `TERM_PROGRAM`, `ConEmuPID`); `SEEK_LEGACY_CONHOST_INPUT=1/0` overrides.
- **Lesson**: a time-window heuristic on "recent runes" cannot distinguish paste from IME-commit or busy-loop batches — scope it to the environment that needs it (conhost sets no identifying vars); bubbletea on Windows reads raw console events (coninput), so the guard is the only defense for non-bracketed paste.
