### Windows Terminal forwards the IME-commit Enter — the 50ms paste guard turned Chinese messages into newlines
- **Saw**: on Windows Terminal, Enter on a Chinese message inserted a newline; sending took two Enters.
- **Why**: `enterInsertsNewlineDuringPaste()` treats any Enter within 50ms of the last KeyRunes as a paste newline, but Windows Terminal delivers an IME-commit as the text AND the closing Enter in one dispatch; also `lastInputRunesAt` is stamped at event-PROCESSING time, so a busy loop handles runes + Enter in microseconds.
- **Fix**: the guard fires ONLY on legacy conhost — `m.legacyConhostInput`, set in `tui.New()` via `paste.go:detectLegacyConhostInput` (`GOOS==windows` AND no terminal-emulator env var: `WT_SESSION`, `TERM_PROGRAM`, `ConEmuPID`); `SEEK_LEGACY_CONHOST_INPUT=1/0` overrides.
- **Lesson**: a time window on "recent runes" can't tell paste from IME-commit or a busy loop — scope it to the environment that needs it (conhost sets no identifying vars); bubbletea on Windows reads raw console events (coninput), so the guard is the only defense for non-bracketed paste.
