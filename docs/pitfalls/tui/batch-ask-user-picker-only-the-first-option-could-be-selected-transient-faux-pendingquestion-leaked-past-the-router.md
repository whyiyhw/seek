### Batch ask_user picker: only the first option could be selected (transient faux pendingQuestion leaked past the router)
- **Saw**: multi-question `ask_user` picker: Enter on the default row (option 0) worked; any other option (arrow-key nav first) silently did nothing.
- **Why**: `handleBatchKey` installs a transient faux `m.pendingQuestion` per keypress with a private buffered `Reply` channel; its in-progress branch returned WITHOUT clearing the field; the router checked `pendingQuestion` before `pendingBatch`, so the next key completed into the previous keypress's orphaned channel. Option 0 escaped: it completes inside one `handleBatchKey` call.
- **Fix**: (1) router checks `pendingBatch` before `pendingQuestion`; (2) `handleBatchKey`'s in-progress branch sets `m.pendingQuestion = nil`. Either alone fixes; both = defense in depth.
- **Lesson**: a "borrow a field, delegate, restore" trick is safe only if the borrowed field is cleared on EVERY exit path. It only shows through the router across two keypresses (direct `handleBatchKey` tests rebuild the faux request, masking the leak), so `TestHandleKey_BatchSingleSelect_NonFirstOption` drives `handleKey`.
- **Refs**: `internal/tui/update_key.go:handleKey`, `internal/tui/update_modal.go:handleBatchKey`, `internal/tui/update_batch_test.go:TestHandleKey_BatchSingleSelect_NonFirstOption`
