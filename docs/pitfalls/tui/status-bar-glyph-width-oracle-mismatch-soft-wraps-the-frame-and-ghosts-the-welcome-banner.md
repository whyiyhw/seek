### Status-bar glyph-width oracle mismatch soft-wraps the frame and ghosts the welcome banner
- **Saw**: after `/model` switched to `deepseek-v4-flash-vision-exp`, the TUI showed the pixel banner TWICE — the previous frame's top block left behind when the repaint didn't reach it.
- **Why**: lipgloss and the terminal disagree 1–2 cols on ambiguous-width glyphs in the status bar (the frame's LAST line — ☀️ U+2600+VS16, ○ U+25CB render wider on CJK-locale Windows Terminal): the bar soft-wrapped onto 2 physical rows; the 10-col longer vision-exp id pushed it into the boundary band (widths 90–110; PowerShell default 100).
- **Fix**: foldStatusBar reserves a 2-col safety margin; RenderStatusBar draws width−2 with MaxWidth truncation; picker "(current)" moved off the `%-32s` id column into the description column; the offending glyphs were later removed (ASCII labels), pinned by `TestRenderStatusBar_NeverExceedsTerminalWidth` + `TestStatusBar_NoRetiredEmojiGlyphs`.
- **Lesson**: under inline bubbletea, any frame line whose terminal-measured width exceeds the frame width is a rendering-desync bomb — the ghost surfaces at the frame TOP from a wrap at the BOTTOM; validate against the strictest available measurer.
- **Refs**: `internal/tui/statusbar.go` (`foldStatusBar`, `RenderStatusBar`), `internal/tui/view.go` (`renderModelPicker`), observed on Windows Terminal zh-CN after /model → vision-exp
