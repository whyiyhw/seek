### Bubble Tea v2 migration: KeyMsg became an interface, paste became PasteMsg, teatest still pins v1
- **Saw**: v1.3.10 → charm.land/bubbletea/v2 (v2.0.8) broke every key-handling file: `msg.Type`/`msg.Runes`/`msg.Paste`/`tea.KeyCtrlC` gone, `View() string` → `View() tea.View`, upstream `teatest` refused to compile (go.mod pins v1.3.5).
- **Why**: v2 restructured input: `KeyMsg` is an interface over `KeyPressMsg`/`KeyReleaseMsg` (both the `Key` struct); `tea.KeyCtrlX` constants deleted; paste is a dedicated `tea.PasteMsg`; teatest had no v2 release, and Go cannot hold two bubbletea versions in one module graph.
- **Fix**: mechanical pass: `View()` wraps its string in `tea.NewView(...)`, key switches use `msg.String()`, `normalizeControlRunes` dropped its paste-passthrough branch, the `msg.Paste` block became `case tea.PasteMsg`, plus a local teatest layer (~230 lines); 28 files, 504 tests green.
- **Lesson**: `String()` is v2's migration-friendly surface — the string keymap survived unchanged; the traps are what it hides (space vs "space", Ctrl keys via Code+Mod); check the test-harness ecosystem first — a pinned-v1 teatest forces a local layer.
- **Refs**: `internal/tui/teatest/`, `internal/tui/keynorm.go`, `internal/tui/update.go`, UPGRADE_GUIDE_V2.md in charm.land/bubbletea/v2
