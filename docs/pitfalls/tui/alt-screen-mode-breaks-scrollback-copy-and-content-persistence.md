### Alt-screen mode breaks scrollback, copy, and content persistence
- **Saw**: running M4 with `tea.WithAltScreen()` accumulated symptoms — terminal scrollback dead (only an in-app viewport had history), copy worked only within the visible viewport, and exiting seek wiped the whole conversation.
- **Why**: alt-screen swaps the terminal to a secondary buffer with no scrollback by design — meant for full-screen apps (vim, less), the wrong trade for a chat-style agent whose users expect arbitrary scrollback, copy of any prior message, and the conversation remaining in the shell after exit.
- **Fix**: M4.5.1 switched to inline mode — `tea.WithAltScreen()` removed (commit `5d1c78c`), committed history (user prompts, tool results, completed assistant messages) published to native scrollback via `tea.Println`, the live region holding only volatile state; a later drift fix switched seek BACK to alt-screen (mouse wheel and copy broke again — replayed 2026-05) before the second re-migration to inline.
- **Lesson**: alt-screen is the wrong default for any "conversation that has history" — use it only for genuinely full-screen modal UIs; inline mode + `tea.Println` for committed content matches gh and gemini CLI.
