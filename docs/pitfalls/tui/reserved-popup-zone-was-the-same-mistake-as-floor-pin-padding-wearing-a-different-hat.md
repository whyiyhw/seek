### Reserved popup zone was the same mistake as floor-pin padding, wearing a different hat
- **Saw**: 9 blank rows sat between content and input so a filter popup (slash menu / model picker / path picker) would not shift the input; users said the input looked "floating".
- **Why**: like floor-pin padding, the zone pinned the input against the terminal, which inline mode cannot do — a transient popup jump traded for a permanent defect: input floating mid-screen, 9 dead rows.
- **Fix**: the zone is retired: idle View() emits nothing between content and separator; a popup open grows the live region by menuMaxRows+1 rows (same "content grew" behaviour as streaming); the fixed height INSIDE the popup (menuMaxRows while filtering) is kept; the status bar stays the LAST row (moving it above the input floated it mid-screen — inline has no fixed top), pinned by `TestView_PopupZoneGrowsOnOpen` + `TestView_StatusBarIsLastRow`.
- **Lesson**: no fixed-height padding for position-stability — the live region's height must equal its content's; a popup shifting the input is content growth, not a bug.
