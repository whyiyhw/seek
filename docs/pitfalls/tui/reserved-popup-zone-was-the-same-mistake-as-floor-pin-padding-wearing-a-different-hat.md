### Reserved popup zone was the same mistake as floor-pin padding, wearing a different hat
- **Saw**: 9 blank rows always sat between content and input so opening a filter popup (slash menu / model picker / path picker) would not shift the input — users complained the input looked like it was "floating".
- **Why**: like floor-pin padding, the zone pinned the input's position against the terminal, which inline mode cannot do — it traded a transient popup jump for a permanent visual defect (input floating mid-screen, 9 dead rows of screen space).
- **Fix**: the zone is retired: idle View() emits nothing between content and separator, a popup open grows the live region by menuMaxRows+1 rows (the same "content grew" behaviour as streaming), the fixed height INSIDE the popup (menuMaxRows while filtering) is kept, and the status bar stays the LAST row (moving it above the input floated it mid-screen — inline has no fixed top), pinned by `TestView_PopupZoneGrowsOnOpen` + `TestView_StatusBarIsLastRow`.
- **Lesson**: no fixed-height padding for position-stability at all — the live region's height must be exactly its content's height; a popup shifting the input is content growth, not a bug.
