### Ctrl+V image paste on Windows was a silent no-op — a missing platform branch with zero feedback
- **Saw**: Windows Ctrl+V with a screenshot did nothing — no `📋 image` marker, no error; text paste still worked.
- **Why**: `clipimage.defaultGrabCommand` had `darwin`/`linux` branches and a bare `default: return nil`; Windows gets `ErrNoGrabber`, swallowed by `tryClipboardPaste` before `clipboard.ReadAll()` — an image-only clipboard has no TEXT, so the handler returned "not handled".
- **Fix**: added the `windows` branch (PowerShell + WinForms `Clipboard::GetImage()`; table returns `(argv, outEnv)`), split `defaultGrabCommandFor(goos)` so every branch is testable anywhere, gated e2e `SEEK_CLIPIMAGE_E2E=1` (asserts PNG magic + 3s TUI budget), fixed `ErrNoGrabber`'s text: only `SEEK_CLIPBOARD_IMAGE_CMD` is wired, not `imagepaste.command`.
- **Lesson**: a fallback ending in a no-op needs a signal — silent failure is indistinguishable from "never built"; test a per-OS table branch via a goos parameter, not `runtime.GOOS` (invisible to green Linux/macOS CI).
- **Refs**: `internal/clipimage/clipimage.go:defaultGrabCommandFor`, `internal/tui/paste.go:tryClipboardPaste`, `internal/clipimage/e2e_windows_test.go`, `docs/guide-windows.md`
