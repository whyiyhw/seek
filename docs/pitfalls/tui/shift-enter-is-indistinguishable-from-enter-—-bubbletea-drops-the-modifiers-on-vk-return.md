### Shift+Enter is indistinguishable from Enter — bubbletea drops the modifiers on VK_RETURN
- **Saw**: on Windows, Shift+Enter SENT the message (user report "Shift+Enter 换不了行了"); the feature was never implemented (M4 comment: "added when terminal keymap support catches up").
- **Why**: bubbletea v1's Windows coninput reader maps `VK_RETURN → KeyEnter` unconditionally (`key_windows.go:keyType`); `KeyMsg` has no Shift field, no `KeyShiftEnter` type, no CSI-u (`ESC[13;2u`) support; only Ctrl+J (KeyCtrlJ) survives as a newline key on Windows.
- **Fix**: documented in `docs/guide-windows.md` (Ctrl+J official; WT settings.json `sendInput: "\n"` workaround); fixed by the v2 migration: the input layer keeps modifiers on VK_RETURN (`key.Mod = translateControlKeyState(cks)`), parses CSI-u/kitty on Unix, and seek binds `SetKeys("ctrl+j", "shift+enter")` (model.go), degrading to plain Enter elsewhere. Pinned by `TestHandleKey_ShiftEnterInsertsNewline`.
- **Lesson**: before designing a modified-key binding, verify the whole input chain carries the modifier (KeyMsg fields, platform input reader, terminal escape sequences); re-verify platform facts after a framework major upgrade.
