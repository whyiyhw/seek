### Inline-mode drift was self-inflicted by floor-pin padding
- **Saw**: under inline mode the input line drifted off the terminal floor after a few turns (commits `16b13ef`, `59bd9a9`, `f218c57` each chased a facet; the "fix" — alt-screen — broke mouse wheel/copy).
- **Why**: `View()` padded `sb` with `strings.Repeat("\n", pad)` every frame to pin the input to the floor, the pad length from a manual `scrollbackLines` counter that lost sync against `tea.ClearScreen`, multi-line `tea.Println` from `/help`, async resize, and discarded `tea.Println` cmds.
- **Fix**: migrated back to inline — `tea.WithAltScreen()` removed AND no floor-pin padding: the live region's height varies per frame, handled via cursor-up + EraseScreenBelow; the welcome banner is printed once to stdout BEFORE `tea.NewProgram` (scrollback, never re-enters the redraw loop).
- **Lesson**: never pad the live region with trailing newlines — `m.height - rowsIn(...)` math is the M3-era drift recomputed — and when an architectural decision was made to fix a symptom, question the root cause: gh and gemini CLI run inline with no floor-pin math.
