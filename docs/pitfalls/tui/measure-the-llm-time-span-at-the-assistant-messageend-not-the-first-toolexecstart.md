### Measure the LLM-time span at the assistant MessageEnd, not the first ToolExecStart
- **Saw**: (design-time) the first draft of the exit-summary timing closed the per-turn LLM span at the first `ToolExecStart` (and `TurnEnd` for tool-less turns) — overcounting agent-side arg-parsing/tool-lookup work, and inconsistent between turn shapes.
- **Why**: pkg/agent events carry no timestamps, so timing is measured at the consumer; the sequence is `TurnStart → deltas → assistant MessageEnd → ToolExecStart…End → TurnEnd`, and only the assistant-role `MessageEnd` marks "stream done" for every turn shape.
- **Fix**: close the span in the `RoleAssistant` branch of the `MessageEnd` case (tool-result MessageEnds are `RoleTool` and must NOT close); close defensively (guarded by `turnStart != zero`, then zero it) at `TurnEnd` / `AgentEnd` (Esc) / `ErrorEvent` (finish="length" fires after MessageEnd, so the guard makes it a no-op).
- **Lesson**: anchor each span to the event that semantically marks its end, and remember same-type events (tool-result MessageEnd) that must not trigger it — a role/type check plus a zero-value guard makes double-close and missed-close impossible.
- **Refs**: `internal/tui/update_agent.go:applyAgentEvent`, `internal/tui/summary.go`, `pkg/agent/agent.go` (turn loop)
