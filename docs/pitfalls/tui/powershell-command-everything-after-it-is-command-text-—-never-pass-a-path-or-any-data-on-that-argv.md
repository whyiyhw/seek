### PowerShell `-Command`: everything after it is command TEXT — never pass a path (or any data) on that argv
- **Saw**: wiring the Windows grabber, `-Command "<script using $args[0]>" <path>` never saw the path; `& { param } <path>` passed e2e until the cache dir was named `clip cache`: the param bound `…\clip` → missing dir → `ErrNoImage` → text-paste fallback.
- **Why**: powershell.exe joins everything after `-Command` into one command string; PowerShell's CLI parser consumes Go's argv quoting before the join, so the re-parsed text is unquoted: a space splits the path, `'`/`;`/`$` become separators; `& { param }` binds only clean trailing tokens.
- **Fix**: the output path never touches argv: `defaultGrabCommandFor` returns `(argv, outEnv)`, `Grab` exports `SEEK_CLIPIMAGE_OUT` on the child, and the script reads `$env:SEEK_CLIPIMAGE_OUT`; pinned by `TestGrab_OutEnvDeliversPath` + `TestDefaultGrabCommandFor_WindowsShape`.
- **Lesson**: when a runner re-parses argv as code (`powershell -Command`, `cmd /c`), pass data out-of-band (env var, stdin, `-File`); "it worked" only means the adversarial input wasn't in the fixture (`t.TempDir()` had no space).
