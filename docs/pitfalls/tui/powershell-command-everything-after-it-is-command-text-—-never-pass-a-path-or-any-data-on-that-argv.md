### PowerShell `-Command`: everything after it is command TEXT — never pass a path (or any data) on that argv
- **Saw**: wiring the Windows grabber: `-Command "<script using $args[0]>" <path>` never saw the path; `& { param } <path>` passed e2e until the cache dir was named `clip cache` — param bound `…\clip`, dir missing, `ErrNoImage` → text paste.
- **Why**: powershell.exe joins everything after `-Command` into one string; its CLI parser eats Go's argv quoting before the join, so the text re-parses unquoted — a space splits the path, `'`/`;`/`$` separate, `& { param }` binds only clean trailing tokens.
- **Fix**: the path never touches argv — `defaultGrabCommandFor` returns `(argv, outEnv)`, `Grab` exports `SEEK_CLIPIMAGE_OUT`, the script reads `$env:SEEK_CLIPIMAGE_OUT`; pinned by `TestGrab_OutEnvDeliversPath` + `TestDefaultGrabCommandFor_WindowsShape`.
- **Lesson**: a runner that re-parses argv as code (`powershell -Command`, `cmd /c`) needs data out-of-band (env var, stdin, `-File`); "it worked" only proves the fixture lacked the adversarial input (`t.TempDir()` had no space).
