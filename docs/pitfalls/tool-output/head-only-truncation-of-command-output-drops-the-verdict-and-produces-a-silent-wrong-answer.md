### Head-only truncation of command output drops the verdict and produces a SILENT wrong answer
- **Saw**: the bash tool clamped over-budget output with `output[:32KiB]` — keep the head, drop the tail. For `go test ./...`, `make`, `npm run build`, `pytest` the verdict is LAST; the model got the passing wall, never the `FAIL` lines, and reported a pass.
- **Why**: `s[:max]` is correct for front-loaded output (a file head, a `grep` result) but backwards for command output, where the tail is the result; the header said only "output truncated to 32768 bytes", no hint the conclusion went missing.
- **Fix**: `clampOutput` keeps 8 KiB of head + ~24 KiB of tail with an elision marker between them, both cuts on line boundaries; the marker states the tail is intact. `grep` left alone — no verdict at the end, and its notice already says to narrow the pattern.
- **Lesson**: before bounding any output, ask where the INFORMATION is, not where the bytes are; removing the answer silently produces a confident wrong conclusion, removing context only a request for detail. When both ends matter, elide the middle and say so.
- **Refs**: `internal/tools/bash/bash.go:clampOutput`, `internal/tools/bash/bash_test.go:TestBash_PreservesVerdictAtTail`
