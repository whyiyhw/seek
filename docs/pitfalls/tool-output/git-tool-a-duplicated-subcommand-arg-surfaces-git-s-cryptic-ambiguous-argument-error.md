### git tool: a duplicated subcommand arg surfaces git's cryptic "ambiguous argument" error
- **Saw**: `git` called with `subcommand: "diff"` + `args: ["diff", "HEAD", "--stat"]` returned `fatal: ambiguous argument 'diff': unknown revision or path not in the working tree. Use '--' to separate paths from revisions, like this: git diff -- <path>...` — the hint misleads (following it yields `pathspec 'HEAD' did not match`).
- **Why**: `git -c color.ui=false <subcommand> <args...>` makes a repeated subcommand a second positional that `git diff` parses as tree-ish; stderr passes through untouched, so the model gets git's generic hint, not the fix.
- **Fix**: pre-exec guard — `args[0] == subcommand` refused, message naming the `subcommand` field and the `["--", <path>]` escape; the schema `args` description now says the subcommand is never repeated. Tests: rejection message + `git log -- log` (a file named `log`) still passing.
- **Lesson**: when a tool wraps another CLI, error passthrough is a UI decision — refuse before exec with the real fix; and in a backtick-delimited raw-string schema, text must not contain backticks.
- **Refs**: `internal/tools/git/git.go:Execute`, `internal/tools/git/git_test.go:TestExecute_RejectsDuplicatedSubcommandArg`
