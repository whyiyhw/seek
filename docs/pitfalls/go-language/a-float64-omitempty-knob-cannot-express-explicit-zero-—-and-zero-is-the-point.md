### A `float64` + `omitempty` knob cannot express "explicit zero" — and the zero IS the point
- **Saw**: adding `--temperature` to the request builders, the obvious shape was `Temperature float64 \`json:"temperature,omitempty"\``. That makes `--temperature 0` — the determinism pin the judge lane exists for — indistinguishable from "the user didn't pass the flag", so the key silently disappears from the body exactly when the caller most wants it there
- **Why**: `encoding/json`'s `omitempty` fires on Go's zero value, and `0.0` *is* that zero value. There is no third state in a bare float, so the encoder is forced to collapse "explicit 0" into "absent". A pointer is the only stdlib-native way to say "absent" without also saying "zero"
- **Fix**: `llm.ChatRequest.Temperature *float64` + `agent.Config.Temperature *float64`, each adapter declaring its own `*float64` wire field with `json:",omitempty"` (nil omits, a pointer to 0 emits `"temperature":0`). cmd/seek builds the pointer from `--temperature` after validating 0..2, so the CLI can express all three states while a session that never sets the knob stays byte-identical to its pre-knob request (prefix-cache contract)
- **Lesson**: before typing a numeric knob as `float64`, ask whether 0 is a legal *deliberate* value. If it is, the wire needs three states, and only a pointer gives them. The same test applies to booleans (`false` is often deliberate) and `int` knobs where 0 means "off" but "off" is also a meaningful request
