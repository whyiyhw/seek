### Feishu IM API returns HTTP 200 on business errors — must parse body `code`, and `content` is double-encoded JSON
- **Saw**: a keyword/signature-protected bot (`feishu`/`feishu-flow` webhook) rejected a POST but got HTTP 200 with non-zero body `code`; seek only checked `resp.StatusCode`, so the WARN never fired.
- **Why**: the open-platform API signals success in the body envelope `{code, msg, data}`, not HTTP status (only network faults give 4xx/5xx); ditto `im/v1/messages`. The `content` field is a JSON *string*: `{"text":"..."}` serialized once and embedded as a string — a raw map there yields a 400-equivalent body error.
- **Fix**: `internal/routines` parses body `code`; `code != 0` returns an error (surfaced by `--probe` and the best-effort dispatcher); token-invalid/expired invalidates the cached token and retries once. `content` is `json.Marshal(map[string]string{"text": s})` placed as a string. Old `feishu`/`feishu-flow` formats removed: `feishu` = self-built-app IM API.
- **Lesson**: checks against a Feishu-shaped API must read the body envelope, not HTTP status; a schema field typed "String" often means a JSON-encoded string. `tenant_access_token` lasts 7200s: cache one holder per `app_id`, refresh ~5 min early.
