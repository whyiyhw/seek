### Second-tier streams had no retry and swallowed sc.Err() — one HTTP/2 PROTOCOL_ERROR killed a whole round
- **Saw**: an opencode round died on `openai: http: Post "https://opencode.ai/inference/go/openai/v1/chat/completions": stream error: stream ID 37; PROTOCOL_ERROR; received from peer`.
- **Why**: `pkg/llm/provider/openai/client.go` did one bare `c.http.Do` with no retry (tier one has `retry.go` + `pumpChatStream`); `compatible.New` → `openai.NewCompatible` left opencode/glm/opendesign/`compatible` naked; `canRetry` matched neither a Do-phase error nor the EOF `streamBody` never surfaced from `sc.Err()`.
- **Fix**: openai mirrors tier one — `openStream` retries transport/5xx/429 once@500ms; `pumpStream` re-opens a pre-event break; `readStreamBody` checks `sc.Err()`; attempts reuse the marshalled `[]byte` (prefix cache); a post-delta break commits the partial turn with the `stream_error:`/`decode_error:` sentinel + buffered tool calls so `canRetry` re-issues; gemini's `parseStream` emits ErrorEvent.
- **Lesson**: "flaky" is a hypothesis, not a diagnosis — without `sc.Err()` on the tail, transport error and silent model look identical, and one naked client infects every lane sharing it.
