### Second-tier streams had no retry and swallowed sc.Err() — one HTTP/2 PROTOCOL_ERROR killed a whole round
- **Saw**: an unattended round on the opencode lane (2026-11-25, session 20261125-112656) died on one line: `openai: http: Post "https://opencode.ai/inference/go/openai/v1/chat/completions": stream error: stream ID 37; PROTOCOL_ERROR; received from peer`. ≥5 same-family deaths already in the ledger (c_54hsls ×2 on 11-22, c_lqtt2m, c_pzq2h6 on 11-24 23:34Z). Every previous occurrence was written off as "upstream flaky".
- **Why**: two independent defects, both only on the second tier. (a) `pkg/llm/provider/openai/client.go` did ONE bare `c.http.Do` — no retry — while the first tier has `pkg/deepseek/retry.go` (maxRetries=1 / 500ms) plus a one-shot re-open in `pumpChatStream` for a body that dies before any event. `compatible.New` delegates to `openai.NewCompatible`, so opencode / glm / opendesign / `--provider=compatible` all shared the naked path. The agent-layer retry (`pkg/agent/agent.go` canRetry) only recognises `errEmptyResponse`, or `len(ToolCalls)>0 && finish` starting `stream_error:`/`decode_error:` — a Do-phase error satisfies neither, so it went straight to ErrorEvent. (b) `streamBody` never read `sc.Err()`, so a body cut mid-stream looked exactly like a normal EOF: it emitted a `TurnDone` with an empty finish_reason, which the agent read as an empty completion (or booked a placeholder) while the real transport error vanished. anthropic had always checked (and emitted ErrorEvent); gemini's `parseStream` had the same hole.
- **Fix**: openai client now mirrors the first tier — `openStream` retries transport errors / 5xx / 429 once with a 500ms backoff and annotates exhaustion `(after N attempts)`; `pumpStream` re-opens once when a body breaks (or ends clean) before ANY event reached the caller; `readStreamBody` checks `sc.Err()`. Every attempt re-builds the request from the SAME marshalled `[]byte` (never a consumed reader, never a re-Marshal) so the prefix cache stays hot. A break after a delta commits the partial turn and reports the DeepSeek `stream_error:`/`decode_error:` sentinel on `TurnDone` — with the buffered tool calls emitted, which is what lets agent.go's canRetry re-issue the turn. Gemini's `parseStream` emits an ErrorEvent on `sc.Err()`. Opt-in `SEEK_LLM_TRACE=1` prints one stderr line per retry, because a silent recovery is otherwise undebuggable.
- **Lesson**: "the provider is flaky" is a hypothesis, not a diagnosis — check whether the client can even tell a reset from an EOF before blaming upstream. A stream tail with no `sc.Err()` check makes a real transport error and a model that said nothing observationally identical; that is the same class as a wire type that doesn't declare a field (see the pricing entry below). And when a lane has a retry policy, the *second* lane sharing the same client gets it free — `compatible.New` made four lanes naked at once without anyone noticing.
