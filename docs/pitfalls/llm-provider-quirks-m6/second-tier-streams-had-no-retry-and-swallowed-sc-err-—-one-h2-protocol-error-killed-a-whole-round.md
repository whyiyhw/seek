### Second-tier streams had no retry and swallowed sc.Err() — one HTTP/2 PROTOCOL_ERROR killed a whole round
- **Saw**: an opencode round died on `openai: http: Post "https://opencode.ai/inference/go/openai/v1/chat/completions": stream error: stream ID 37; PROTOCOL_ERROR; received from peer`.
- **Why**: `pkg/llm/provider/openai/client.go` did one bare `c.http.Do` — no retry (first tier: `retry.go` + `pumpChatStream`) — with `compatible.New` → `openai.NewCompatible` leaving opencode/glm/opendesign/`compatible` all naked; `canRetry` matched neither a Do-phase error nor the silent EOF from `streamBody` never reading `sc.Err()`.
- **Fix**: openai mirrors tier one: `openStream` retries transport/5xx/429 once@500ms; `pumpStream` re-opens once if the body breaks pre-event; `readStreamBody` checks `sc.Err()`; attempts reuse the same marshalled `[]byte` (prefix cache); a post-delta break commits the partial turn with the `stream_error:`/`decode_error:` sentinel + buffered tool calls so `canRetry` can re-issue; gemini's `parseStream` emits ErrorEvent.
- **Lesson**: "flaky" is a hypothesis, not a diagnosis — a stream tail without `sc.Err()` makes transport error and silent model observationally identical, and one naked client propagates to every lane sharing it.
