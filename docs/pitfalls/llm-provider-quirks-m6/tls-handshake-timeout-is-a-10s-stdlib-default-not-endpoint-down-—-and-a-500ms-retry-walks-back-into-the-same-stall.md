### TLS handshake timeout is a 10s stdlib default, not "endpoint down" — and a 500ms retry walks back into the same stall
- **Saw**: an unattended round on the OpenDesign Cloud lane died on one line, surfaced through ACP as `code=-32000`: `openai: http: Post "https://amr-link.open-design.ai/v1/chat/completions": net/http: TLS handshake timeout (after 2 attempts)`. The ledger already holds the same string twice for `api.deepseek.com`, and 14× `tls: bad record MAC` / 1× `stream error: stream ID` in sessions — every one filed as "upstream flaky".
- **Why**: two layers, both invisible until measured. (a) Neither inference client passed a `Transport`, so both inherited `http.DefaultTransport`'s `TLSHandshakeTimeout: 10s` — a general-purpose web number. seek's shape is a long-lived streaming POST through an HTTP-proxy tunnel (`HTTPS_PROXY` → local mihomo); a cold CONNECT + TLS negotiation measured 0.57–1.2s here, so a transient proxy/gateway stall of a few seconds eats the budget outright. Verified on the wire (30/30 proxied probes at ~0.6s, 1/3 direct probes dying at 5s): intermittent slow path, not a dead endpoint. (b) The retry waited the same fixed 500ms regardless of failure class. A `instant reset / 5xx / EOF` is a blip and 500ms is right; a *timeout* means the last attempt consumed its entire budget producing nothing, so retrying half a second later re-enters the same stall — the pair of 10s handshakes + 500ms is exactly the 20.5s the error line reports.
- **Fix**: the second-tier lanes got ONE shared client — `pkg/llm/httpclient.go` (`llm.HandshakeTimeout` 20s + `llm.NewHTTPClient()`, a `sync.OnceValue` transport cloned from `http.DefaultTransport` so proxy/HTTP2/idle tuning is preserved), now used by the openai/compatible, anthropic and gemini adapters; `pkg/deepseek/client.go` keeps the identical copy plus a new `WithHTTPClient` option (it may not import `pkg/llm` — CI layer-lint — so the two agree by hand), and the openai client gained a `newWithClient` test seam. Both retry paths grew a class-dependent backoff — `backoffFor(err)`: `errors.As(err, *net.Error)` with `Timeout()` → 3s, everything else → 500ms — applied in `openStream`/`pumpStream` (openai), `retryCall`/`pumpChatStream` (deepseek). Attempt counts, `(after N attempts)` annotation, 4xx-not-retried and byte-identical retry bodies all unchanged. Cards c_3j2ovf (this) / c_koutux (the retry machinery it plugs into).
- **Lesson**: when a lane dies on a transport string, ask *whose* deadline fired before blaming the endpoint — `net/http`'s defaults are tuned for web pages, not for proxied multi-minute model streams, and a timeout failure wants a backoff on the order of the budget that just elapsed. Proof that the fix is real requires a test where the deadline genuinely fires: a raw listener that accepts TCP and never says ServerHello, plus an injected short `TLSHandshakeTimeout`, then assert two accepts and a gap ≥ the long backoff — a hand-rolled fake error would have passed vacuously.
