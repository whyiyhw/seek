### TLS handshake timeout is a 10s stdlib default, not "endpoint down" — and a 500ms retry walks back into the same stall
- **Saw**: an OpenDesign round died: `openai: http: Post "https://amr-link.open-design.ai/v1/chat/completions": net/http: TLS handshake timeout (after 2 attempts)`.
- **Why**: neither client passed a `Transport`, both inheriting `http.DefaultTransport`'s `TLSHandshakeTimeout: 10s` — wrong for a proxied streaming POST (`HTTPS_PROXY`→mihomo): a transient stall eats the budget; the fixed 500ms retry ignored failure class — a timeout (budget already spent) re-entered the same stall.
- **Fix**: one shared client `pkg/llm/httpclient.go` (`HandshakeTimeout` 20s, `NewHTTPClient()` a `sync.OnceValue` clone of `http.DefaultTransport`) for all 3 adapters; `pkg/deepseek/client.go` mirrors it + `WithHTTPClient`; `backoffFor(err)`: `*net.Error`+`Timeout()` → 3s, else 500ms — 4xx-not-retried and byte-identical bodies unchanged.
- **Lesson**: ask whose deadline fired before blaming the endpoint — stdlib defaults fit web pages, not proxied streams; a timeout wants a backoff scaled to the budget spent, and its regression test must make the deadline truly fire.
