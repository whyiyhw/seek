### OpenCode Go: the model list needs no key, the base URL has three routable aliases, and each new lane re-invents the hardcoded-endpoint bug
- **Saw**: unauthenticated probes settled all three `待核`: `GET https://opencode.ai/inference/go/v1/models` lists 32 chat models with `api.chat-completions.base_url`, `limit.context/output`, `cost`, `capabilities`, `go.monthly_usage`; POST without `x-opencode-session` → `400 MissingSessionID`; bogus key → `401 Invalid credential`; bad path → `404`.
- **Why**: all three aliases route (`/inference/go/openai/v1/chat/completions`, `/inference/openai/v1/…`, `/inference/go/v1/…`), so a wrong-but-routable path hides until usage attribution reads the prefix. Subagent route hardcoded `opencodeBaseURL`, parent honoured only `--base-url` — `glmEndpoint` divergence again.
- **Fix**: pinned metadata-canonical `/go/openai/v1` + drift test; `opencodeEndpoint(cfg, flag)` mirrors `glmEndpoint` (env `OPENCODE_BASE_URL` / `providers.opencode.base_url` > `--base-url` > default) for both sites; `pricing.OpenCodeGoModels` (20 ids: 16 metered + 4 `*-Free`) feeds ACP `session/new` + TUI `/model`, free rows at $0; docs-table prices are peak — `/v1/models` quotes half + a 2× Mon–Fri 01–04 & 06–10 UTC multiplier.
- **Lesson**: `curl` the list + one unauthenticated POST before wiring a provider; one resolver per lane once it gains an endpoint override; `monthly_usage: null` = unmetered, not unusable.
- **Dynamic follow-up** (`internal/opencatalog`): fetches its own catalogue with the lane key, caches `~/.seek/opencode-catalog.json` (24h fresh / 7d stale), installs rates + windows via `pricing.SetModelRates` / `budget.SetLimits` (write-once-per-startup, mutex-guarded reads, compiled-row fallback); remote cost must be force-flattened (`NoOffPeakDiscount`) or the peak clock halves estimates; shared wire ids (`glm-5.3`, `deepseek-v4-pro`) skipped — a dynamic card would reprice the direct lanes.
- **Browser login** (`internal/opencodeauth`): OAuth AS `https://console.opencode.ai/.well-known/oauth-authorization-server` (PKCE S256, DCR, refresh, token-exchange); the device grant lives only in the console SPA (`POST /console/auth/device/code` + `/auth/device/token`, grant `urn:ietf:params:oauth:grant-type:device_code`), which DCR rejects → register an authorization_code client, reuse its `client_id`. `verification_uri_complete` is a PATH needing the console origin; inference auth needs `x-org-id: org_…` (else 403 `permission_error: Workspace selection is required`; id from `GET /console/api/user/workspaces`); `expires_in:2591999`. Refresh tokens are single-use with family revocation — two concurrent refreshes → `invalid_grant`, all credentials dead — so `Token()` serialises on a process mutex + `.<auth>.lock` (O_CREATE|O_EXCL, 60s stale steal), re-reading after both locks. "Authorize Unknown client" is the device page's hard-coded allowlist (`opencode-cli` / `opencode-console-cli` / `opencode-desktop` / `opencode-ios`), not a wiring bug; a workspace default can be region-blocked (`deepseek-v4.1-flash` → 400 until privacy changes); keyed `GET /v1/models` ≠ public list (19 rows, no `glm-5.2`).
