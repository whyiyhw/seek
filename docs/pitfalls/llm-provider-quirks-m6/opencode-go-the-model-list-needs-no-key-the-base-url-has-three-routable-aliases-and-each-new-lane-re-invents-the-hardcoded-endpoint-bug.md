### OpenCode Go: the model list needs no key, the base URL has three routable aliases, and each new lane re-invents the hardcoded-endpoint bug
- **Saw**: three `待核` markers all fell to unauthenticated facts: `GET https://opencode.ai/inference/go/v1/models` returns 32 chat models with `api.chat-completions.base_url`, `limit.context/output`, `cost`, `capabilities`, `go.monthly_usage`; POST without `x-opencode-session` → `400 MissingSessionID`, with header + bogus key → `401 Invalid credential`, made-up path → `404`.
- **Why**: three aliases all route (`/inference/go/openai/v1/chat/completions`, `/inference/openai/v1/…`, `/inference/go/v1/…`), so a wrong-but-routable path is invisible until usage attribution depends on the prefix; and the subagent route hardcoded `opencodeBaseURL` while the parent honoured only `--base-url` — the `glmEndpoint` divergence recurring because the resolver wasn't shared.
- **Fix**: pinned the metadata-canonical `/go/openai/v1` + a drift test; `opencodeEndpoint(cfg, flag)` mirrors `glmEndpoint` (env `OPENCODE_BASE_URL` / `providers.opencode.base_url` > `--base-url` > default) with both construction sites routed through it; `pricing.OpenCodeGoModels` (20 ids: 16 metered + 4 `*-Free`) feeds ACP `session/new` + TUI `/model`, free rows carrying $0 cards; docs-table prices are peak — `/v1/models` quotes half plus a 2× Mon–Fri 01–04 & 06–10 UTC multiplier.
- **Lesson**: `curl` the model list and one unauthenticated POST before wiring a provider; route every construction site through one resolver the day a lane gains an endpoint override; read the provider's definition before excluding rows — `monthly_usage: null` means unmetered, not unusable.
- **Dynamic follow-up** (`internal/opencatalog`): the lane fetches its own catalogue with the lane key (unkeyed list = public superset), caches `~/.seek/opencode-catalog.json` (24h fresh / 7d stale), installs rates + context windows via `pricing.SetModelRates` / `budget.SetLimits` (write-once-per-startup, mutex-guarded reads, fallback to compiled rows); remote cost must be force-flattened (`NoOffPeakDiscount`) or the peak clock halves subscription estimates, and shared wire ids (`glm-5.3`, `deepseek-v4-pro`) are skipped — a dynamic card would reprice the direct lanes.
- **Browser login** (`internal/opencodeauth`): the OAuth AS is at `https://console.opencode.ai/.well-known/oauth-authorization-server` (PKCE S256, DCR, refresh, token-exchange), but the device grant lives only in the console SPA (`POST /console/auth/device/code` + `/auth/device/token`, grant `urn:ietf:params:oauth:grant-type:device_code`) and DCR rejects it — register an authorization_code client and reuse its `client_id`. `verification_uri_complete` is a PATH needing the console origin; the token authenticates inference only with `x-org-id: org_…` (else 403 `permission_error: Workspace selection is required`; org id from `GET /console/api/user/workspaces`); `expires_in:2591999`. Refresh tokens are single-use with family revocation — two concurrent refreshes answered `invalid_grant` and killed every stored credential — so `Token()` serialises on a process mutex + a `.<auth>.lock` file (O_CREATE|O_EXCL, 60s stale steal), re-reading the file after both locks. The device page's "Authorize Unknown client" is its hard-coded allowlist (`opencode-cli` / `opencode-console-cli` / `opencode-desktop` / `opencode-ios`), not a wiring bug; a workspace's default can be region-blocked (`deepseek-v4.1-flash` → 400 until the privacy setting changes); keyed `GET /v1/models` ≠ public list (19 rows, no `glm-5.2`).
