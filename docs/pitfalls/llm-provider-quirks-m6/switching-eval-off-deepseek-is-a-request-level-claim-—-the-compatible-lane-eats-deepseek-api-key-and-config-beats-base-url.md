### Switching eval off DeepSeek is a request-level claim — the compatible lane eats DEEPSEEK_API_KEY and config beats --base-url
- **Saw**: eval switched with `-provider compatible -base-url <url>` had two reach-backs: the `compatible` case resolves credentials from `OPENAI_API_KEY` **or `DEEPSEEK_API_KEY`**; `opencodeEndpoint` / `glmEndpoint` rank `providers.<lane>.base_url` config above `--base-url`.
- **Why**: `buildProvider`'s compatible case accepts `DEEPSEEK_API_KEY` as a deliberate vLLM/Ollama fallback; endpoint precedence config/env > flag > default is intentional (`glmEndpoint`).
- **Fix**: eval/run.sh's provider lane (c_ffzic2) scrubs `DEEPSEEK_API_KEY` from the child env while a lane is active and exports `OPENCODE_BASE_URL` alongside `-base-url` (env > config closes the preset hole); `scripts/eval-provider-test.sh` plants metered-key canaries (env + config) and a preset-hijack endpoint, asserting zero canary hits and the override holding.
- **Lesson**: "provider switched" must be proven at the endpoint (auth + model on the wire), not the argv; migrating off a metered key means scrubbing the credential from the env, not the argv.
- **Refs**: `cmd/seek/main.go:buildProvider`, `cmd/seek/main.go:opencodeEndpoint`, `eval/run.sh`, `scripts/eval-provider-test.sh`
