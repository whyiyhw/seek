### A second subscription lane on the same wire id: capability and price tables are keyed by id, so one lane's "yes" silently governs the other
- **Saw**: OpenDesign Cloud serves `deepseek-v4.1-flash`, the OpenCode Go lane's wire string — so the id-keyed `internal/pricing` / `internal/budget` / `internal/modelcap` inherited the Go lane's rate card, window and capabilities: wrong for documents, answering 200 "no PDF is attached" while silently DROPPING the `file` part (rates/vision were right).
- **Why**: entries are yes/no with no provenance, one-lane-per-id by design — whichever lane asserted first owns the answer for all.
- **Fix**: documented, not solved: tables stay id-keyed (lane-aware keys are the surface `pricing.ModelPricing` refuses); limitation at `modelcap.go:fileModels` and `docs/guide-config.md` §3; `modelcap.LaneOf` resolves shared ids to the older lane (OpenCode; `lane.go`).
- **Lesson**: before reusing another lane's wire ids, diff the providers' ACTUAL behaviour per id — metadata lies both ways (declares `file` but drops it; declares `-eco` text-only but answered an image); a 200 doesn't prove the part arrived, so ask a question whose answer depends on it.
- **Refs**: `internal/modelcap/modelcap.go:fileModels`, `internal/modelcap/lane.go`, `internal/pricing/pricing.go:ModelOpenDesignV41Flash`, `docs/guide-config.md` §3 "与 OpenCode 车道的 id 冲突"
