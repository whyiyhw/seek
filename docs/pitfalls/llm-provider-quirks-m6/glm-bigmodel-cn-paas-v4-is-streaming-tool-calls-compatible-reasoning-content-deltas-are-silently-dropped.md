### GLM (bigmodel.cn paas/v4) is streaming-tool_calls compatible; `reasoning_content` deltas are silently dropped
- **Saw**: smoke-running `--provider glm` (glm-5.3, coding-plan key): a full tool loop and a plan-mode run both worked, but stats showed `cache hit 0/0 ratio n/a` and TTFB 11.8–42.5s.
- **Why**: the endpoint speaks OpenAI Chat Completions — `delta.tool_calls[]` keyed by `index`, `finish_reason:"tool_calls"`, final-chunk usage (`stream_options.include_usage` honored) — but also emits `reasoning_content` deltas the openai client's wire types don't declare, so `encoding/json` skips them: thinking renders as dead air, prefix-cache stats stay empty.
- **Fix**: none needed — `compatible.New` + pinned default `https://open.bigmodel.cn/api/paas/v4/chat/completions` registered as `case "glm"` in `buildProvider`; a `reasoning_content` passthrough (deepseek's Reasoning shape) is the documented escape if silent thinking becomes a UX problem.
- **Lesson**: "OpenAI-compatible" needs three verifications — streaming tool_calls delta shape, usage-in-stream opt-in, and what the model emits that your wire types DON'T parse.
- **Refs**: `cmd/seek/main.go:buildProvider` (glm case + `glmBaseURL`), `pkg/llm/provider/openai/client.go:streamDelta`, `docs/book/chapter-14.md`
