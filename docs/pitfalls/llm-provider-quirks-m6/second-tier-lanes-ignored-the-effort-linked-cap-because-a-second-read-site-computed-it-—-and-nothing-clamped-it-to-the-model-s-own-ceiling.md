### A second-tier lane silently ignored the effort-linked completion cap — and nobody clamped it to the model either
- **Saw**: `/effort max` did nothing on `llm.Provider` lanes: the wire body carried `max_tokens: 16384` regardless, so the 64K thinking budget never reached the second tier.
- **Why**: two read sites, one unclamped — `runTurnDeepSeek` read `a.turnMaxTokens()` (effort-linked authority), `runTurnLLM` read `a.cfg.MaxTokens` (raw config, 16K default). The clamp had no home: `internal/budget` owned the context window, not the completion cap, while the effort base (64K) exceeds gpt-4o's 16K and gemini's 8K — linking without a clamp turns a silent no-op into a hard 400.
- **Fix**: `internal/budget` grows `OutputLimit(model) (int, bool)` + `SetOutputLimits`; `internal/opencatalog` parses `limit.output` per row, `directLaneIDs` included; `Agent.turnMaxTokens` is now the single authority for both lanes, clamping the derived base — an explicit `--max-tokens` still wins verbatim.
- **Lesson**: two code paths sharing a concept must share one authority — grep for the second read site before declaring a knob wired; a vendor ceiling has three states (value/absent/unknown), so a bare-`int` lookup eventually clamps to zero.
