### OpenDesign Cloud is two hosts and two key kinds — amr-link for inference, amr-api for the plan

- **Saw**: wiring `--provider=opendesign` from the docs alone sent us to `open-design.ai` (the marketing site, HTML 404), then to `amr-api.open-design.ai/api/v1/...` (a working host that answers `{"error":"unauthenticated"}` on everything except its public price list), and to `~/.amr/config.json` (a Vela desktop profile holding `vela_ctrl_…` keys that are not API keys). The actual inference contract — `https://amr-link.open-design.ai/v1/chat/completions`, `Authorization: Bearer sk-amr-…`, keys minted at `open-design.ai/cloud/api-keys` — was a different host, a different key prefix, and a different credential store from every plausible-looking neighbour.
- **Why**: the product splits into a **model plane** (`amr-link`, `sk-amr-` keys, `/models` + `/chat/completions` + `/responses` + `/messages` on one base) and a **control plane** (`amr-api`, `vela_ctrl_` keys, plan / wallet / allowance windows). Both halves are documented, but in different places (help center vs. the CLI-login plugin ecosystem), so researching the lane from one document lands half of the contract. The desktop app's `vela login` also writes a machine credential pair that looks like "the key" and isn't.
- **Fix**: pinned `opendesignBaseURL` + `opendesignEndpoint` in `cmd/seek/main.go` with the same env/config > flag > default precedence as the GLM and OpenCode lanes; keys resolve only through `OPENDESIGN_API_KEY` / `providers.opendesign.api_key`; the wizard's key hint is the real `sk-amr-` prefix so a `vela_ctrl_` paste is visibly wrong before it hits the network.
- **Lesson**: for a subscription provider, probe the **model list** before writing any code — `curl -H "Authorization: Bearer <key>" https://<host>/v1/models` distinguishes "host exists but wrong auth" (401 with a JSON error code), "wrong host" (HTML 404), and "no key yet" in three calls. And when a vendor publishes a control-plane API next door, note in the code comment which host is which; the next reader will otherwise try the billing host for inference.
