### OpenDesign Cloud is two hosts and two key kinds — amr-link for inference, amr-api for the plan
- **Saw**: wiring `--provider=opendesign` hit `open-design.ai` (HTML 404), then `amr-api.open-design.ai/api/v1/...` (`{"error":"unauthenticated"}` except the price list), then `~/.amr/config.json` (`vela_ctrl_…` keys, not API); the inference contract: `https://amr-link.open-design.ai/v1/chat/completions`, `Bearer sk-amr-…`, minted at `open-design.ai/cloud/api-keys`.
- **Why**: the model plane is `amr-link` + `sk-amr-` keys; the control plane is `amr-api` + `vela_ctrl_` keys (plan / wallet); `vela login` writes a machine credential, not an API key.
- **Fix**: pinned `opendesignBaseURL` + `opendesignEndpoint` with the usual env/config > flag > default precedence; keys resolve only via `OPENDESIGN_API_KEY` / `providers.opendesign.api_key`; the wizard hint shows the `sk-amr-` prefix so `vela_ctrl_` pastes look wrong.
- **Lesson**: for subscription providers, probe the model list first — `curl -H "Authorization: Bearer <key>" <host>/v1/models` distinguishes wrong auth (401 JSON) / wrong host (HTML 404) / no-key in three calls; when a vendor publishes a control-plane API next door, note which host is which.
