### OpenDesign Cloud is two hosts and two key kinds — amr-link for inference, amr-api for the plan
- **Saw**: wiring `--provider=opendesign` hit `open-design.ai` (HTML 404), then `amr-api.open-design.ai/api/v1/...` (`{"error":"unauthenticated"}` except the price list), then `~/.amr/config.json` (`vela_ctrl_…` keys, not API). The inference contract: `https://amr-link.open-design.ai/v1/chat/completions`, `Bearer sk-amr-…`, minted at `open-design.ai/cloud/api-keys`.
- **Why**: model plane = `amr-link` + `sk-amr-` keys; control plane (plan / wallet) = `amr-api` + `vela_ctrl_` keys; `vela login` writes a machine credential, not an API key.
- **Fix**: pinned `opendesignBaseURL` + `opendesignEndpoint` (env/config > flag > default); keys only via `OPENDESIGN_API_KEY` / `providers.opendesign.api_key`; the wizard hint shows the `sk-amr-` prefix so `vela_ctrl_` pastes look wrong.
- **Lesson**: for subscription providers, probe the model list first — `curl -H "Authorization: Bearer <key>" <host>/v1/models` separates wrong auth (401 JSON) / wrong host (HTML 404) / no-key in three calls; note which host is which when a control-plane API sits next door.
