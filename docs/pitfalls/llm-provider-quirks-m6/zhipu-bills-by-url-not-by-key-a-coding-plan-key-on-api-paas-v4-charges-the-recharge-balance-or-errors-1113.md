### Zhipu bills by URL, not by key: a Coding Plan key on /api/paas/v4 charges the recharge balance (or errors 1113)
- **Saw**: `--provider=glm` with a Coding Plan key billed the recharge balance (empty → `1113`「余额不足或无可用资源包」); pinned default `/api/paas/v4`, no `base_url` in config, only the TUI-invisible `--base-url`.
- **Why**: `open.bigmodel.cn/api/paas/v4/chat/completions` = pay-as-you-go; `…/api/coding/paas/v4/chat/completions` = Coding Plan quota; third base: `/api/anthropic` (Anthropic protocol); the keys look identical.
- **Fix**: `config.ProviderConfig.BaseURL` + `config.BaseURLFor` (`GLM_BASE_URL` > config), resolved by `glmEndpoint(cfg, flag)`: override > `--base-url` > `glmBaseURL`; default unchanged (pay-as-you-go majority). Live-key check (2026-11-18): `/api/monitor/usage/quota/limit` (raw key, no `Bearer`) reports the plan's 5h + weekly windows; truncating to `…/api/coding/paas/v4` 404s (`path:"/v4"`) — `base_url` POSTed verbatim; 401 = stale key.
- **Lesson**: the endpoint is part of the provider contract when billing splits by URL — a pinned default silently mis-bills the other side; ship the override with the default, never write "both share it" without a real-key test of both paths.
