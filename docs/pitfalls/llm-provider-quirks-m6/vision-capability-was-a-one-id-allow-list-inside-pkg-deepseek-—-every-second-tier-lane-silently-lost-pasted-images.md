### Vision capability was a one-id allow-list inside pkg/deepseek — every second-tier lane silently lost pasted images
- **Saw**: a pasted screenshot on the OpenCode lane (`deepseek-v4.1-flash`) produced `[image: pasted-image.png — 当前模型不支持图片输入，/model deepseek-flash 切换]`; the model accepts images.
- **Why**: two gaps: `deepseek.IsVisionModel` was `model == ModelV41Flash` with no lane info at its three call sites; past the gate, `pkg/llm.Message` was text-only — `msgsToLLM` dropped `Images` in-band.
- **Fix**: new `internal/modelcap` as the single capability authority (per-lane tables + `internal/opencatalog` grants); `deepseek.IsVisionModel` deleted. `llm.Message.Images []llm.Image` (data URLs), text-only messages keeping exact wire bytes; send station mirrors `runTurnDeepSeek`: gate → `ResolveImages` → `PrepareMessages` → convert.
- **Lesson**: "which models support X" is cross-cutting, not a provider fact — parked where X first shipped, every new lane answers "no"; a silent in-band downgrade makes the wrong answer look like product design; a downgrade note must never name another lane's id.
