### An approval-mode suffix that only the model reads is state nobody restores
- **Saw**: after `seek -resume`, a plan approved with "auto-approve per step" behaved like plain ask-per-call: `plan(action="start", N)` closed the gate instead of arming it, though the transcript still promised it would.
- **Why**: the only carrier is the `(auto-approve-per-step)` tag `propose.approveResult` appends after `[plan: approved]`; `plan/reconstruct.go` matched only the strict prefix; `planBridge.batch` is unpersisted.
- **Fix**: `ReconstructFromTranscript` returns the batch flag as a third value (`batchApproval` reads the tag after the bracket); `cmd/seek` installs it via `planBridge.RestoreApprovalMode` before `planTool.Restore`, through `StepChanged` — the one place re-arming `preApproved`. Tests: `TestReconstruct_BatchApprovalTagRestored` / `_ReadFromLatestApproval`, `TestRestoreApprovalMode_*`.
- **Lesson**: beside a parsed marker, a model-only tag is state — restore paths must return every optional bit in one call.
