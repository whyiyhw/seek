### A flag's default and "the user passed that value" are different facts — only `flag.Visit` tells them apart
- **Saw**: `--effort`'s `off` maps to the empty string (no `reasoning_effort` key), same as the default — the parsed value can't distinguish "user asked for off" from "not passed"; resume must inherit saved effort only when NOT passed.
- **Why**: `flag.Parse` can't distinguish defaults from explicit values in the `*T` pointers; `flag.Visit` walks only set flags, and must run after `flag.Parse`, before inheritance.
- **Fix**: `cmd/seek/main.go` records `visited := map[string]bool{}` after `flag.Parse()`; `sessionEffort` starts at the historical `"max"` unless `visited["effort"]`; `-resume` inheritance is guarded by `!visited["effort"]` (same "flags set after -resume win" rule as `--model`/`--yolo`/`--plan`). Tested in `TestEffortFlagE2E_ResumeInheritsUnlessFlagged`.
- **Lesson**: a knob whose "off"/default is also a legal explicit choice needs a visitation table, not a sentinel — inherited resume state creates the collision.
- **Refs**: `cmd/seek/main.go` (`visited`, `parseEffortFlag`, `sessionEffort`, `-resume`), `cmd/seek/effort_temperature_flag_test.go` (`TestEffortFlagE2E_ResumeInheritsUnlessFlagged`), `docs/guide-budget.md` §1.2
