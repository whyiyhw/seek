### A flag's default and "the user passed that value" are different facts — only `flag.Visit` tells them apart
- **Saw**: adding `--effort` where `off` maps to the empty string (no `reasoning_effort` key), the same empty string the flag defaults to. Reading the parsed value alone cannot answer "did the user ask for off, or just not pass the flag?" — and the answer changes behaviour, because a resumed session's saved effort must be inherited only when the flag was NOT passed
- **Why**: `flag.Parse` only resolves values; the defaults are indistinguishable from explicitly-passed ones in the `*T` pointers. `flag.Visit` (which walks only the flags that were actually set) is the one stdlib surface carrying that fact, and it must be called after `flag.Parse` and before any inheritance logic runs
- **Fix**: `cmd/seek/main.go` records `visited := map[string]bool{}` right after `flag.Parse()` and threads it through the two decisions: `sessionEffort` starts at the historical `"max"` unless `visited["effort"]`, and the `-resume` inheritance is guarded by `!visited["effort"]` (the same "flags set after -resume win" rule `--model`/`--yolo`/`--plan` already follow). Tested end-to-end in `TestEffortFlagE2E_ResumeInheritsUnlessFlagged`
- **Lesson**: any knob whose "off"/"default" value is also a legal explicit choice needs a visitation table, not a sentinel value. Reserve the sentinel ("-1", "", "unset") approach only when no legal value can collide with it — and even then, a resumed session's inherited state gives the collision a place to happen
