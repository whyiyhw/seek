### skill_commit must not silently pick a scope — the model has no signal for user intent
- **Saw**: `skill_commit` installed at user scope (`~/.seek/skills/`) by default, so "install this skill from GitHub" could silently land in `$HOME` when the user wanted the project repo, or vice versa.
- **Why**: user scope is private to the machine, project scope is shared via git — neither tool name nor source URL tells the model the user's intent, and hard-coding `user` meant it never learned to ask.
- **Fix**: `scope` is a required enum (`"user"` | `"project"`) rejected by schema validation when omitted; system prompt + tool description instruct the model to ask first, the approval prompt shows the resolved target path, and tests cover missing/invalid/both valid scopes. Commit `d86d509`.
- **Lesson**: a parameter encoding a high-consequence user choice (private vs shared, local vs remote) must be a required enum, not a silent default — the model cannot infer intent for binary filesystem-layout or visibility decisions; such an "A or B" is an `ask_user` candidate.
- **Refs**: `internal/tools/skillinstall/skillinstall.go` (scope validation + approval prompt), `cmd/seek/main.go` (system prompt instruction), `docs/guide-skills.md` (scope docs), commit `d86d509`
