### `[plan: approved]` is a load-bearing wire-format prefix shared between propose and the plan reconstructor
- **Saw**: emitting `[plan: approved batch]\n…` for the "approve with auto-approve-per-step" picker option broke `seek -resume`: the task list rebuilt as empty after a session that approved a batched plan.
- **Why**: `plan/reconstruct.go` scans transcript tool results for the literal prefix `[plan: approved]` (closing bracket included); `[plan: approved batch]` lacks that prefix, so the seeding point was missed and the downstream `plan(start)`/`plan(complete)` history was discarded.
- **Fix**: the batch path emits `[plan: approved] (auto-approve-per-step)\n…` so the prefix scan still matches, with `TestExecute_ApproveBatch` asserting `HasPrefix(out, "[plan: approved]")` so future variants can't regress it.
- **Lesson**: a result string with two consumers (model + reconstructor) is wire format — variants append AFTER the contract token, never inside it; same rule as schema bytes (CLAUDE.md / PRD §4.8.1).
