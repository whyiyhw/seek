### `[plan: approved]` is a load-bearing wire-format prefix shared between propose and the plan reconstructor
- **Saw**: emitting `[plan: approved batch]\n…` for the "approve with auto-approve-per-step" option broke `seek -resume`: the task list rebuilt empty after a batched-plan session.
- **Why**: `plan/reconstruct.go` scans tool results for the literal prefix `[plan: approved]` (closing bracket included); `[plan: approved batch]` lacks it, so seeding was missed and the downstream `plan(start)`/`plan(complete)` history discarded.
- **Fix**: the batch path emits `[plan: approved] (auto-approve-per-step)\n…` so the prefix scan still matches; `TestExecute_ApproveBatch` asserts `HasPrefix(out, "[plan: approved]")` so variants can't regress it.
- **Lesson**: a result string with two consumers (model + reconstructor) is wire format — variants append AFTER the contract token, never inside it; same rule as schema bytes (CLAUDE.md / PRD §4.8.1).
