### Slash menu / status bar floated mid-screen on /clear, /help close, and other "banner gone" states
- **Saw**: on `/clear` + `/`, `/help` then Esc + `/`, and slash-menu open on a tall terminal, the input/status assembly sat 14 rows above the terminal floor; each `bannerWiped` patch fixed one path, another re-introduced it.
- **Why**: `view.go` computed `cursorRow := welcomeFixedLines(14) + scrollbackLines`, assuming the 12-row banner + 2 stderr loader lines printed by `PrintPixelWelcomeBanner` before `tea.NewProgram` still sit at rows 0..13; inline bubbletea can't query the real cursor, so `tea.ClearScreen` or a 40+-row `/help` overlay on a sub-60-row terminal scrolls them away.
- **Fix**: render the banner inside `View()` via `renderWelcomeHeader(opts)`, gated on `scrollbackLines == 0`, instead of printing to stdout before bubbletea starts; `cursorRow` becomes `m.scrollbackLines`, deleting `bannerWiped`, `welcomeFixedLines`, `welcomePadding`, `PrintPixelWelcomeBanner`, `animateBanner`, `shouldAnimate`.
- **Lesson**: an invariant resting on "feature X sits at terminal row N" drifts when the model can't observe the terminal; rendering the banner inside `View()` makes `cursorRow = scrollbackLines` the stable one.
- **Refs**: `internal/tui/view.go` (welcome-screen block + bottom-pin pad), `internal/tui/banner.go` (renderWelcomeHeader is the surviving emitter), `internal/tui/run.go` (no more pre-tea banner print)
