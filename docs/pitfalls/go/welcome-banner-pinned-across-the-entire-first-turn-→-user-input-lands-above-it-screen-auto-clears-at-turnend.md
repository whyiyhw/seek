### Welcome banner pinned across the entire first turn → user input lands above it, screen "auto-clears" at TurnEnd
- **Saw**: after the first prompt the `▌ you: …` line appeared ABOVE the SEEK wordmark banner, and at `TurnEnd` the terminal "auto-cleared" — real scrollback content (cwd marker, earlier conversation) vanished in one frame.
- **Why**: `view.go` gated the banner on `m.turns == 0`, but `m.turns` increments only at `agent.TurnEnd`, so the 11-row banner block stayed pinned in the live region for the entire first turn; every `tea.Println` landed above it, then `turns` flipping 0→1 made the inline cursor-up + EraseScreenBelow over-erase 11 rows of scrollback.
- **Fix**: gate on `m.turns == 0 && len(m.promptHistory) == 0` — `promptHistory` gains its first entry in `submit()` before any streaming, so the banner disappears on a quiet frame before the `tea.Println` redraw storm; `cmdNew` resets `promptHistory`/`historyIdx`/`savedDraft` so `/clear` restores the welcome state.
- **Lesson**: a layout block gated on a late-updating counter (`turns` at TurnEnd, seconds after submit) disappears on the busiest frame; use the earliest stable state-change signal (`promptHistory` append in submit) instead of the latest.
- **Refs**: `internal/tui/view.go` (welcome gate), `internal/tui/commands.go:cmdNew` (promptHistory reset), `internal/tui/view_test.go:TestView_WelcomeBannerHiddenAfterFirstSubmit` (regression test)
