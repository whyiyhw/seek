### Cross-compile failure: platform-specific syscall in non-tagged file
- **Saw**: goreleaser failed with `undefined: syscall.Kill` when cross-compiling for Windows, though CI's `go build ./...` on a Windows runner had passed; the error only appeared in the release pipeline, which cross-compiles all targets from a single Linux runner.
- **Why**: `syscall.Kill(-pid, SIGKILL)` sat in `bash.go` with no build constraint; native Windows builds compile via platform-specific `syscall` re-exports, but cross-compiling FROM Linux TO Windows doesn't find the same symbols and the build fails.
- **Fix**: extracted `killProcessGroup(cmd)` into `bash_unix.go` (`//go:build !windows`) and `bash_windows.go` (`//go:build windows`), matching the pattern already used by `detachStdin`; every Unix-only syscall lives behind a build tag.
- **Lesson**: `go build ./...` on a native Windows runner is NOT a sufficient guard for cross-compilation — add an explicit cross-compile step (`GOOS=windows GOARCH=amd64 go build ./cmd/seek`) on the Linux CI runner, mirroring the goreleaser build matrix, to catch "compiles natively but fails cross-compiled" before release.
- **Refs**: `.github/workflows/ci.yml` (cross-build job), `internal/tools/bash/bash.go`, `internal/tools/bash/bash_unix.go`, `internal/tools/bash/bash_windows.go`
