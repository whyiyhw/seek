### Cross-compile failure: platform-specific syscall in non-tagged file
- **Saw**: goreleaser failed with `undefined: syscall.Kill` cross-compiling for Windows, though CI's `go build ./...` on a Windows runner passed; the error only showed in the release pipeline, which cross-compiles all targets from one Linux runner.
- **Why**: `syscall.Kill(-pid, SIGKILL)` sat in `bash.go` with no build constraint; native Windows builds compile via platform-specific `syscall` re-exports, but cross-compiling FROM Linux TO Windows can't find those symbols and the build fails.
- **Fix**: extracted `killProcessGroup(cmd)` into `bash_unix.go` (`//go:build !windows`) and `bash_windows.go` (`//go:build windows`), matching `detachStdin`'s pattern; every Unix-only syscall lives behind a build tag.
- **Lesson**: `go build ./...` on a native Windows runner is NOT a sufficient guard for cross-compilation — add an explicit cross-compile step (`GOOS=windows GOARCH=amd64 go build ./cmd/seek`) on the Linux CI runner mirroring the goreleaser matrix, to catch "compiles natively, fails cross-compiled" before release.
- **Refs**: `.github/workflows/ci.yml`, `internal/tools/bash/bash.go`, `internal/tools/bash/bash_unix.go`, `internal/tools/bash/bash_windows.go`
