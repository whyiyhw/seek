### Worktree-isolated subagent edited the MAIN tree (isolation silently bypassed)
- **Saw**: autopilot e2e — a subagent spawned with `isolation:"worktree"`, asked to append to `README.md`; the report named the worktree, but the line landed in the main repo's `README.md` (worktree untouched).
- **Why**: `read`/`edit`/`write` resolved relative paths with `filepath.Clean(a.Path)` against the PROCESS cwd, never `policy.CWD()`; `buildSubagentRunner` reused the parent's tool instances, which embed the PARENT policy — the child policy's worktree CWD was never consulted (`bash`/`git` looked isolated only because they pin `cmd.Dir`).
- **Fix**: `permission.Policy.Resolve(path)` (relative paths joined to `policy.CWD()`) in read/edit/write; `buildSubagentRunner` rebuilds the policy-bearing tools with `job.Policy`, not reusing parent instances.
- **Lesson**: a child policy's CWD is inert unless the child's TOOLS are constructed with it — in-process file tools must resolve against `policy.CWD()`; registries must not reuse parent tool instances.
