### GoReleaser owns the GitHub release — `gh release create` collides on tag push
- **Saw**: a release card saying "`gh release create` (body = the tag message)" fails with `release already exists`; the other order leaves a lightweight tag at the default-branch head that the annotated tag push cannot replace.
- **Why**: `.github/workflows/release.yml` triggers on every `v*` tag push and runs GoReleaser, whose `release:` block publishes a non-draft release (archives + auto-generated changelog) within seconds — the release object exists before a human or agent could create it.
- **Fix**: (1) push the annotated tag alone, its message being the release note; (2) wait for the `release` workflow to upload the archives; (3) `gh release edit vX.Y.Z --notes-file docs/release-notes-vX.Y.Z.tagmsg`. `gh release create` is only correct if the workflow never ran, and only after the annotated tag is pushed.
- **Lesson**: when a workflow publishes the release, the release body is an **edit**, not a **create**; the body's one source stays the `.tagmsg` file (also the annotated tag object) — v0.12.3's release body equals its tag message for exactly this reason.
- **Refs**: `.github/workflows/release.yml`, `.goreleaser.yml` (`release:` block), `docs/budget.json` CHANGELOG.md entry
