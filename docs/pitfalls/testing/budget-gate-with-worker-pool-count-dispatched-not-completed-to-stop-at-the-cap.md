### Budget gate over a worker pool: flip the flag from the emitter (completion), but stop the feeder on DISPATCH — select on a done channel, not just an atomic Load
- **Saw**: `seek judge --max-cost --parallel 4` kept calling past the cap; a test asserting "exactly 4 in flight" saw 7–8 requests. A bare `atomic.Bool` check before `jobs <- job` can't stop a send already blocked on a full worker channel.
- **Why**: only the emitter folds outcomes; the feeder may be parked on a channel send. Between `Load()` and `jobs <- …` the gate can close while a worker frees up; `select` with two ready cases picks at random.
- **Fix**: the emitter closes `budgetDone` exactly once (`atomic.Bool.Swap`-guarded) when folded cost crosses the cap; the feeder non-blocking-checks `<-budgetDone`, then `select { case jobs <- job; case <-budgetDone }`. In-flight entries drain; only NEW dispatches stop. `cmd/seek/judge.go:judgeStream`, tests `TestJudgeE2E_MaxCostStopsEarlyExitsThree` / `_MaxCostDrainsInFlight`.
- **Lesson**: a budget stop is producer-side but driven by consumer-side accounting: a channel close is the edge-triggered stop, checked on both sides of the blocking send. Test the CONTRACT (stopped before input ran out; every started call has a row), not an exact count.
