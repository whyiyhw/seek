### Batch string replacement on an SSE fixture swallowed a brace — surfaced as an unrelated test's deterministic timeout
- **Saw**: renaming a tool name inside an inline SSE `data:` line in `pkg/agent/agent_test.go` via a batch find/replace made `TestAgent_CancelDuringToolCallStreamDoesNotPoisonHistory` fail 10/10 with "never saw MessageStart from blocking server" — a *different* test than the edited line, looking like a flake but fully deterministic.
- **Why**: the replacement pattern captured two trailing `}}` but the replacement string contained only one, silently producing invalid JSON in the `data:` payload. The deepseek stream reader hit a decode error before any `EventToolCallDelta`, so `MessageStart` never fired and the test's 2s wait expired. The corruption was invisible in ordinary diffs (escaping renders the lines near-identical).
- **Fix**: re-applied the edit with an exact single-site pattern and verified bytes (`od -c`) against the original line; test went 0/10 failures. (c_cs4dw6, 2026-11-22)
- **Lesson**: the wire-format strings inside test fixtures are byte contracts (same discipline as AGENTS.md's "wire-format strings are contracts"). After any scripted edit to an embedded JSON/SSE literal, `od -c` the line against git HEAD — and when a "timeout" failure appears in a *streaming* test after touching fixtures elsewhere in the same file, suspect a silently broken fixture first, not goroutine timing.
- **Refs**: `pkg/agent/agent_test.go` (blocking-server fixture), `pkg/deepseek/stream.go` (decode error precedes event emission), AGENTS.md §Code conventions.
