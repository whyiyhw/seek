### 结束不等 run close-out 的 e2e 测试把 D-C3 写回留给了 TempDir 清理竞态
- **Saw**: TestWeb_ApprovalRunEndWithdrawsCard 隔离跑与 -count=3 全绿，但全套 `./internal/controlplane/` 在本机高负载（80+ 进程）下约 4/5 概率红，错误恒为 `TempDir RemoveAll cleanup: unlinkat …/001: directory not empty`——`/001`（newTestWeb 的第一个 TempDir）在清理时仍被写入。
- **Why**: `newStreamE2E` 的泵 `go r.Handle(ctx, m)` 镜像 Serve 的 dispatch 但没人 join 它；`cancelled` 帧由 attempt 的 defer `req.Approval.Cancel()` 发出，之后该 goroutine 还欠两步——D-C3 会话写回 `store.Put`（saveLocked 在 `/001` 内 `CreateTemp`+`Rename`）和 reply close-out。测试不等 close-out 就返回，写回便与 `t.TempDir` 的 RemoveAll 并发；go1.27 `os.RemoveAll`（at 变体）在 [Readdirnames → removedirat] 窗口内落进新文件时恰好报 `unlinkat …: directory not empty`。负载把写手拖过测试尾部（实测尾部仅 ~150-200µs）并拉宽该窗口，空载下写手先落地所以绿。ctxmeter 的 TestWeb_UsageCarriesLaneAndWindow 只等到 usage 帧（运行中段），同样暴露。
- **Fix**: 两个用例末尾各加一行 `wantFrame(t, tap, "", "conv":"web:default", "session_id":…)` 等 close-out——handlePrompt 的最后一步，观测到它即 happens-before 于 TempDir 清理（roundtrip/cmd/stream/usagebar 本就这么收尾，这两个是漏网的）。诊断证据：临时 HOLD 旋钮把写回停 400ms，修复前 cleanup 起点观测 SAL-landed=false，修复后两测试耗时恰好 = Put 次数×400ms（等待真的闸在写手上）且全绿。
- **Lesson**: e2e 测试收到「最后一个业务帧」≠ run 结束：凡走 newStreamE2E（真实 Router+Executor），收尾必须等到 reply close-out 帧，否则把异步写手留给 t.TempDir 清理去撞。给「测试尾部只有 ~200µs」这类窗口留个心眼：负载态的红别先怀疑代码逻辑，先用观测器量一量 goroutine 在 cleanup 起点还欠什么。
