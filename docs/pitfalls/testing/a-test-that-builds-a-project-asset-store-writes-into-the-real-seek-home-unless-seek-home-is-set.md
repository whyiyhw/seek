### A test that builds a project asset store writes into the real `~/.seek` unless `SEEK_HOME` is set
- **Saw**: `TestBuildACPPromptText_FileRefs` left `assets/<sha>.pdf` blobs under a new `~/.seek/projects/<id>/`, all green (2026-11-25, c_7vpiz5); under `SEEK_HOME=$tmp` nothing grows.
- **Why**: `paths.Home()` falls back to `os.UserHomeDir()+"/.seek"` when unset; construction-time resolvers (`fileroute.New`, `newVisionRouter`, `fileResolver`/`fileAssetsLoader`) inherit it; the lazy `assets.StoreDoc` (MkdirAll on first store) leaks only on attach paths.
- **Fix**: ① `t.Setenv("SEEK_HOME", t.TempDir())` at construction — test or `newTestWeb` fixture (defaults, doesn't override); ② assert the asset sits under `paths.ProjectAssets(projectAbs)` and `paths.Home()` ≠ the real home (`TestWeb_AttachStagesUsableReference` ditto `fe.attachDir`). Commits `ff848697`, c_7vpiz5.
- **Lesson**: a helper reaching `paths.*` owns process-global env — make the test prove where bytes land. Audit: `grep -rn 'fileroute.New\|assets.Store\|assets.StoreDoc\|paths.ProjectAssets' --include='*_test.go'`; every hit must sit under `SEEK_HOME` (`cmd/seek/acp_test.go`, `cmd/seek/fileresolve_test.go`, `internal/tui/commands_test.go`, `internal/worktree/worktree_test.go`, `newTestWeb`).
