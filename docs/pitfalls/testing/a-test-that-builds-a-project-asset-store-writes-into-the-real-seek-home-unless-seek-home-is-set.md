### A test that builds a project asset store writes into the real `~/.seek` unless `SEEK_HOME` is set

- **Saw**: `TestBuildACPPromptText_FileRefs` (`fileroute.New` → `paths.ProjectAssets`) left content-addressed `assets/<sha>.pdf` blobs under a brand-new `~/.seek/projects/<id>/` on the developer's machine. Every assertion in the test was green — the marker text, the `Asset` field, the part shape — because the leak is not on any assertion's path. With the one `t.Setenv("SEEK_HOME", …)` line deleted, the diff of `find ~/.seek/projects` grows by exactly `<id>/`, `<id>/assets`, `<id>/assets/<sha>.pdf` (verified 2026-11-25, butler c_7vpiz5); the same run under `SEEK_HOME=$tmp` grows nothing. It made 坑8 (unattended-lane verification) unattributable: the new project dir appears during the test window with no test to blame it on.
- **Why**: `paths.Home()` falls back to `os.UserHomeDir()+"/.seek"` when `SEEK_HOME` is unset — no cache, no per-test default. Every second-tier/generic-lane helper that RESOLVES a project path at construction (`fileroute.New`, `newVisionRouter`, `fileResolver`/`fileAssetsLoader`) inherits that fallback. The write is content-addressed (`assets.StoreDoc` MkdirAlls on first store) and lazily triggered, so a test only leaks on the code path that actually attaches a document — a suite can be "isolated" for months and leak the day someone adds an attach case.
- **Fix**: two halves, both needed. ① Set `SEEK_HOME` at the point the store is CONSTRUCTED (`t.Setenv("SEEK_HOME", t.TempDir())` in the test, or in the shared fixture — `internal/controlplane`'s `newTestWeb` carries it for the whole web surface; it defaults rather than overrides, so a test that pinned its own home keeps it). ② Assert the resolution, not just the marker: require the stored asset to live under `paths.ProjectAssets(projectAbs)` AND that `paths.Home()` is not `os.UserHomeDir()+"/.seek"`. The web sibling (`TestWeb_AttachStagesUsableReference`) does the same for staging: the returned path must sit under `fe.attachDir`, and `fe.attachDir` must not sit inside the real `~/.seek`. Assertion ② is what makes a missing fixture line red instead of a comment; with ① alone nothing catches the next regression. Commits: `ff848697` (ACP FileRefs), c_7vpiz5 (web `newTestWeb` + both assertions).
- **Lesson**: a test helper that reaches `paths.*` is a test that owns process-global env. Silence is not isolation — make the test prove where the bytes landed, or the leak returns the first time someone reorders the fixture. Audit shape: `grep -rn 'fileroute.New\|assets.Store\|assets.StoreDoc\|paths.ProjectAssets' --include='*_test.go'` — every hit must sit under a `SEEK_HOME` (this repo: `cmd/seek/acp_test.go`, `cmd/seek/fileresolve_test.go`, `internal/tui/commands_test.go`, `internal/worktree/worktree_test.go`, plus the `newTestWeb` family).
