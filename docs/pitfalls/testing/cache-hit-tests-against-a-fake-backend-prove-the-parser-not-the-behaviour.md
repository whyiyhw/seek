### Cache-hit tests against a fake backend prove the parser, not the behaviour
- **Saw**: assertions on `PromptCacheHitTokens` (`pkg/deepseek/stream_test.go`, `pkg/agent/agent_test.go`) ran against `httptest` fakes whose usage numbers the test itself wrote — a prefix-stability break (re-serialising old tool results, per-turn timestamp, reordering tool schemas) would ~10×'d cost, tests still green.
- **Why**: the fake proves the wire format round-trips; prefix-cache is a property of the BYTES across successive requests, scored only by the provider. seek maintains those bytes by convention (never modify old messages, write-time-only trimming, `TestCompose_IsDeterministic`).
- **Fix**: `pkg/agent/cache_e2e_test.go` — key-gated (`DEEPSEEK_API_KEY`, skips without key / `-short`), real multi-step turn, asserts `PromptCacheHitTokens > 0` on every turn after the first, hit+miss sums to `prompt_tokens`; turn 0 unasserted (server-side cache outlives the process).
- **Lesson**: a discipline-maintained property needs a test that fails when the discipline lapses; provider-scored ones must hit the provider — mocks set the format, one key-gated e2e the behaviour (dsh: `packages/core/agent-loop/tests/request-cache.e2e.ts`).
- **Refs**: `pkg/agent/cache_e2e_test.go`, `docs/dsh-analysis.md` §8.2
