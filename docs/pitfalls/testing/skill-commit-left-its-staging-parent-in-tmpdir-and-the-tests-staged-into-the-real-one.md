### skill_commit left its staging parent in $TMPDIR — and the skill install tests staged into the real one
- **Saw**: 3717 `seek-skill-staging-*` dirs in `$TMPDIR` (oldest 12 days), bursts of 14 lining up with full `go test ./...` runs; one `go test ./internal/tools/skillinstall/ ./internal/skillmgr/` added 7 (2026-11-28, c_7wyr6t).
- **Why**: `Commit` renames `<parent>/pkg` to the target, leaving `<parent>`. The CLI path (`skillmgr.Install`) deferred `RemoveAll(filepath.Dir(stage.StagingDir))`; the `skill_commit` tool never did → one empty dir per install. `skillinstall_test.go` pinned `SEEK_HOME` but not `TMPDIR`, so fetch-without-commit cases staged into the real temp dir via `os.MkdirTemp("")`.
- **Fix**: `skill_commit` removes the staging parent only after a successful `Commit` — failures keep the tree, since a refused or mis-argued commit is retryable (force, other scope) only while the staged files exist. Tests pin `TMPDIR` (`pinStagingTmp`); `TestCommit_UserScope`/`_ProjectScope` assert `os.TempDir()` empty after, `TestCommit_Denied`/`_NameMismatch` assert the tree survives, `TestCommit_StagingParentRemovedOnlyOnSuccess` pins the lifecycle.
- **Lesson**: a helper calling `os.MkdirTemp("")` owns process-global state (`TMPDIR`) as `paths.Home()` owns `SEEK_HOME` — the test must prove where bytes land; a two-phase API gaining a second caller must carry the first caller's `defer`s.
