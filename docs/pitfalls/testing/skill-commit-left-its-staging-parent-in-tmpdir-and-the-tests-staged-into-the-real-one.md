### skill_commit left its staging parent in $TMPDIR — and the skill install tests staged into the real one
- **Saw**: 3717 `seek-skill-staging-*` dirs in `$TMPDIR` (oldest 12 days), arriving in bursts of 14 that lined up with full `go test ./...` runs; one `go test ./internal/tools/skillinstall/ ./internal/skillmgr/` added 7 (2026-11-28, c_7wyr6t).
- **Why**: `Commit` renames `<parent>/pkg` to the target and leaves `<parent>`. The CLI path (`skillmgr.Install`) deferred `RemoveAll(filepath.Dir(stage.StagingDir))`; the `skill_commit` tool never did, so each successful install dropped one empty dir. And `skillinstall_test.go` pinned `SEEK_HOME` but not `TMPDIR`, so every fetch-without-commit case staged into the developer's real temp dir through `os.MkdirTemp("")`.
- **Fix**: `skill_commit` removes the staging parent after a successful `Commit` only — failures keep the tree, because a refused or mis-argued commit can be retried (force, other scope) only while the staged files exist. Tests pin `TMPDIR` (`pinStagingTmp`); `TestCommit_UserScope`/`_ProjectScope` assert `os.TempDir()` is empty afterwards, `TestCommit_Denied`/`_NameMismatch` assert the tree survives a refusal, `TestCommit_StagingParentRemovedOnlyOnSuccess` pins the whole lifecycle.
- **Lesson**: a helper that calls `os.MkdirTemp("")` owns process-global state (`TMPDIR`) exactly the way `paths.Home()` owns `SEEK_HOME` — the test has to prove where the bytes land, not just that the call succeeded. And when a two-phase API gains a second caller, check the first caller's `defer`s travelled with it.
