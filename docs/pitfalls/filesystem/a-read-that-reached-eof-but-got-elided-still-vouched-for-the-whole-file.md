### A read that reached EOF but got elided still vouched for the whole file
- **Saw**: I3 (full-read vouches) + I4 (cap+elide) in one commit; Observe checked only `reachedEOF && offset<=1 && !truncated` — scan terms, none about what the model RECEIVED. 70 KiB file, 100 sub-1-KiB lines: EOF untruncated, over 64 KiB cap, middle elided — Observe fired anyway, authorising overwrite of ~38 KiB unseen; in-band elision (≤32 KiB read, over-long line → 1 KiB + marker) likewise.
- **Why**: "covered the file" is a scan property, "seen every byte" a result property — elision is where they diverge; neither's tests caught it.
- **Fix**: `read` tracks both elision kinds — full-but-elided records `NoteElided` not `Observe`; `StatusElided`'s refusal names the real recovery (`edit` / ask the user), NOT "read it again" (same parts elide every time); stale outranks elided.
- **Lesson**: when two features land together, test their INTERSECTION, not each side; a guard's recovery advice must be achievable — unachievable advice is worse than none, the model retries it.
