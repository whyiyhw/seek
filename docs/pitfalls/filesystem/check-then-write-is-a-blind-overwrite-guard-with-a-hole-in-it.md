### Check-then-write is a blind-overwrite guard with a hole in it
- **Saw**: (design-time) v1 was `observer.Check(path)` followed by `os.WriteFile`; it passes single-threaded tests yet clobbers anything created between check and write — the realistic racer is the user's editor, a build, or a `git checkout` in another terminal.
- **Why**: the check answers a question about the past, an assumption by write time. dsh returns an INTENT (`createIfAbsent` / `replaceIfVersion`, `packages/fs/fs-observation-policy/src/index.ts:65-71`) resolved under a per-target lock, published via `link()` — no window.
- **Fix**: `fsobserve.Plan` returns a `Decision` (guarded? exists? token?); `write.writeGuarded` re-establishes it at the syscall — absent target → `O_CREATE|O_EXCL` (EEXIST = race winner, refused); present target → open without `O_CREATE`, stat the **fd** not the path, compare the token, then truncate+write.
- **Lesson**: a guard run before the operation guards a snapshot, not the operation — if the property must hold at write time, make it the syscall's precondition (`O_EXCL`, CAS, fd-scoped check). The disabled path needs its own branch: routing a nil-observer write through exclusive-create broke overwrites in non-opted-in tools.
