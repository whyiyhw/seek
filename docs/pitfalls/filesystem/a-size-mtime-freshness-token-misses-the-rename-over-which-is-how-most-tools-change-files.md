### A size+mtime freshness token misses the rename-over, which is how most tools change files
- **Saw**: the token was `(size, mtime)`; formatters, code generators and `git checkout` rename a temp file over the target — same size is common, coarse mtime can match, so the token reads "unchanged" and a stale write passes.
- **Why**: size and mtime describe CONTENT STATE, not whether the path still refers to the same file; rename-over changes identity, not state.
- **Fix**: the token carries `(dev, ino, size, mtime)`, matching dsh's `dev:ino:size:mtimeNs:ctimeNs` (`packages/fs/fs-local/src/fsio.ts:74-75`); on Unix from `fi.Sys().(*syscall.Stat_t)`. Off Unix `FileInfo` has no portable answer (Windows needs an open handle), so `ident_other.go` returns `(0, 0)` — degrade to size+mtime rather than invent an identity making unrelated files compare equal.
- **Lesson**: "changed?" and "same file?" are different questions; the second is what a coding agent's environment breaks. The regression test must pin size AND mtime identical so only the inode differs — else it passes wrongly.
