### O_APPEND|O_CREATE doesn't create the parent dir — a lazy-mkdir sibling silently lost the first rows
- **Saw**: The voice billing ledger (`<serve>/voice-usage.jsonl`) is opened `O_APPEND|O_CREATE|O_WRONLY` only. On a fresh host where nothing had written `~/.seek/serve/` yet, the first append failed ENOENT and the code's `best-effort` contract swallowed it into one stderr WARN — spend recorded, row lost.
- **Why**: `O_CREATE` creates the FILE, never its parent directories. The ledger looked like it worked because the sibling writer (`BindingStore.saveLocked`) MkdirAll's the same serve dir — so any host that had ever `/bind`-ed got rows, and only the paths that can precede a bind (a cron broadcast speaking before any conversation exists) silently produced nothing. A `best-effort` sink whose failure is a stderr line is invisible in exactly the ordering that exposes it.
- **Fix**: `internal/controlplane/voiceusage.go` — `appendVoiceUsageLine` MkdirAll's `filepath.Dir(path)` at 0o700 (the binding store's mode: the sibling env file holds credentials) before opening. Both lanes (TTS speaker, ASR frontend) go through that one helper, so the fix is one place. `TestAppendVoiceUsageLine_CreatesParentDir` pins it on a nested path that does not exist yet. Card c_yc2thl.
- **Lesson**: "append-only, best-effort" and "create the parent lazily" have to be decided together. If the append is allowed to fail quietly, its parent-dir creation cannot be another component's incidental side effect.
- **Refs**: `internal/controlplane/speaker.go` (TTS rows), `internal/controlplane/voicefrontend.go` (ASR rows), `internal/controlplane/bindings.go` (the sibling that did MkdirAll)
