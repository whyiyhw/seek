### Attributing a failure to the sandbox needs three gates, because the errno text alone is worthless
- **Saw**: (design-time) scanning output for "Permission denied" / "Operation not permitted" and blaming the sandbox is usually wrong — those strings are common in ordinary tool output (root-owned file, bad chmod, `find` on `/proc`).
- **Why**: the errno text describes the syscall result, not its cause; under confinement a denial and an ordinary permission problem are byte-identical in stderr — the distinguisher (jail applied to this command?) is not in the output.
- **Fix**: three gates, all required: `t.sandbox != nil`, non-zero exit, platform signature (EPERM darwin/seatbelt, EACCES linux/landlock). Runner failure (jail not applied, command never ran) uses seek's own `seek sandbox:` / `sandbox-exec:` marker, not exit code (127 is also "command not found"), and is checked FIRST (its stderr can also carry an errno phrase).
- **Lesson**: before diagnosing from a string, ask what ELSE produces it; if ordinary things do, the detector is signature plus context gates. Validate against a REAL denial — hand-written errno text proves only the matcher (`TestBash_SandboxDenial_IsAttributed` drives real seatbelt).
