### Landlock create_ruleset returns EINVAL if you "handle" an access right the kernel's ABI doesn't know
- **Saw**: (design-time, 柱 O) a fixed `handled_access_fs` mask including `LANDLOCK_ACCESS_FS_TRUNCATE` (ABI 3) / `REFER` (ABI 2) / `IOCTL_DEV` (ABI 5) fails `landlock_create_ruleset` with EINVAL on older kernels — the jail silently fails on machines most needing a fallback.
- **Why**: Landlock is versioned: `landlock_create_ruleset(NULL, 0, LANDLOCK_CREATE_RULESET_VERSION)` returns the kernel's ABI (1..N); handleable rights grow per ABI — a newer right on an older kernel is rejected, not ignored.
- **Fix**: probe the ABI, then mask the handled write-rights to it (base FS-write rights ABI≥1, REFER at ≥2, TRUNCATE at ≥3, IOCTL_DEV at ≥5). `no_new_privs` MUST be set before `restrict_self`; the trampoline FAILS CLOSED (exit 127) if the jail can't be applied — never runs the command unconfined.
- **Lesson**: for a versioned kernel LSM API, query the version and mask down to it — never hardcode the union of all features. Also confine IN-PROCESS file tools: landlock applies to the process, but only bash/git pin `cmd.Dir` (permission-side parallel: worktree-isolation pitfall).
- **Refs**: `internal/sandbox/sandbox_linux.go:applyLandlock`, `internal/sandbox/sandbox_linux_test.go`
