### StdoutPipe forbids concurrent Wait — kill-able line-streaming needs cmd.Stdout=io.Writer + io.Pipe
- **Saw**: line-streaming the seek child (RunStream, W0.1) wanted `cmd.Wait()` in a goroutine racing a timeout/kill select, but `cmd.StdoutPipe()` documents "it is incorrect to call Wait before all reads from the pipe have completed" — the obvious StdoutPipe+scanner wiring loses the tail (or hangs) on kill.
- **Why**: Wait closes the StdoutPipe read end after reaping; setting `cmd.Stdout = io.Writer` makes Wait join os/exec's own copy goroutine — compatible with concurrent Wait and kill-tree.
- **Fix**: `cmd.Stdout = pw` on an `io.Pipe`; reader goroutine does `bufio.Reader.ReadString('\n')` per line (NOT Scanner — its 64KB token cap truncates huge `tool_end.result` lines); after Wait returns, close pw so the reader folds a final unterminated line; on kill-grace expiry snapshot under mutex and walk away (card `c_n3pghs`).
- **Lesson**: kill-able stdout streaming has one sound shape — `cmd.Stdout = io.Writer` + own pipe/reader with close-after-Wait; line readers with token caps don't fit unbounded JSONL.
