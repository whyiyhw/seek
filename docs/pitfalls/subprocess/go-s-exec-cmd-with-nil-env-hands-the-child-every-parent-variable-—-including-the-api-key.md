### Go's `exec.Cmd` with nil `Env` hands the child EVERY parent variable — including the API key
- **Saw**: the bash tool never set `cmd.Env`; a model-issued `env` printed `DEEPSEEK_API_KEY`, `GH_TOKEN`, `GITHUB_TOKEN`, `OPENAI_API_KEY` verbatim, and so did every npm postinstall / Makefile it spawned. Same hole in the MCP and LSP clients (third-party binaries).
- **Why**: `os/exec` documents `Env == nil` as "inherit the current process's environment" — a maximally-permissive zero value; and the OS sandbox confines file effects only (seatbelt/landlock), so env inheritance is uncovered.
- **Fix**: `internal/childenv` name-based scrub (`KEY|SECRET|TOKEN|PASSWORD|PASSWD|CREDENTIAL` substrings + `SEEK_` prefix) at spawn points seek doesn't control: bash tool (fg+bg), `pkg/mcp`, `internal/lspclient`. Escape hatches explicit-only (`config.BashEnvPassthrough`, `ServerConfig.Env`), layered after the scrub. NOT `internal/routines/tick.go` (re-spawns seek, needs the key).
- **Lesson**: `cmd.Env = nil` is a decision — audit it wherever argv is model-chosen or the binary third-party; match variable NAMES, never values; keep the predicate narrow (`AUTH` would scrub `SSH_AUTH_SOCK` and break ssh-backed `git push`).
