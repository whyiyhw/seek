### `seek autopilot run` 车道从不升 pref，且 `--yolo` 没有可表达的位置——产线 subagent 的 bash 全被拒

- **Saw**: 2026-11-21（c_2aymtn）真跑 `seek autopilot run "<goal>"`：worktree 子代理 `edit`/`write` 成功，`bash` 一律返回 `permission denied: bash is gated; re-run seek with --yolo …`，worker 因此跑不了 `go test ./...`，只能静态自查后回报"完成"。
- **Why**: `run()` 只在 `goalMode` 分支 `policy.SetPref(permission.PrefYolo)`（`cmd/seek/main.go:1745-1750`）；`autopilotMode` 分支（`:1377-1388`）没有，pref 停在 `PrefDeny`，子代理经 `ParentPolicy.Spawn` 继承（只降不升）。想用 `--yolo` 补也补不上：flag.Parse 在第一个非 flag 参数处停止，`autopilot` 是位置参数 —— `seek autopilot run "g" --yolo` 把 `--yolo` 折进 goal 字符串（实测 Report 里 goal 就是 `noop gauge --yolo`）；`seek --yolo autopilot run "g"` 则因 `autopilotMode` 判的是 `os.Args[1]`（`:1241`）认不出车道，掉回 TUI（无 TTY 直接报错）。两种形状实测都不通。
- **Fix**: **已修（c_skczdu，2026-11-25）**。两半都修：①车道探测改读 `flag.Args()`（而不是 `os.Args[1]`），所以 `seek --yolo autopilot run "g"` 认得出车道；pref 由 `initialPreference`（`cmd/seek/autopilot_lane.go`）在 `initialPref` 处一次解出，autopilot 车道直接 Yolo —— 与 goal 车道同姿态，bash 仍被 no-remote 闸 `LaneAutopilot` 约束（`git push` 拒、`go test` 放行，`TestAutopilotLane_NoRemoteGuardStillDenies` 钉住）。②错误形状不再静默：`seek autopilot run "g" --yolo` 现在直接报 `--yolo is a flag, but flag parsing stops at the autopilot subcommand — put it BEFORE the subcommand` 并 exit，而不是把 `--yolo` 折进 goal 串（`TestAutopilotInvocation` + 二进制实测两形状）。
- **Lesson**: 无人值守车道的 pref 必须由车道自己升；「子命令在前」与「全局 flag 在后」在 Go 的 flag 语义下互斥，这个互斥只能靠**实测两条命令形状**发现，读代码不容易看出来。修的时候要注意：车道探测改 `flag.Args()` 之后**必须**顺手把「flag 误放在子命令后面」变成显式报错 —— 否则那个形状仍然静默把 flag 折进 goal。顺带：该状态下 worker 仍能改文件，"done" 与 "自己验过" 是两件事。
