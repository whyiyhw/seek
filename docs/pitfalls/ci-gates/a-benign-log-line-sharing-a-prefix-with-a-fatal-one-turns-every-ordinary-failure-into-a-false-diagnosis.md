### A benign log line sharing a prefix with a fatal one turns every ordinary failure into a false diagnosis
- **Saw**: seek's runner-failure detector matched `"seek sandbox:"` as a substring of the output — safe only because every such line in `internal/sandbox/sandbox_linux.go` is followed by `os.Exit(127)`.
- **Why**: dsh shipped this (postmortem 0004): the launcher prints `landlock-run: partial enforcement (older Landlock ABI)` on success, and the classifier matched `landlock-run: ` + any nonzero exit — so ripgrep's exit 1 ("no matches" = success) became a sandbox-failure report, breaking `glob`/`grep` on old-ABI hosts.
- **Fix**: match runner markers per line, after subtracting a `benignSandboxNotices` exclusion list compared exactly (a prefix test would re-create the ambiguity). The list is empty; new informational `seek sandbox:` output must be registered same-change (`TestDiagnoseSandbox_BenignNoticeIsNotRunnerFailure`).
- **Lesson**: when a component prints fatal and informational lines, the shared prefix is an ambiguity — subtract the informational cases explicitly and match line-scoped. dsh reserves exit 125 for launcher failure; seek reuses 127 + the marker requirement — the weaker construction.
- **Refs**: `internal/tools/bash/sandboxhint.go:benignSandboxNotices`, `internal/tools/bash/sandboxhint_test.go`, dsh `docs/postmortem/0004-landlock-partial-notice-misclassified-child-failures.md`
