### A benign log line sharing a prefix with a fatal one turns every ordinary failure into a false diagnosis
- **Saw**: seek's runner-failure detector substring-matched `"seek sandbox:"` — safe only because every such line in `internal/sandbox/sandbox_linux.go` ends in `os.Exit(127)`.
- **Why**: dsh shipped this (postmortem 0004): the launcher prints `landlock-run: partial enforcement (older Landlock ABI)` on success, and the classifier matched the `landlock-run:` prefix + any nonzero exit — so ripgrep's exit 1 ("no matches" = success) became a sandbox-failure report, breaking `glob`/`grep` on old-ABI hosts.
- **Fix**: match runner markers per line after subtracting an exactly-compared `benignSandboxNotices` list (a prefix test re-creates the ambiguity); list is empty, so new informational `seek sandbox:` output must be registered same-change (`TestDiagnoseSandbox_BenignNoticeIsNotRunnerFailure`).
- **Lesson**: a shared prefix between fatal and informational lines is an ambiguity — subtract the informational cases explicitly, match line-scoped. dsh reserves exit 125 for launcher failure; seek reuses 127 + the marker — weaker.
- **Refs**: `internal/tools/bash/sandboxhint.go:benignSandboxNotices`, `internal/tools/bash/sandboxhint_test.go`, dsh `docs/postmortem/0004-landlock-partial-notice-misclassified-child-failures.md`
