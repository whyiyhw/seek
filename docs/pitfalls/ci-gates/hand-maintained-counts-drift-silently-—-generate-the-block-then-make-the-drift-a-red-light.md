### Hand-maintained counts drift silently — generate the block, then make the drift a red light
- **Saw**: this file carried three hand-written derivations of its own body (live total, Per-section table, four-bucket rollup). Measured 2026-11-20: table summed 264 vs 268 real, Total row said 255, rollup still 34/35/43/143 — three stale generations of the same number, each partly updated by a different past edit.
- **Why**: a derived number is a second source of truth, kept in step only by whoever last edited the body remembering to re-derive. Partial updates are worse than none: fix the table but not the sentence and you have two contradictory numbers, neither detectably wrong. "Review it by eye" had no carrier — no file, no test, no gate — so it was never done.
- **Fix**: `scripts/pitfalls-count.sh` generates the header block between two HTML-comment markers from the body (`--write`) and diffs it back (`--check`), so drift is a non-zero exit naming the section; it also warns on same-prefix sections so the six merges can't regrow. Wired into `ci.yml`'s doc-budgets job + `scripts/selftest.sh`. Marker matching is whole-line and single-occurrence — a prose mention of the marker name once made `--write` duplicate the entire block.
- **Lesson**: any number summarising a file must be computed from it, where the edit happens; "keep this in sync" is a convention with no carrier, and conventions lose to whoever is in a hurry. The tell is the same number written twice in one file — that is not redundancy, it is a scheduled contradiction.
