### trace `Detail` doc said it carried token counts on a compact — the producer writes the trigger
- **Saw**: wiring the compact duration into `ui-trace` (card c_x2qga6) and reading `uitrace.Event.Detail` to decide what a jq query could group by: the field comment said "_token counts on a compact_", but `internal/tui/update_agent.go:handleCompactDone` writes `msg.trigger` (`"manual"` / `"auto"`). The tokens live in the separate `Tokens` field. A report built from the comment groups by the wrong axis and finds none of the data it expected.
- **Why**: the comment dated from the row's first iteration (before `Tokens` was split out into its own field specifically so a jq query never has to branch on event). Splitting the field left the sentence behind. Nothing tests a comment, and `TestTrace_CompactRowCarriesTrigger` only pins the produced value — so both were individually consistent while disagreeing.
- **Fix**: corrected the comment (`internal/uitrace/uitrace.go`), and while there added `DurMSByEvent` so the duration axis has an aggregate slot instead of being readable only row-by-row. A field whose *meaning* changed keeps its wire spelling — renaming `detail` would break every existing row.
- **Lesson**: when a field's payload is split (here `Detail` losing the token counts to `Tokens`), the doc comment is part of the contract and must be edited in the same commit. "The test passes" does not cover it: a test asserts the value written, never the prose that tells the next reader how to query it.
- **Refs**: `internal/uitrace/uitrace.go` (`Event.Detail`, `Summary.DurMSByEvent`), `internal/tui/update_agent.go:handleCompactDone`, `internal/uitracecli/uitracecli.go:printSummary`
