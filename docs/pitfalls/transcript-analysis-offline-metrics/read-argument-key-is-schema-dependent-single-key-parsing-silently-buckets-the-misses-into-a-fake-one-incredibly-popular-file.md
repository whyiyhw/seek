### read-argument key is schema-dependent; single-key parsing silently buckets the misses into a fake "one incredibly popular file"
- **Saw**: an analyser reading only `"path"` and bucketing every parse failure as one file gave "file read 3800+ times" — near the 68% reread rate under test. Corpus 2026-11-19: `schema_version=2` and `=3` overwhelmingly use `"path"`, 2 early calls use `"file"`, 1 puts the filename in `"offset"`, and `"file_path"` never appears in a `read` argument (only in `bash`/`edit` payloads and output).
- **Why**: an unparsed read in a shared bucket inflates the bucket's keyed file identity; the bigger the unparsed population, the more plausible the fake number. `grep file_path` on transcripts hits tool output far more than arguments — hence the "new format uses file_path" impression.
- **Fix**: `scripts/transcript-stats` resolves `path` > `file_path` > `file`; unresolvable reads go to a separate `unresolved` field, never a per-file bucket. `--read-key-mode path-only|naive-bucket` reproduces both shapes; `--selftest` asserts three modes differ (50.0% vs 37.5% vs 62.5% on the fixture).
- **Lesson**: an analyser's "can't parse" branch must be counted and named, never folded into the denominator or grouping key; confirm schema drift against *arguments* only.
