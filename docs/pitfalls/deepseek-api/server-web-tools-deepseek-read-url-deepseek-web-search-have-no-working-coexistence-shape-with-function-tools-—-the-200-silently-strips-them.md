### Server web tools (`deepseek_read_url`/`deepseek_web_search`) have NO working coexistence shape with function tools — the 200 silently strips them
- **Saw**: R0 gate tests (2026-11-14, feature-deepseek-app-api §2.2): function tool + `deepseek_read_url` → off = 400 (`client tools can only be used together with \`deepseek_web_search\`, \`deepseek_read_url\`, \`safety_check\` or \`title\` in thinking mode`)；thinking ON = 200 with the server tool stripped (no `server_tool_calls`). Unknowable probe (httpbin.org/uuid): alone-declared read_url fetches in both modes, mixed never; `deepseek_web_search` same 400.
- **Why**: undocumented server-side validation; docs forbid only mixing server tools.
- **Fix**: no code — read_url closed red (PRD §2.2, R1–R4 archived); if revisited, probe with unknowable content, never trust 200.
- **Lesson**: a 200 can succeed while the capability is gone — read the model's stated tool inventory. Also: `usage.server_tool_use` absent when all counters are zero; round-tripping `server_tool_calls`+`signature` prevents re-fetch & re-billing (dropping re-fetches); cached re-fetches still billed.
