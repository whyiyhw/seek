### `reasoning_content` rule for V4 thinking is the OPPOSITE of the old reasoner — conditional on tool_calls
- **Saw**: a multi-turn V4 thinking-mode session with a tool_call in turn 1 hit a 400 on turn 2: `The 'reasoning_content' in the thinking mode must be passed back to the API`. `pkg/deepseek.StripReasoningContent` unconditionally cleared the field on every assistant message.
- **Why**: V4 changed the contract (api-docs.deepseek.com/guides/thinking_mode): pre-V4 `deepseek-reasoner` (retired 2026-07-24) REJECTED retained prior `reasoning_content`; V4 thinking reverses it for tool-call turns — the intermediate assistant's `reasoning_content` must be passed back in all subsequent turns; plain assistant turns (no tool_calls) may still drop it.
- **Fix**: `StripReasoningContent` is now conditional — keeps `reasoning_content` on assistant messages where `len(ToolCalls) > 0`, strips everywhere else; pinned by `TestAgent_PreservesReasoningContentOnToolCallTurns` asserting the resend body.
- **Lesson**: provider contracts can REVERSE between major model versions — a pitfall load-bearing for one generation can be 100% wrong for the next; when upgrading model families, re-validate every "must" against the vendor doc.
- **Refs**: `pkg/deepseek/stream.go:StripReasoningContent`, `pkg/agent/agent_test.go:TestAgent_PreservesReasoningContentOnToolCallTurns`, api-docs.deepseek.com/guides/thinking_mode
