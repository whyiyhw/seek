### `deepseek-reasoner` without `Thinking` parameter silently behaves like fast-chat
- **Saw**: picking `deepseek-reasoner` produced fast-chat output — no chain-of-thought, no `reasoning_content` field — despite the id selecting "the reasoner".
- **Why**: V4 made thinking a request-level parameter (`Thinking.Type="enabled"`) rather than a model id; the legacy alias maps to "V4-Flash + thinking mode" per api-docs.deepseek.com, and sending it without `Thinking` falls back to plain V4-Flash, no CoT (same opt-in for `deepseek-v4-pro`; alias removal scheduled 2026-07-24).
- **Fix**: `pkg/deepseek.ShouldEnableThinking(model)` is the canonical reasoning-model predicate (`ModelV4Pro` + `ModelReasoner`); `pkg/agent.runTurnDeepSeek` sets `req.Thinking = &ThinkingMode{Type: "enabled"}` for those, and the same explicit-Thinking pattern is wired into `internal/memory/distill.go` / `dream.go` so /distill and -dream survive `ModelV4Flash` being passed directly or the alias retiring.
- **Lesson**: backward-compat aliases through a parameterised backend change semantics silently — when a provider exposes a feature as both model id AND request parameter, read the docs for the exact mapping and normalise to one shape at the boundary.
- **Refs**: `pkg/deepseek/types.go:ShouldEnableThinking`, `pkg/agent/agent.go:runTurnDeepSeek`, `internal/memory/distill.go`, `internal/memory/dream.go`
