### PrePromptHook output must be byte-stable across runs or prefix-cache collapses
- **Saw**: M5.2 M-index injection: early implementations iterated `map[string]Entry` directly; two sessions with identical on-disk M produced different injected bytes (Go map order is randomised per-process), and `prompt_cache_hit_tokens` dropped to near-zero on the second turn.
- **Why**: DeepSeek's prefix cache keys on the exact byte sequence of the prompt history; PrePromptHook output sits before the cache lookup, becomes part of the prefix, so varying bytes at the same logical state make every old message a miss.
- **Fix**: `Project.Index()` sorts by Name; `FormatLCandidatesMarkdown` sorts + dedupes its sources; `TestHook_OnPrePrompt_ByteStable` SHA-256-checks two `Hook.OnPrePrompt` invocations over the same disk state.
- **Lesson**: every `PrePromptHook` byte must be deterministic from on-disk content — map iteration, time.Now()-stamping, and "let the LLM format it" are silent prefix-cache killers. Lock determinism at the source; assert with a hash round-trip test.
- **Refs**: `internal/memory/hook.go`, `internal/memory/project.go:Index`, `internal/memory/hook_test.go:TestHook_OnPrePrompt_ByteStable`
