### DeepSeek's peak/off-peak window semantics flipped on 2026-08-16 — "off-peak is the default" inverts tier logic
- **Saw**: 2026-08-13 check: V4 pricing moved to peak/off-peak billing effective 08-16 16:00 UTC — peak = 01:00–04:00 & 06:00–10:00 UTC (09:00–12:00 / 14:00–18:00 Beijing), rest off-peak at half price; seek still had promo prices ($0.14/$0.28 flash) and window [00:30, 08:30) Beijing. After the update placeholder tests failed silently — the `noon()` helper's 12:00 "standard" representative sits on the new peak→off-peak boundary.
- **Why**: the window model inverted from "one contiguous off-peak window, standard by default" to "two small peak windows, off-peak by default"; a representative mid-window under the old rules can sit on a new boundary, where answers flip.
- **Fix**: `internal/pricing` re-based to the 08-16 card storing peak prices with the existing 0.5 off-peak discount; `CurrentTier`/`NextTransition` rewritten as a 4-segment switch; test representatives moved to mid-peak (10:00), boundaries only in dedicated cases.
- **Lesson**: annotate rate cards with "verified-on" AND "effective-on" dates; keep "representative time" helpers far from window boundaries; when a provider flips which window is default, re-check every default branch and label, not just the constants.
- **Refs**: api-docs.deepseek.com/quick_start/pricing, `internal/pricing/pricing.go`, `internal/tui/placeholder_test.go:noon`
