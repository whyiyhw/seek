### 多 GOOS 仓里 `deadcode` 只按当前 GOOS 扫描 — build-tag 下 live 的符号会被报成死码
- **Saw**: 减法卡（c_bufwel 第 6 刀，2026-11-24）拿 `go tool deadcode ./...` 的清单逐项裁决，`routines.noopNotifier` 判为「生产不可达、只被测试引用」的删除候选；实际它是 linux（`$DISPLAY`/`$WAYLAND_DISPLAY` 皆空的 headless 降级）与 windows（BurntToast 未落地前的 no-op）两条 `DefaultNotifier` 路径的 live 实现，darwin 单平台扫描当然看不到这两条边。
- **Why**: `deadcode` 是构建后的可达性分析——一次运行只覆盖**一个** `GOOS/GOARCH` 的包集合。`//go:build linux` / `windows` / `!darwin && !linux && !windows` 的变体整个不在 darwin 的包里，引用它们的代码也不在，于是符号在该次扫描里没有任何入边，被如实报成「unreachable」。同理本仓 `sandbox.Wrap`、`tools/bash` 的 `bash_{unix,windows}.go` / `proc_{linux,other_unix}.go`，以及任何 `*_windows.go` 里的实现都是同一陷阱的候选。
- **Fix**: 本次**不删**——`noopNotifier` 保留为三处 build-tag 引用（`internal/routines/notify_linux.go:26`、`notify_windows.go:20`、`notify_other.go:11`）的共用降级实现；教训落成本条目。实证命令：`GOOS=linux go build ./...`、`GOOS=windows go build ./...` 全过；`grep -rn "noopNotifier" --include="*.go" internal/` 三处非测试引用分别是 linux / windows / other 变体的赋值。
- **Lesson**: **删前必须跨平台核对 build-tag 引用**——凡候选落在「同名多文件按 `//go:build` 分派」的包里（`*_linux.go` / `*_windows.go` / `*_other.go` / `!darwin` 组合），先 `grep -rn '<symbol>' --include='*.go' .` 看**全部**变体的引用，再 `GOOS=linux` / `GOOS=windows` 各 `go build ./...` 兜一遍；单平台 `deadcode` 的「生产不可达」对这类符号是伪信号，只有「在我扫的那个平台上不可达」。跨平台复扫的正确姿势是在 host 上构建 deadcode 二进制、再 `GOOS=x` 传 env 运行（`GOOS=x go tool deadcode` 会把工具本体也按目标平台编译，exec format error）。
