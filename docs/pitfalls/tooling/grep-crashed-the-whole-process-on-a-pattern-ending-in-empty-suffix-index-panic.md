### grep crashed the whole process on a pattern ending in `**` (empty-suffix index panic)
- **Saw**: `grep path="internal/**"` panicked with `index out of range [0] with length 0` at `grep.go:389` (reproduced from a test, which re-panicked through `testing`)
- **Why**: the separator-strip was `if suffix != "" && suffix[0] == '/' || suffix[0] == filepath.Separator` — precedence makes it `(a && b) || (c)`; a pattern ending in `**` leaves the suffix empty, so the right-hand `suffix[0]` indexes an empty string. The grep tool runs in-process inside the TUI, so this is a host crash, not a recoverable tool error.
- **Fix**: `strings.HasPrefix(suffix, "/") || strings.HasPrefix(suffix, string(filepath.Separator))` — no indexing. `TestGrep_Glob_DoubleStarTrailing` pins it (`<dir>/**` must match everything below the dir).
- **Lesson**: in `a && b[i] || c[j]` shapes, short-circuit protects only the operand it guards — a mixed-precedence condition needs parentheses, or better, prefix checks (`HasPrefix`/`TrimPrefix`) that are total by construction. An unguarded panic turns a malformed argument into a dead session.
- **Refs**: `internal/tools/grep/grep.go:expandDoubleStarGlob`, `internal/tools/grep/grep_test.go:TestGrep_Glob_DoubleStarTrailing`
