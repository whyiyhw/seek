### Zero hits for the old-path grep does not mean links survived a move — relative spellings lack the prefix
- **Saw**: 4 PRDs `git mv`'d into `docs/prd/archive/` (31850170); `git grep` for the old full paths was empty, delivery claimed every reference repointed. Two targets still didn't resolve: one link text updated while its target kept the old relative spelling `./prd/<moved-file>.md`; another was one `../` short all along (`../../docs/prd/<moved-file>.md` from two directories deep) — only its filename segment rewritten.
- **Why**: rewrite and acceptance check shared one full-path string; relative spellings never contain that prefix, so replace can't reach them and grep can't see them — a check sharing the bug's blind spot is green either way.
- **Fix**: accept by resolution — resolve every relative `.md`/`.html` target to an existing path, diff against the pre-move tree (13 unrelated older pairs; `ci.yml` has no link gate); repointed both, in `docs/guide-memory.md` and `eval/cases/serve-web-stream/README.md` (c_cq77nj).
- **Lesson**: after a move, acceptance is "every link resolves", not "the old string is gone". `git grep` stays a coarse pre-filter; run a resolution pass per archive / subtraction card. Quoting a broken target verbatim makes the entry itself an old-path hit — use a placeholder.
- **Refs**: `docs/prd/archive/README.md` policy (inbound → `archive/<file>.md`); card c_cq77nj
