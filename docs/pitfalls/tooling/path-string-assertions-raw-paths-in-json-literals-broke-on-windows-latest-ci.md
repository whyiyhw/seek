### Path-string assertions / raw paths in JSON literals broke on windows-latest CI
- **Saw**: `go test ./...` red on windows-latest in three shapes: `strings.HasSuffix(p, "/foo")` failing because Windows gives `\foo`; `strings.Contains(p, ".seek/skills")` ditto; `read: bad arguments: invalid character 'U' in string escape code` from `json.RawMessage(`{"path":"`+p+`"}`)` with `p` = `C:\Users\...` — `\U` is an invalid JSON escape.
- **Why**: tests written against `filepath.Join` output on macOS/Linux assert via Unix-style literals or embed paths into JSON unescaped (JSON requires `\\`); both work locally, both break on a Windows runner.
- **Fix**: `filepath.Base(p)` for last-segment checks or `filepath.ToSlash(p)` for substring matching; build JSON via `json.Marshal(map[string]string{"path": p})` — the marshaller escapes backslashes correctly.
- **Lesson**: review any path-touching test with "what does this do on Windows?"; grep the antipatterns periodically: `HasSuffix(.*"/`, `Contains(.*"/`, `json.RawMessage(.*+.*+` — the JSON one looks like correct setup until a backslash lands inside.
- **Refs**: `internal/skillmgr/skillmgr_test.go` `update_test.go`, `internal/skill/loader_test.go`, `internal/tools/read/read_test.go`, `internal/tui/filepicker_test.go`, `internal/tools/plan/artifact_test.go`
