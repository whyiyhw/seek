### `edit` tool: small models burn turns retrying byte-mismatched `old_string`
- **Saw**: a v4-flash session ran ~10 consecutive `edit` calls on a Unicode-dense HTML file (`─` `🌙` `○` `▊`), each failing with `expected 1 replacements but old_string occurs 0 times`; ~20 wasted turns for one edit.
- **Why**: exact byte matching only; two failure classes: (1) NFC vs NFD — visually identical (`é` = `U+00E9` vs `e`+`U+0301`); (2) the error gave no near-match location, retries are blind guesses.
- **Fix**: two-tier matching in `internal/tools/edit/edit.go`: tier 1 exact; tier 2 retries after NFC-normalising both sides (file rewritten in NFC). On double miss it embeds the closest line window — scored by canonicalised line equality (NFC + strip Unicode Cf chars like ZWS/ZWJ/BOM + collapse whitespace) — plus a raw-byte unified diff. Schema bytes unchanged → prefix cache preserved.
- **Lesson**: byte-exact is the right default but hostile to non-top-tier models; fix it in the tool layer, not the prompt — a raw-byte closest-window diff is recoverable where "0 matches, broaden context" isn't. Aider's multi-tier matcher is canonical; Cursor routes through a fine-tuned "apply" model; we took the Aider path (prefix-cache neutral).
- **Refs**: `internal/tools/edit/edit.go:closestCandidate`, `internal/tools/edit/edit.go:canonForCompare`, `internal/tools/edit/edit_test.go` (NFC fallback + closest-candidate + ZWS diff cases)
