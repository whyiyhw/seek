### Grep tool with broad pattern can deadlock the agent — no recovery via /compact
- **Saw**: `grep "llm"` twice against a large codebase filled the model's context completely; `/compact` can't recover because the compact call itself needs an LLM round-trip through the already-overflowed history → hard deadlock.
- **Why**: `max_matches` (200) caps match count, not total output bytes — 20 matches × 7 context lines × variable line length (minified JS, multi-MB JSON-on-one-line) easily hits 50 KiB/call; two calls = 100 KiB ≈ 25K tokens, DeepSeek's 128K context fills, and `/compact` can't fit its own pre-prompt.
- **Fix**: two-layer cap inside `internal/tools/grep/grep.go`: `maxOutputBytes = 16 KiB` on formatted output (back up to last newline, append "(truncated at N KiB; M KiB dropped — refine pattern)") and `maxLineChars = 240` per-line (rune-aware `…(truncated)` clip). Both run inside the tool, so the byte ceiling holds regardless of `max_matches`.
- **Lesson**: a per-tool output budget is the worst case of one call, not the model's argument choice — a count cap doesn't bound bytes when payloads are variable-length; any tool returning user-content (read, grep, listdir, webfetch) needs a hard byte ceiling, and the cap-notice must say how to refine.
- **Refs**: `internal/tools/grep/grep.go:maxOutputBytes` + `truncateOutput`, `internal/tools/grep/grep_test.go:TestGrep_HardBytesCap`/`TestGrep_TruncatesLongLines`
