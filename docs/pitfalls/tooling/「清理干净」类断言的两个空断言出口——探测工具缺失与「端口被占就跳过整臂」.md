### 「清理干净」类断言的两个空断言出口——探测工具缺失与「端口被占就跳过整臂」
- **Saw**: `scripts/web-manual-nontty-test.sh` 第一版「/tmp 无残留 + 端口无监听残留」断言有两个空转出口：① `port_listening` 只调 `lsof`，无 lsof（精简镜像/PATH 裁剪）时输出空 → 恒判 `no` → 永远绿；② 端口被占时 `check_one` 直接 `return` 跳过整臂，臂内断言全没发生。脚本立身理由即禁无凭据绿（c_gqo32q）。
- **Why**: 断言的价值=能观察到反例；把观测手段（lsof、mktemp、端口）当前提，手段一缺断言即退化成 `true`。跳过规避冲突删的是断言本身，比误判更难发现。
- **Fix**: `port_listening` 在 lsof 缺失时退 `/dev/tcp` 实探；`check_one` 改用 `free_port` 找空闲端口（`$$` 散列错开并行实例），找不到就 `fail=1`；`ADDR` 由载体脚本注入子脚本，断言查同一端口。变异验证：「rc=3 + 文案对但故意留 listener/临时目录」的桩让两条清理断言转红。
- **Lesson**: 写「XX 已清理」类断言先问「观测不到『残留』时这条断言会说什么」；答案是「绿」就不是断言。规避冲突只能换能观测的样本（换端口），不能跳过断言。
