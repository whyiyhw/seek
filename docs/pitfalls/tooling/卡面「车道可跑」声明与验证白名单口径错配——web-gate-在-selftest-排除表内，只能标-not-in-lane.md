### 卡面「车道可跑」声明与验证白名单口径错配——web-gate 在 selftest 排除表内，只能标 not-in-lane
- **Saw**: 两张 web 卡把 `bash scripts/web-gate.sh` 写成 `{车道可跑：…}`：c_lbys7d 的验证会话实跑被 don't-ask 白名单拒（卡面 blocker「声明可跑、实跑被拒」），c_25d2ey 的代拍合并 decision 保留意见一「web-gate 没被独立验证……必须由主会话或人补跑」。验证车道白名单只认 `bash scripts/selftest.sh <名>` 固定入口（c_ck6djl B 方案），而 web-gate 在 selftest 排除表内——声明与入口能力结构性错配。
- **Why**: 卡面「车道可跑」是**白名单形态**的声明，不是「仓库里有这个脚本」的同义词：车道能跑的只有 `go test ./...` / `go vet ./...` / `bash -n` / `node --check` / git 只读 / selftest 固定入口那几种，`bash scripts/<任意脚本>` 一律不在名单。web-gate 被排除是结构性的，不是措辞问题：①闸语义——trip 即红是它的职责（同 verify-doc-budgets，c_i2cyb7 口径）；②测量线依赖——判据是绝对字节数对 pin，读数随工具链线（基线文件实证 1.25.8→1.27.3 差 +1.8MB）与构建目录（跨路径实测 +21KB、±9KB 抖动）漂移，车道跨目录/跨机跑出的红绿不能当验收判据。原排除理由里被截断的「构建成本」反而不是主因：本机实测 2.2s（暖 GOCACHE）/ 5.9s（冷 GOCACHE 191MB 重建）。
- **Fix**: c_5qrafk 选 B（不登记）：保留排除，把理由从被截断的成本措辞重写成结构性理由 + 卡面写法（`{not-in-lane：合并闸+测量线}`，合并后动作=主会话看三闸结果补证）；`selftest.sh` 头注释补「卡面车道声明口径」一段。web-gate 的补证点在合并处——它是合并三闸之一（doc-budgets / pitfalls-count / web-gate，c_vxh4ro 归位进 butler 合并闸），合并点必跑、验证车道不重复。
- **Lesson**: 排除了一个脚本，还得写明「卡面该怎么标」——排除表原本只回答「车道为什么不跑它」，不回答「写卡人该怎么声明」，于是下一个写卡人照样标「车道可跑」。白名单形态是封闭集合，验收点名的命令不在集合内就必须标 not-in-lane 并预填合并后动作（c_gk6cb2 两层标注）。
