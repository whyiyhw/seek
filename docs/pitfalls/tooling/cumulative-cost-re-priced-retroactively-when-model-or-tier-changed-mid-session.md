### Cumulative cost re-priced retroactively when model or tier changed mid-session
- **Saw**: switching `deepseek-v4-flash` → `deepseek-v4-pro` mid-session made `cost $X` jump ~3.1×, though prior turns billed at Flash rates; the 00:30/08:30 Beijing off-peak flip halved or doubled it.
- **Why**: `tui/statusbar.go` rendered `pricing.Cost(s.Model, s.Tier, s.Usage)` — cumulative tokens × CURRENT (model, tier), per render. `cache.Tracker` stored only `[]deepseek.Usage`, no per-turn model/tier, so the session re-priced.
- **Fix**: `cache.Tracker` stores `[]turnRecord{Usage, Model, Tier, Cost}`, locking `Cost = pricing.Cost(model, tier, usage)` at `Record`; `CumulativeCost()`/`LastCost()` return summed/last $; `StatusSnapshot.CumulativeCost float64` renders directly. All 7 `Tracker.Record` call sites (TUI, RPC, runPrint, runJSON, benchmark, session-resume, compact) pass `(model, tier)`. Pinned by `TestTracker_CumulativeCostLockedInAtRecord` (Flash→Pro→Flash: 1.43 not 0.84) + `TestTracker_TierTransitionDoesNotRePrice`.
- **Lesson**: aggregate state drops the per-event dimensions behind derived values; re-deriving at current dimensions mutates the past — store the value at write time, or the dimensions too.
- **Refs**: `internal/cache/cache.go:Tracker`, `internal/tui/statusbar.go:rightSegments`, `internal/cache/cache_test.go:TestTracker_CumulativeCostLockedInAtRecord`
