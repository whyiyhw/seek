### 排除表纪律只写在「存量复查」侧就没有闸——新增脚本照样加一行带借口的排除臂

- **Saw**: `selftest.sh` 头注释已有一条「排除理由会腐化，默认倾向重判」（c_kwiajf），但 c_gqo32q 打开文件时排除表里躺着**两条自证过时**的手测臂：`web-stream-manual` 的理由原文就写着「移出前先补 exit 3」（＝己方承认可修），`web-md-manual` 有无头分支却从没进过任何判据。此后 c_5m3fm6（web-stop-manual）、c_txz6vz、c_ni7mzw 三张 W5 卡继续撞同一面墙。
- **Why**: 那条纪律的**作用对象是已有条目**（「看到旧理由要怀疑」），对新作者完全没有约束力——写新脚本的人下次还是可以顺手加一行 `xxx-manual) echo "交互阻塞" ;;`。纪律只约束了存量，机制缺口在增量侧，于是验证车道继续一张卡一张卡地被它挡。
- **Fix**: c_gqo32q 在 `selftest.sh` 头注释补「新增门禁」三条硬口径：① 新增 `*-manual.sh` **默认不进排除表**（缺的是无头通路，那是脚本的活）；② 「有无头分支但缺非 TTY 退路」**不是合法排除理由**（`[ ! -t 0 ] → exit 3` 三行可修，非结构性）；③ 排除条目须写**结构性**理由并注明依据，理由里出现「补 X 后可移出」＝自证过时，当场重判。
- **Lesson**: 写纪律前先问「它约束的是存量还是增量」。描述既有状态的文档（排除理由、弃用清单、白名单）都只对存量生效；要挡住下一次，必须把**默认值**（新脚本进名单）和**举证责任**（排除须结构性理由）写进去——光写「记得复查」不产生闸。
