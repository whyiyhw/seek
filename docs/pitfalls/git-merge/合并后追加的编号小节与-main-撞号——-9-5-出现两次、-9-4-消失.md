### 合并后追加的编号小节与 main 撞号——`### 9.5` 出现两次、`### 9.4` 消失
- **Saw**: 卡 c_3acz3q 在分支给 `docs/prd/v8.md` §9 追加「### 9.5 内核清单修订…」，main 同时新增「### 9.4 止损线读数」「### 9.5 R2 落地记录」；`git merge main` 不报冲突（两处新增文本不重叠），合并结果两个 9.5、没有 9.4，独立验证才抓出来。
- **Why**: `### 9.x` 是手写序号，git 只做文本合并，不知道序号是共享命名空间；两边同时「追加到列表末尾」，各自占用同一个"下一个号"。
- **Fix**: merge 后按号核对：`awk '/^### 9\./{print NR": "$0}' <file>`；重号把本卡小节改到最大号之后（9.5→9.6），main 两节原样保留（`git show main:<file>` 节区段与当前文件逐字相等）；再 `grep -rn '§9\.[0-9]'` 改交叉引用。
- **Lesson**: 往手写编号列表追加条目是合并冲突的隐形形状——文本不冲突，语义冲突；merge 后按编号机械核对，别信 "Automatic merge went well"。
