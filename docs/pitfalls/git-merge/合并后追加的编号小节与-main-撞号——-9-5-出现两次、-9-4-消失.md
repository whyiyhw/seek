### 合并后追加的编号小节与 main 撞号——`### 9.5` 出现两次、`### 9.4` 消失
- **Saw**: 卡 c_3acz3q 在分支里给 `docs/prd/v8.md` §9 追加了「### 9.5 内核清单修订…」，而 main 同时新增了「### 9.4 止损线读数」「### 9.5 R2 落地记录」。`git merge main` **不报冲突**（两处新增落在不同位置，文本不重叠），合并结果成了两个 9.5、没有 9.4；读者按「§9.5」查引用时指向哪节取决于读的是哪一行，独立验证才抓出来。
- **Why**: 编号小节（`### 9.x`）是**手写序号**，git 只做文本合并，不知道序号是共享命名空间；「追加到小节列表末尾」这个动作在两边同时发生，于是各自占用了同一个"下一个号"。
- **Fix**: merge 后按号核对一遍：`awk '/^### 9\./{print NR": "$0}' <file>`；重号就把本卡小节改到**最大号之后**（本节 9.5→9.6），main 的两节原样保留（逐字比对：`git show main:<file>` 的节区段与当前文件相等）；再 `grep -rn '§9\.[0-9]'` 把交叉引用一并改。
- **Lesson**: 往「手写编号列表」追加条目是合并冲突的**隐形形状**——文本不冲突，语义冲突。merge 后要按编号做一次机械核对，别信 `git merge` 的 "Automatic merge went well"。
