### 派生生成块的合并冲突不能「挑一侧」——解完必须重跑生成器
- **Saw**: 卡 c_nqvbdu 两轮 `git merge main` 都在 `docs/pitfalls.md` 的 `<!-- pitfalls-count: BEGIN … -->` 块内冲突（live 数字 / `| **Total** |` 行 / 四桶 rollup），正文其余自动合并干净；挑任一侧数字都「看着没冲突」，但两侧都错——数只对各自合并前的正文成立。
- **Why**: 生成块是正文的函数（`scripts/pitfalls-count.sh` 从 `### ` 条目算），双方各跑过 `--write`，「当时正确、现在过期」；合并后正文是两边条目并集，任一侧数字都少算对方增量——挑一侧即手写派生数（见「Hand-maintained counts drift silently」条）。
- **Fix**: 不逐数字比对，留任意一侧（或删整块）跑 `bash scripts/pitfalls-count.sh --write`，再 `--check` 收绿（本卡合并后 283 live 一次通过）；丢条目核对靠标题集合：`我方 ### 集合 ∪ main ### 集合 == 合并后集合`。
- **Lesson**: 对派生值两侧都不是答案——重算；生成块/计数表类派生物的 merge 解法永远是「丢两边的值，重跑生成器」。
- **Refs**: `scripts/pitfalls-count.sh`（`--write` / `--check`）、`docs/pitfalls.md` §Status 生成块；card c_nqvbdu 两轮合并。
