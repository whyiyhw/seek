### 派生生成块的合并冲突不能「挑一侧」——解完必须重跑生成器
- **Saw**: 卡 c_nqvbdu 两轮 `git merge main` 都在 `docs/pitfalls.md` 的 `<!-- pitfalls-count: BEGIN … -->` 块内报冲突（live 数字 / `| **Total** |` 行 / 四桶 rollup 三处），正文其余部分自动合并干净。挑任一侧的数字都能让文件「看着没冲突」，但两侧都错——块里的数只对各自合并前的正文成立。
- **Why**: 生成块是正文的**函数**（`scripts/pitfalls-count.sh` 从 `### ` 条目算），双方各跑过一次 `--write`，两边都是「当时正确、现在过期」。合并后的正文是两边条目的并集，任何一侧的数字都少算了对方的增量。挑一侧 = 手写派生数，正是这条生成块要消灭的东西（见「Hand-maintained counts drift silently」条）。
- **Fix**: 解冲突时**不要**逐数字比对，直接留任意一侧（或删掉整块）跑 `bash scripts/pitfalls-count.sh --write`，再用 `--check` 收绿。本卡合并后正文 283 live，`--check` 一次通过。核对有没有丢条目靠标题集合而非数字：`我方 ### 集合 ∪ main ### 集合 == 合并后集合`。
- **Lesson**: 冲突标记告诉你「这里两边都改过」，但对派生值而言**两边都不是答案**——答案是重算。凡是生成块/计数表/清单这类派生物，merge 的正确解法永远是「丢掉两边的值，重跑生成器」，而不是三方比对。
- **Refs**: `scripts/pitfalls-count.sh`（`--write` / `--check`）、`docs/pitfalls.md` §Status 生成块；card c_nqvbdu 两轮合并。
