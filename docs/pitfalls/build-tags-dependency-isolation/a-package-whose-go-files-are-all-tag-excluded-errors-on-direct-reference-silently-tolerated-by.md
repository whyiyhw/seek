### A package whose .go files are ALL tag-excluded errors on direct reference, silently tolerated by `./...`
- **Saw**: gating the feishu frontend SDK behind `//go:build feishu` with only tagged files, go1.27 silently skips the package in `go build`/`go vet`/`go test ./...` — only directly naming it (`go build ./internal/.../pkg`) or importing it from untagged code errors ("build constraints exclude all Go files").
- **Why**: pattern-matched packages with zero matching files are dropped from the pattern expansion, while an explicitly named package must produce a build result and has none to produce.
- **Fix**: keep an untagged `doc.go` as package anchor (carries the tag contract in godoc) and assert the default-build `GoFiles == [doc.go]` via `go/build.Default.ImportDir` in an ordinary CI test (`internal/controlplane/buildtags_test.go`) — go/build evaluates //go:build per tags without spawning builds.
- **Lesson**: `./...` staying green does NOT prove a tag-gated package is wired right — prove the gate both ways: default tags exclude the file (go/build assertion in CI) and `-tags feishu` compiles AND runs it.
- **Refs**: `internal/controlplane/feishu/doc.go` (anchor), `internal/controlplane/buildtags_test.go`, `docs/serve/README.md` "build-tag 依赖隔离"、docs/book/chapter-24.md
