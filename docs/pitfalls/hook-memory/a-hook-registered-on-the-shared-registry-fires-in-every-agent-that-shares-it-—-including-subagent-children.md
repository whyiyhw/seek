### A hook registered on the shared Registry fires in EVERY agent that shares it — including subagent children
- **Saw**: `hooksReg.Register(subagent.NewNotifier(mgr))` silently corrupts delivery: `buildSubagentRunner` hands every child `agent.New` the same `*hooks.Registry`, so a child's `Prompt` also runs `ApplyPrePrompt` — a background sibling's completion notice drains into the child's transcript (wrong session file; the parent never sees it).
- **Why**: the registry is shared parent+children by design (pre_tool deny / post_tool audit must cover subagent calls), and children read it at spawn time after everything is registered — ordering can't scope a hook to the parent.
- **Fix**: `hooks.Registry.CloneWithout(exclude)` — children resolve their registry via a lazy `hooksFn` closure (`hooksReg.CloneWithout(bgNotifier)` per spawn): every hook so far minus the parent-only drain point. Notifier DRAINS the inbox; the TUI wake PEEKS (`PendingNotices`) — one consumer per semantics. Card c_bickfj.
- **Lesson**: registering a hook broadcasts to every agent sharing the registry — parent-scoped hooks need explicit exclusion at the child boundary, lazy (closure) when the registry grows after the children's factory is built.
