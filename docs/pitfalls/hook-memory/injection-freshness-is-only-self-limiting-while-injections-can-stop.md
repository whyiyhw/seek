### Injection-freshness is only self-limiting while injections can stop
- **Saw**: the fast path injects EVERY non-stale M-index entry, refreshing `last_injected_at` each session; under the 1500-token budget the active set is exempt from the stale cliff.
- **Why**: "injection is effective use" (c_ff4pcp) counts freshness against the names `buildMIndex` injected; the exemption is bounded by three stop channels: born-stale exclusion (`Index()` skips stale), token-budget squeeze, and project abandonment.
- **Fix**: accounting set = injected set (`injectSnapshot` touches exactly `buildMIndex`'s returned names); each locked by a test: `TestLifecycle_InjectedEntrySurvivesDay21`, `TestHook_OnPrePrompt_TruncatedEntriesNotTouched`, `TestLifecycle_FreshnessExpiresWhenInjectionStops`.
- **Lesson**: freshness follows the injected bytes, not the entry table — widening the injection surface (raising `maxMIndexTokens`, injecting outside `buildMIndex`, delta-path touching with the full entry list) makes the exemption permanent; every new injection site re-derives its touched set from what landed in the prompt.
