### `seek -upgrade` returned raw "permission denied" — users couldn't see they needed sudo
- **Saw**: plain `seek -upgrade` hit `upgrade: replace /usr/local/bin/seek: rename ... permission denied` — the install one-liner ships the binary via `sudo tar -xz` (root-owned dir), so `os.Rename` fails for any non-sudo run, and nothing said "try sudo".
- **Why**: `internal/upgrade/replace.go:replaceBinary` wrapped the rename verbatim (`fmt.Errorf("upgrade: replace %s: %w", ...)`) — right for `errors.Is(err, fs.ErrPermission)` chaining, but the POSIX strings don't suggest the fix.
- **Fix**: on `errors.Is(err, fs.ErrPermission)` rewrite to `upgrade: cannot write <path> — requires elevated privileges. Try: sudo seek -upgrade`; `replace_windows.go` → "Re-run from a PowerShell launched as Administrator" (elevation, not the unix command); tests chmod a target dir `0o555`; other errors keep the original wrap.
- **Lesson**: when an OS error has a known remediation its own message doesn't suggest, rewrite at the boundary — the branch is one `if errors.Is`.
