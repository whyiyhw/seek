### A refusal the model does not learn from is a pure tax — auto-fix unambiguous intent instead
- **Saw**: the git tool's duplicated-subcommand guard (`git diff --stat` as subcommand "diff" + args ["diff","--stat"]) refused naming the correct shape, yet DeepSeek repeated the mistake twice in four consecutive calls — a wasted round trip each.
- **Why**: an in-error correction teaches only within its turn — the next call is built fresh from schema + attention, so a systematic arg-construction tic makes refusals recurring cost with no compounding benefit.
- **Fix**: the guard now DROPS the duplicated subcommand and runs the intended command, prepending a note naming the effective invocation (`ran `git log --oneline -n 5``) and genuine same-named path/ref forms — same philosophy as read's directory→listing fallback.
- **Lesson**: before refusing a malformed-but-unambiguous call, ask if the model learns across calls (check transcripts, not hope) and the worst case of auto-fix (read-only → recoverable); refuse dangerous/ambiguous, auto-fix-and-note the rest.
