### /compact's own rescue call cannot fit an overflowed context — the recovery path was the deadlock
- **Saw**: once history overflows the window, `/compact` sends the FULL history to the summariser and gets the same `maximum context length` 400; reproduced in `TestSummarise_OverflowRescue_Completes` (≈159K vs 128K window) — unrecoverable in-app.
- **Why**: `Summarise` took the untrimmed history by design — a rescue needing the resource it recovers cannot terminate.
- **Fix** (c_idisqf): `pkg/agent/compact_rescue.go`, both lanes — `estimateTokens` (ASCII ≈4 B/token, CJK ≈1 token/rune) against `budget.Limit(model)` − output reserve; stage 1 caps oversized bodies (keep-head + marker; content cuts can't break pairing), stage 2 drops OLDEST messages (never system or the summariser turn), skipping cuts that orphan a tool result; elision note in the prompt; one half-budget retry on `isContextOverflowError`; fitting histories pass byte-unchanged (`TestSummarise_NormalPath_BytesUnchanged`).
- **Lesson**: size recovery paths to run in the state they recover; cuts must respect wire invariants (tool_call/tool_result pairing) — truncate content, keep structural messages.
