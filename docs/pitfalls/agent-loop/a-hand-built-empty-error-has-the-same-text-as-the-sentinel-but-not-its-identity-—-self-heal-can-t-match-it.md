### A hand-built empty error carries the sentinel's TEXT but not its identity — the self-heal gate can never match it
- **Saw**: `opencode:deepseek-v4.1-flash` sessions kept dying mid-task with `_seek_turn_stop stopReason=internal_error detail="agent: model returned an empty response (no content and no tool calls)"` — 8+ times on 11-20, twice on 11-24, and card c_trrsn7 on 11-25 (all on that one lane, all with zero file changes on the branch). `/tmp/seek-acp.log` showed the same speech going back to 11-20 with no fix in sight
- **Why**: three defects stacked. (1) `pkg/llm` has NO reasoning channel — `openai/client.go:streamDelta` doesn't declare `reasoning_content` (same shape as the documented GLM variant), so a thinking-heavy turn emits zero events and `started` stays false. (2) The second-tier budget is `a.cfg.MaxTokens`, not `a.turnMaxTokens()` — the `/effort max` 64K linkage only ever applied to the DeepSeek first-class path, so the hidden thinking burned the whole 16384 and closed with `finish_reason="length"`. (3) That combination (nothing streamed + finish≠stop) hit the guard's `errors.New(...)` fallback — a FRESH error value with the sentinel's text. `Prompt`'s gate is `errors.Is(err, errEmptyResponse)`, which is identity, not string: the branch was unreachable by construction, so the whole self-heal family (`c_jdel6u` / `c_7kco3z` / `c_geyjoo`) silently skipped it and `ErrorEvent` ended the session
- **Fix**: `errBudgetExhaustedEmpty` sentinel (third member of the family, deliberately NOT retryable and deliberately NOT `errEmptyResponse`) + `budgetExhaustedMarker` (`[empty: 上游结束原因非 stop 且零内容…，未重试]` — the clean-empty marker claims `已重试1次`, which this shape never is). `Prompt`'s gate now accepts all three and books the matching marker. Same commit adds the two siblings that shared the dead path: `runTurnLLM` never called `isSafetyRefusal`, so a deliberate `refusal`/`content_filter` was booked as an empty response; and the openai assembler's `for i := 0; i < len(accum); i++ { if a == nil { break } }` dropped every tool call AFTER an index hole and emitted nothing at all, which looked exactly like an empty completion
- **Lesson**: an error's *text* is for humans, its *identity* is for control flow — a guard whose recovery is `errors.Is` must be the ONLY place that value is constructed, so never inline `errors.New` in a branch that a sentinel already covers. Corollary for lanes: a client that can't see part of the upstream's output cannot distinguish "the model said nothing" from "the budget went into output we don't parse", so an empty-with-odd-finish is a normal lane outcome, not a fatal one
