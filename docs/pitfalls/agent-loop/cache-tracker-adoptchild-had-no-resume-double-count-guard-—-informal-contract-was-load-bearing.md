### `cache.Tracker.AdoptChild` had no resume-double-count guard — informal contract was load-bearing
- **Saw**: v5 柱 G audit: `AdoptChild` documented the SAFETY contract "never adopt a child already folded into `baseUsage`" but enforced nothing — resume code re-adopting restored Trackers post-`SetBase` would silently double-count in `Cumulative()`/`CumulativeCost()` (wrong dollar figure, no panic/log).
- **Why**: prior validation only blocked spawn-depth > 1; `SetBase` seeds `baseUsage` with last-session cumulative INCLUDING every child, so walking a re-adopted child via `children` adds them again — dormant today (children die with their session).
- **Fix**: `hasBase bool` set by `SetBase`; `AdoptChild` captures `childHasUsage` under `child.mu`, pointer-dedups first (spawn-retry idempotence), then panics if `t.hasBase && childHasUsage`; tests pin both panic and both pass-through branches.
- **Lesson**: a doc-only contract is a regression deferred — cheap check + silent-mis-pricing failure means write the runtime guard; the nested-children panic is the precedent.
