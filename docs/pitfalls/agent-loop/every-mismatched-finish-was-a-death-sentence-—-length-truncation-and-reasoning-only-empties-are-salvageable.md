### Every mismatched finish was a death sentence — `length` truncation and reasoning-only empties are salvageable
- **Saw**: two ways a long unattended run died mid-task on the flash lane on 11-21. (a) A single turn emitted two large-argument `Write` tool_calls and closed with `finish_reason="length"` (16K default `turnMaxTokens`) — `Prompt` refused to commit the turn and returned, ending the session (6529…/628903ab). (b) A reasoning model streamed `reasoning_content` and then went silent (`finish=stop`, no content) — the empty guard's hard error ended the session too (c_geyjoo)
- **Why**: both branches were written for *correctness* reasons (unverified `tool_call_ids` orphan the transcript; an assistant message with neither content nor `tool_calls` 400s the next request), and correctness was implemented as "surface an error and stop". But neither invariant says the *session* must end: a `length` cut carries a known reason, and a reasoning-only stream has already been billed and rendered — the turn is recoverable with a marker plus, for `length`, a corrective user nudge. A hard error in `Prompt` is a session-level outcome, so any guard whose only job is "this turn's shape is uncommittable" over-reaches
- **Fix**: `pkg/agent/agent.go` Prompt loop: (a) `finish=length` + `tool_calls` drops the unverified calls, keeps streamed text or stamps `truncationMarker`, emits the existing visible notice, appends a user nudge ("被输出上限截断（max_tokens=N）… 一次只发一个调用、参数拆小") and continues; `truncationHardStop=2` consecutive salvages → clear error, reset by any productive turn. (b) both `runTurn` paths return the new sibling sentinel `errReasoningOnlyEmpty` (same text as `errEmptyResponse`, added to the `:707` self-heal gate, deliberately NOT added to `canRetry`) and book `emptyResponseMarker` as content *inside runTurn* (where `started` is known) so no second `MessageStart` opens; both count into `emptyPlaceholders`. Every other mismatched finish keeps the original refusal
- **Lesson**: when a guard's failure is "this turn is not committable", separate *the turn* from *the session*: drop the uncommittable part, book a wire-legal marker, and keep the loop alive behind a consecutive-failure gate. Also: when a marker must be emitted where the UI-block state (`started`) is known, emit it there — the loop cannot tell whether `MessageStart` already fired, and guessing wrong double-renders the reasoning
