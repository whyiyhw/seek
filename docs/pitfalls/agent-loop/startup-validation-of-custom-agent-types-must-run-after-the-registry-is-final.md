### Startup validation of custom agent types must run AFTER the registry is final
- **Saw**: P2-b's D13 startup pass (warn when a custom type's `tools` aren't in the parent registry), placed next to `agenttypes.Load` or at Manager construction, flags `plan`/`propose` as unknown for EVERY custom type — they are `reg.Add`ed later than both points.
- **Why**: the parent tool registry is built in stages (initial set → `agent.New` → agent tool → plan/propose → memory_observe, some env-gated); `ManagerOpts.ParentToolNamesFn` is a closure for this reason. Any snapshot taken before the last `reg.Add` is a partial registry.
- **Fix**: the pass runs after the last registration in `cmd/seek/main.go` (comment pins the constraint); spawn-time resolution (`Manager.resolveType` → `ResolveCustomType`) re-checks against the live `ParentToolNamesFn()` as the authority, so the startup pass is UX only.
- **Lesson**: "validate against the registry" needs a registry-final anchor: gate validation at the point of use (spawn), treat startup passes as advisory echoes — else staged construction manufactures phantom config errors.
- **Refs**: `cmd/seek/main.go`, `internal/subagent/manager.go` (`resolveType`), `internal/subagent/custom.go`
