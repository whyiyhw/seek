### Symlinked CWD made every RELATIVE `write` compare "outside" — the escape fix over-tightened
- **Saw**: under symlinked CWD (macOS `/tmp`→`/private/tmp`), `write`/`edit` with RELATIVE paths denied "outside the working directory" (print/Ask); absolute paths worked (c_7hudp6).
- **Why**: `isWithin` canonicalised the sides on different bases — root via `EvalSymlinks` (physical), relative target from `resolveClosest` + `filepath.Abs` onto the logical `PWD` (`Abs` never resolves symlinks; `os.Getwd` prefers `PWD`), so `Rel(physicalRoot, logicalTarget)` starts `..` → outside.
- **Fix**: both sides through one pipeline: `Abs`, then symlink resolution (`EvalSymlinks` root, `resolveClosest` target: not-yet-existing files OK); `..` and symlink-escape denials hold; `permission.TestIsWithin_RelativePathUnderSymlinkedCWD` builds an explicit symlink (reproduces on Linux); commit `a191f45`.
- **Lesson**: containment checks mean anything only when BOTH operands were canonicalised by the same pipeline in the same order — `filepath.Abs` is lexical, `EvalSymlinks` physical (macOS `/tmp`/`/var`/`$TMPDIR` are symlinks).
- **Refs**: `internal/permission/permission.go:isWithin`, `resolveClosest`; prior entry "Symlinks inside CWD let `write`/`edit` escape the CWD gate" (the fix whose asymmetry caused this)
