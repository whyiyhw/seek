### ProjectID hashes the path STRING, not the directory — one physical dir via /tmp and /private/tmp is two projects
- **Saw**: 2026-11-13 paseo smoke (c_bnjrw5): the same dir as `/tmp/...` vs `/private/tmp/...` gave two ProjectIDs (be6a800f… vs 6e7915a5…) under `~/.seek/projects/`.
- **Why**: `paths.ProjectID` = `sha256(absPath)[:16]`; macOS `/tmp` symlinks to `/private/tmp`, and `os.Getwd` returns the shell's logical `$PWD` when it stats equal to `.` — spelling follows arrival, not location.
- **Fix**: c_4c6dar (`5bc9846`): keep ProjectID byte-pure — canonical-path contract pinned by `TestProjectID_AliasSpellingsDiffer`, no internal EvalSymlinks; callers EvalSymlinks cwd once; `<project>/.seek/project-id` (`internal/memory` `resolveProjectID`) pins the ID per physical dir.
- **Lesson**: internal EvalSymlinks is an identity migration in disguise: it errors on not-yet-created paths (worktrees anchor before dirs exist) forcing a silent fallback, and re-keys stored symlinked paths, orphaning pointer-less state (checkpoints, subagents.jsonl, plans/, assets/); revisit only if a lane reconciles state across machines by ProjectID.
