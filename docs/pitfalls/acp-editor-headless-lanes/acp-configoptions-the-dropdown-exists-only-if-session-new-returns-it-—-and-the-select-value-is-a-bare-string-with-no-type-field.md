### ACP configOptions: the dropdown exists only if session/new RETURNS it — and the select value is a bare string with no "type" field
- **Saw**: model selection (c_6thhqc): `paseo provider diagnostic seek` printed `models=0; modes=0` while the agent was fully functional — no dropdown, no `set_config_option` traffic.
- **Why**: ACP session configuration is a pull contract — the client renders ONLY what `session/new` returns (`configOptions`; `modes` likewise), and unknown methods stay -32601. Wire specifics: `SessionConfigOption` is discriminated by `type` ("select"|"boolean") with the payload FLATTENED onto the same object (`currentValue`/`options` inlined next to `id`/`name`); `session/set_config_option`'s string variant carries `value` as a BARE string with no `type` field (the boolean variant carries `type:"boolean"`); the response must echo the FULL `configOptions` — a partial echo blanks the menu.
- **Fix**: `internal/acp/server.go` (types + dispatch) + `cmd/seek` acpBackend (`acpModelMenu`, value ids `"<provider>:<model>"`) — c_6thhqc; shape read from the bundled SDK (`~/.paseo/zcode-acp/node_modules/@agentclientprotocol/sdk/schema/schema.json`), cross-checked against zcode-acp-server's `CONFIG_META`.
- **Lesson**: ACP capability discovery is "what the agent reports", never "what the agent supports" — a healthy handshake with an empty result set silently filters the UI; reverse the local SDK schema FIRST.
