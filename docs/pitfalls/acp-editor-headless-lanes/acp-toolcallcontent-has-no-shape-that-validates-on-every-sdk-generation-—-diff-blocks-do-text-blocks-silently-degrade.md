### ACP ToolCallContent has NO shape that validates on every SDK generation — diff blocks do; text blocks silently degrade
- **Saw**: v1 `(Content & {type:"content"})` → zod `zContent.and(type:"content")` (`type` both "text" and "content"); a text-block send stuck every call in_progress.
- **Why**: `oneOf {type:const}+allOf $ref` codegen breaks when the $ref has a conflicting discriminator; `x-deserialize-default-on-error` silently skips failing items, but paseo's `zToolCallUpdate` is bare `z.array(zToolCallContent).nullish()` — one failing item fails the whole update (status/rawOutput never land).
- **Fix**: content = edit-success DIFF blocks (`{type:"diff", path, oldText, newText}`); text blocks never sent; detail rides rawOutput/rawInput as PARSED objects + `title` arg summary (77f2250).
- **Lesson**: check the client's bundled SDK (its mock agent is the reference shape); prefer shapes without conflicting discriminators; send only provably-valid items or none when array leniency is unknown; binary grep over .asar misses — `grep -abo` + byte slicing.
- **Refs**: `cmd/seek/main.go` `acpToolContent` / `acpRawValue` / `acpToolTitle`, `@agentclientprotocol/sdk` dist/schema/zod.gen.js `zToolCallContent`, paseo.app asar (bundled SDK zToolCallContent ~byte 2619232, zToolCallUpdate's bare `z.array(zToolCallContent)` ~2622104; mock agent's rawInput/rawOutput objects ~2559484), paseo app-dist frontend `toolCallDetails:{input,output,empty}`, zcode-acp-server dispatch.js:406
