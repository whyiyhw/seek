### Session cwd has TWO resolution conventions — anchoring only one leaves half the toolbox in the daemon's dir
- **Saw**: `seek acp`'s `NewSession` ignored `session/new`'s `cwd` — invisible under Zed (same dir), but headless clients (paseo) spawn the child without a cwd, inheriting the daemon's (usually `/`); re-anchoring `permission.Policy` alone still left `git` (no cmd.Dir pin) and `grep`/`list_dir` (WalkDir on the raw relative path) in `/`.
- **Why**: the tool layer deliberately runs two cwd conventions — policy-anchored (file tools + bash) and process-anchored (walking tools + exec defaults); a session-level cwd must move BOTH anchors.
- **Fix**: `acp.AnchorSession`: `os.Chdir(abs)` + `Policy.Reanchor(abs)` as one atomic step; an unenterable cwd fails the session loud (-32000). `Policy.Reanchor` is the one sanctioned post-construction cwd change — tools hold the `*Policy` by pointer.
- **Lesson**: "make cwd effective" is TWO operations; any per-session cwd consumer must go through both anchors (Zed sends its spawn dir, so anchoring is a no-op there).
