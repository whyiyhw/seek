### The turn gate serialises turns — it is not a memory-safety edge for the read loop
- **Saw**: c_5flg7r round 1: a second `session/new` mid-turn read `b.sess.Model/SystemPrompt/Yolo/Plan/Effort` while the turn goroutine wrote them; tests only hit it idle, yet a torn session-ID produced `rename … invalid argument` in `store.Save`.
- **Why**: `session/new` runs INLINE in the serial read loop, skipping the in-flight checks of `session/load`/`set_config_option`/`set_mode` (a second panel must not queue behind a turn) — a read-loop method shares NO memory edge with the turn goroutine.
- **Fix**: cross-gate session-slot access takes `b.mu` on BOTH sides (`NewSession`+insert, `saveTurn` — disk save on a copy, outside the lock — `activate`, `deactivate`); `TestACPBackend_MultiSession_NewDuringTurn{FreshBranch,FirstBranch}NoRace` red before / green under `-race`. Rejected: startup snapshot — reverts the fresh branch's inheritance of the INSTALLED session's lane.
- **Lesson**: a serialisation gate is a protocol edge; ungated code needs a real lock every holder takes. `-race` green means no unsynchronised pair was EXECUTED, not that none exists — drive both sides from separate goroutines (no happens-before edge).
- **Refs**: `cmd/seek/main.go` (`acpBackend.mu`), `internal/acp/server.go` (dispatch), `docs/guide-architecture.md` §12
