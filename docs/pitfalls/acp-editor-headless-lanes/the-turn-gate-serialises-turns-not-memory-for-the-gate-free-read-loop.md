### The turn gate serialises turns — it is not a memory-safety edge for the read loop
- **Saw**: Independent verification of ACP·P1-2 (c_5flg7r round 1) flagged a data race: a second `session/new` arriving while another session's turn is in flight read `b.sess.Model/SystemPrompt/Yolo/Plan/Effort` unlocked while the turn goroutine wrote the same slot (`saveTurn`'s `b.sess.Model = …`, `activate`'s `*b.sess = *st.sess`). Every existing test called `session/new` while idle, so `-race` was green — and the damage is real, not theoretical: a torn session-ID string header produced `rename … invalid argument` from `store.Save` under the race load (garbage path bytes from a half-old-half-new string).
- **Why**: `internal/acp`'s dispatch runs `session/new` INLINE in the serial read loop, deliberately without the in-flight checks `session/load` / `set_config_option` / `set_mode` have (a client opening a second panel must not queue behind the first conversation's turn). The turn gate therefore orders turn-side traffic only — a read-loop method shares NO edge with the turn goroutine, so plain field reads there are unordered writes-vs-reads in the Go memory model, however unlikely the wall-clock overlap.
- **Fix**: every cross-gate access to the live session slot takes the backend mutex on BOTH sides — `NewSession`'s slot block (merged with the table insert into one hold), `saveTurn`'s field writes (disk save runs on a private copy outside the lock), `activate`'s install, `deactivate`'s pull-back; `b.mu`'s doc comment now states the invariant. Proven by `TestACPBackend_MultiSession_NewDuringTurn{FreshBranch,FirstBranch}NoRace` (`cmd/seek/acp_multi_test.go`), red before the fix (write `main.go` activate vs read `main.go` NewSession — the verifier's exact sites) and green after under `-race`. Rejected alternative: snapshotting the template (Model/SystemPrompt/…) into immutable fields at construction — race-free but silently changes semantics, because the fresh branch inherits the INSTALLED session's current lane (a model switch in panel A should carry into panel B), which a startup-time snapshot reverts.
- **Lesson**: a serialisation gate (channel/mutex that some goroutines never take) is a protocol edge, not a memory edge — anyone who can run without the gate needs a real lock, and the lock needs every gate-holder to participate too (a mutex only excludes when everyone takes it). Also: `-race` green means "no unsynchronised pair was EXECUTED", not "none exists" — tests must drive the two sides from separate goroutines with no happens-before edge (the detector's vector clocks then flag the pair even without wall-clock overlap).
