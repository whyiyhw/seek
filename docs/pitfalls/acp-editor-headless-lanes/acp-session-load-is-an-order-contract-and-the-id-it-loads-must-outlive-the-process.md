### ACP session/load is an ORDER contract, and the id it loads must outlive the process
- **Saw**: `loadSession` was `false` since 柱 P, so paseo/Zed never offered resume; implementing it surfaced three contracts.
- **Why**: (1) the schema streams history via notifications; paseo registers the native id BEFORE awaiting the load — result-first drops the history; (2) `session/new` returned `filepath.Base(cwd)` as sessionId — indexes no file, changes with the client's dir; (3) the ACP lane never persisted (TUI/print/rpc call `store.Save`).
- **Fix**: `session/load` runs inline in dispatch (replay+result share the write mutex); `cmd/seek/acp_replay.go` maps transcript→updates (system skipped; user/assistant → `*_message_chunk`; tool_calls/results → `tool_call(_update)`); `LoadSession`: load → `Repair()` → `AnchorSession(cwd)` → `subagent.ResolveRoute` → `*b.sess = *loaded` → `ag.Reset`; `NewSession` returns `session.ID`; `Initialize` advertises `LoadSession` iff a store exists; `Prompt` saves once per `agent.TurnEnd`.
- **Lesson**: a capability flag is a two-sided promise — `loadSession:true` means durable ids AND replay; read its ordered obligations and identity contract first.
