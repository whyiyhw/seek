### ACP session/load is an ORDER contract, and the id it loads must outlive the process
- **Saw**: `loadSession` was `false` since 柱 P (paseo/Zed never offered resume); turning it on surfaced three contracts.
- **Why**: (1) the schema streams history via notifications, and paseo registers the native id BEFORE awaiting the load — result-first drops it; (2) `session/new` returned `filepath.Base(cwd)` as sessionId — no file behind it, shifts with the client's dir; (3) the ACP lane never persisted (TUI/print/rpc call `store.Save`).
- **Fix**: `session/load` inline in dispatch (replay+result share the write mutex); `cmd/seek/acp_replay.go` maps transcript→updates (system skipped; user/assistant → `*_message_chunk`; tool_calls/results → `tool_call(_update)`); `LoadSession`: load → `Repair()` → `AnchorSession(cwd)` → `subagent.ResolveRoute` → `*b.sess = *loaded` → `ag.Reset`; `NewSession` returns `session.ID`; `Initialize` advertises `LoadSession` iff a store exists; `Prompt` saves per `agent.TurnEnd`.
- **Lesson**: `loadSession:true` is a two-sided promise — durable ids AND replay; read its obligations and identity contract first.
