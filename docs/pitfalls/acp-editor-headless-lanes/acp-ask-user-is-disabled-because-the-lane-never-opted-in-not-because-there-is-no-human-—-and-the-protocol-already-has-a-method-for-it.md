### ACP 的 ask_user 不是"没有人类"，是"没接协议"——而协议早就有

- **Saw**: 在 ACP 车道（Paseo / Zed 驱动）上让模型问用户一个选择题，工具结果永远是 `ErrDisabled`「rephrase as a plain-text question」，于是模型把问题写进正文、等一个可能永远不来的回复。第一反应是「无头车道没人类，这是对的」——但 ACP 车道**有**人类（就在编辑器里盯着），`/tmp/seek-acp.log` 里几千轮真实会话也证明客户端在线。
- **Why**: 两个独立事实叠在一起，各自看都合理、合起来是错的。①`askPolicy` 出生 `ModeDisabled`，只有 TUI 在 `cmd/seek/main.go:1916` 显式 `SetMode(ModeAsk)`；`runACP` 从来没有那一行——它是 v0.13.0 反转默认值时留下的正确遗留（把 `ErrNoCallback` 的"programming error"改成 `ErrDisabled` 的"改用纯文本"），对 print/rpc/goal 都对，**唯独对 ACP 错**，因为那些车道真没人类。②ACP schema 里早就有 `elicitation/create`（form 模式），由 `clientCapabilities.elicitation.form` 门控——我们没接，而 `docs/guide-zed.md` 当时写的是「要么等 ACP 出现 elicitation 类方法……两者都不在 seek 单侧可达范围内，故 backlog 里不立卡」。**协议已有，我们以为没有**。
- **Fix**: `internal/acp/elicitation.go`（wire 类型 + 解析 + nil-safe 能力闸）+ `cmd/seek/acp_askuser.go`（`askuser.Question` → form schema，回答 → `Answer`）+ `initialize` 里一行门控：申报了 `elicitation.form` 才 `SetMode(ModeAsk)`。没申报的客户端**逐字节维持旧行为**，所以既有的「ACP 报 ErrDisabled」用例不用改一个字。
- **Lesson**: 判断一条车道"该不该有交互"时，别用车道的名字（headless / acp / rpc）下结论，用车道的**能力申报**下结论——`initialize` 的 `clientCapabilities` 就是客户端在说"我能渲染什么"。另一个具体形状：schema 里 sub-capability 是**对象在场即支持**（`{"form":{}}` 是开，`null` 与省略都是关），所以 Go 侧必须解成 `*struct{}` 而不是 `bool`——`bool` 会把"未申报"和"声明为关"合并，而这个区别正是门控的全部内容。
- **Refs**: `internal/acp/elicitation.go`、`cmd/seek/acp_askuser.go`、`internal/acp/server.go`（`InitializeParams.ClientCapabilities`）、`docs/guide-zed.md` §5.7、`@agentclientprotocol/sdk` 1.9.0 `schema/types.gen.d.ts`（`CreateElicitationRequest` / `ElicitationCapabilities`）。旁证：同机的 zcode bridge 实现了同一条判断（`zcode-acp-server/dist/server.js:1313` `supportsElicitationForm()`）。
