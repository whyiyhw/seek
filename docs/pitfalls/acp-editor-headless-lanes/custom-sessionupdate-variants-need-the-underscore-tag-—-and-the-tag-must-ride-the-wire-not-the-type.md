### Custom sessionUpdate variants need the underscore tag — and the tag must ride the wire, not the type
- **Saw**: the `_seek_turn_stop` frame reached the client as `{"stopReason":…,"detail":…}` — no `sessionUpdate` discriminant; clients route by that tag (smoke grep times out).
- **Why**: ACP updates are tagged unions (`{"sessionUpdate":"agent_message_chunk","content":…}`); `acpUpdate` builds them as `map[string]any` with the tag inline — a typed struct with only the fields drops it. v2 reserves `_`-prefixed names for implementation-specific updates; v1-schema clients (current Zed) DROP unknown tags with a log line, not fail.
- **Fix**: `TurnStopUpdate` carries `SessionUpdate string \`json:"sessionUpdate"\`` buildable only via `NewTurnStop`; the wire-shape test asserts full JSON with tag-first ordering (c_vfgeam).
- **Lesson**: for a custom variant: `_`-prefix the name, constructor-pin the tag, assert exact wire bytes before wiring consumers, assume v1 clients drop the frame — put the client-critical subset on the spec-side surface too (the response `stopReason`).
