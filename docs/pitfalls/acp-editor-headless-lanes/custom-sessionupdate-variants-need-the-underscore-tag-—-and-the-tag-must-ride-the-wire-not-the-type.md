### Custom sessionUpdate variants need the underscore tag — and the tag must ride the wire, not the type

- **Saw**: the `_seek_turn_stop` termination frame reached the client as `{"stopReason":…,"detail":…}` — no `sessionUpdate` discriminant at all. Every client routes updates by that tag, so the frame was unmatchable (the smoke test greps for `_seek_turn_stop` and timed out; a JS client's switch just falls through).
- **Why**: ACP update objects are tagged unions — `{"sessionUpdate":"agent_message_chunk","content":…}` — and seek's existing `acpUpdate` builds them as `map[string]any` with the tag key inline. A typed struct payload that models only the fields silently drops the tag; Go struct→JSON has no idea a discriminator is required. Separately, the choice of tag matters: the v2 schema reserves `_`-prefixed names for implementation-specific updates (unknown names are reserved for future ACP versions), and v1-schema clients (current Zed) **drop** unknown tags with a log line rather than failing — ndJson lines are independent, so one dropped notification cannot corrupt the stream.
- **Fix**: `TurnStopUpdate` carries `SessionUpdate string \`json:"sessionUpdate"\`` and is only buildable through `NewTurnStop`, which pins the tag; the wire-shape test asserts the full JSON including tag-first ordering (c_vfgeam).
- **Lesson**: when adding a custom ACP update variant, (1) name it with the `_` prefix, (2) make the tag a constructor-pinned field of the typed payload — never rely on the call site to remember the map key, (3) assert the exact wire bytes in a test before wiring consumers, and (4) assume v1-schema clients drop the frame: put the client-critical subset of the information on the spec-side surface too (here: the response `stopReason`).
