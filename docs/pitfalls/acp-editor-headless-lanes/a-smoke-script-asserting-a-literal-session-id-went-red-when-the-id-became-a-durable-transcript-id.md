### A smoke script's assertion outlived the contract it pinned — `acp-smoke-test.sh` was red on a clean tree
- **Saw**: `bash scripts/acp-smoke-test.sh` failed at step 2 on an untouched checkout: `session/new: sessionId != smoke-ws`. The script asserted the session id equals the project directory basename and got `20261121-160649-b66397366242e24a`.
- **Why**: `session/new`'s id became the **durable transcript id** when `session/load` shipped (a project name can't be handed back to a later process), but the smoke script kept the pre-`session/load` assertion. Nothing in CI runs `scripts/*.sh` — they ride `scripts/selftest.sh`'s discovery list, invoked by the verification lane — so the drift surfaced only when a card happened to run the script.
- **Fix**: assert the id's **shape** (`^\d{8}-\d{6}-[0-9a-f]{16}$`, parsed as JSON rather than grepped) instead of a literal name, and say so in the comment. A client's requirement is "this string survives the process", which the shape check still covers; the exact value was never the contract. Card c_uzlczr found and fixed it while adding the context-window cases to the same script.
- **Lesson**: a smoke test that pins a **value** which another layer is allowed to redesign is a time bomb with no alarm — the alarm is a CI job, and this repo has none for `scripts/`. When the thing you pin is an identifier a client must round-trip, assert its *shape/format* and its round-trip behaviour, not its literal text. Generalisation: after changing a wire-visible string (an id scheme, a marker, a result prefix), grep `scripts/` and the eval runners in the SAME change — they are the surfaces that silently rot because they run on demand, not on push.
