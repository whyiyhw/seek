### Fake-LLM e2e scripting must discriminate on the LAST message, not on history
- **Saw**: a two-turn ACP e2e (acp_mode_e2e_test.go) stalled 60 s waiting for the turn-2 tool call: the fake answered "done." on turn 2's FIRST request, and a mode-reminder assertion kept matching turn 2 after the mode was switched back.
- **Why**: turn 2's first request legitimately carries turn 1's tool result in its history, so "body mentions a tool result" (or "[Mode: plan") is true of every later turn; history is immutable (prefix cache) — only the CURRENT turn's messages reflect current state. Corollary: `prefGate` classes an inside-cwd `write` as NOT dangerous (runs ungated).
- **Fix**: script the fake by the LAST message's role (fresh user turn ⇒ issue the tool call; ends in tool result ⇒ wrap up), assert per-turn labels on the LAST user message's content only, and expect inside-cwd writes ungated outside plan mode. c_cotikz.
- **Lesson**: a conversation-state assertion must name its message — "the current turn's user message", never "the request"; check `prefGate`'s dangerous-vs-safe split before promising a permission frame in a fixture.
- **Refs**: `cmd/seek/acp_mode_e2e_test.go` (`endsInToolResult`, `lastUserContent`), `internal/permission/permission.go` `prefGate`, `docs/guide-zed.md` §5.3.
