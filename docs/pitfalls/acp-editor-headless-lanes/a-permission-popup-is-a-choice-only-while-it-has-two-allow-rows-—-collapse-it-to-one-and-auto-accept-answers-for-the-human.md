### 权限弹窗「像选择题」靠的是两个同种 allow 行——折成一个，auto-accept 就会替人答题
- **Saw**: 给没有 `elicitation/create` handler 的 ACP 客户端（Paseo 0.17.4）兜问句通道，照 zcode 把多选题拆成「每项一对 Include/Skip」：无人值守宿主（butler drive 的 `paseo run`）把每对当普通 `[allow_once, reject_once]` 审批对，`auto_accept` 直接选 allow——模型收到「全选了」，人却没见弹窗。
- **Why**: `session/request_permission` 是 yes/no 门，客户端只看**选项形状**：Paseo 的 `isACPChooserRequest(options)` 仅在同一种 allow kind 出现**两次或以上**时为 true，`requestAcceptsAutoAccept` 挂其反面（chooser ⇒ 不代答）。折成一对即落进 auto-accept 默认路径；单选兜底安全，只因模型的 2–4 个选项天然给出 ≥2 个同种 allow 行。
- **Fix**: fallback 只承载单选（每题一 popup，各选项全 `allow_once` + 末尾 `seek:skip` 作 `reject_once`）；`multi_select:true` **不发帧**，回 `cancelled:true` + stderr 一行。实现 `cmd/seek/acp_askuser.go` 的 `askViaPermission` / `buildAskPermissionParams`；用例 `TestBuildAskPermissionParams`（allow_once ≥2）+ `TestACPAskUser_FallbackMultiSelectCancelled`（一帧没发）。
- **Lesson**: 借语义被钉死的协议方法，先找对方**怎么识别你要的用法**，再看形状是否稳定在其一边。「≥2 个同种 allow」既是 chooser 识别信号，也是 auto-accept 豁免条件——兜底不做多选不是偷懒，是唯一能保证「答案来自人」的形状。宁可 cancelled，不可伪造。
