### 空态会话头横穿侧栏——绝对定位没给主栏定位，空态类又只看实时列表

- **Saw**: 空态与「点开历史会话」下会话头从页面最左端起横穿 280px 侧栏盖住品牌行（W6-4 起）；手机宽压住 44px 图标轨，历史首条消息第一行也被盖。
- **Why**: ① `body.chat-empty-on #conv-head { position: absolute; left: 0; right: 0 }` 想贴主栏顶，但 `#center` 没定位，包含块落到页面，left/right 即页面两端。② `chat-empty-on` 只按实时 `#list` 判定；W6-5 看历史时列表空着，该类仍挂着，空态布局（会话头绝对化、内容居中、composer 上浮 64px）整套跟进历史视图。
- **Fix**: 空态给 `#center` 定位（仅非看历史态）；`body.viewing.chat-empty-on` 下会话头回文档流、内容顶对齐、composer 落回底部（c_mo7quv）。四态 × 两视口几何探针 + 32 张重拍。W6-4 同族另两处——空态开后台面板、开只读浏览器（W6-5 前的 `sess-detail`），会话头压在面板首行 / `#browser-head`——各补 `body.<视图>.chat-empty-on` 回文档流（0559af59 / d7229a27）。
- **Lesson**: 绝对定位先问「包含块是谁」——想在某栏贴边，那一栏就得定位。按单容器判的状态类，新增视图必须显式排除：「列表为空」≠「页面是空态」。这份让位清单没落笔，W6-4/W6-5 漏了三回（面板、只读浏览器、返工连带删掉面板让位规则）。挂会改共享骨架的 body 类前先 grep `classList.add`，把主区换面的类列全组合看；探针按同一清单枚举。Go 的字符串钉钉得住「规则在不在」，钉不住「还缺哪一态」。
