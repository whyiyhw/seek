### 新类名是旧类名加前缀——旧的单类规则会静默命中新元素

- **Saw**: W6-3 把消息统一成 `.msg.user / .msg.seek / .msg.hint`，旧的单类规则 `.seek { background }`、`.hint { font-style: italic }` 没删。页面测试绿、两轮截图过目没看出来；重验时对着 dsh 看 06/20 才发现每条助手回复整块灰底、系统灰行是斜体——`.msg.seek` 同时命中 `.seek`。
- **Why**: 旧选择器是新选择器的后缀，级联上互不冲突，「该删」不会以冲突暴露，只以样式不对出现在截图里；而过目的人看的是「元素在不在」，不是「哪条规则给的底色」。
- **Fix**: 删三条旧规则，`TestWeb_PageChatFlowW63` 钉住它们不存在（c_ovly6d 返工）。同一轮另两处同类问题：`.msg.user { align-self:flex-end }` 把整个 768 盒推出阅读列；`#sess-msgs` 自己的规则以同特异性后者胜出，盖掉容器规则的内边距。
- **Lesson**: 换类名词汇表时把旧类名 grep 三处——规则、标记、JS 拼的 className；给「旧规则不存在」加负向断言，正向断言证明不了它不在。截图过目要对着参考图量边（气泡右缘对阅读列右缘）。
