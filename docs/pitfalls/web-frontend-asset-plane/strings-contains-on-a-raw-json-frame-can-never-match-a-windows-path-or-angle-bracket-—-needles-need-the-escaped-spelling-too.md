### strings.Contains on a RAW JSON frame can never match a Windows path or angle bracket — needles need the escaped spelling too
- **Saw**: 2026-11-17/18 nightlies, Windows lane only: `TestWeb_CommandE2E` failed as `default frame …"text":"候选项目：\n• C:\\Users\\RUNNER~1\\…\\001…"} lacks "C:\\Users\\RUNNER~1\\…\\001"` — needle and haystack print identically.
- **Why**: the assertion runs `strings.Contains` on the raw SSE data line (Go-marshalled JSON, never decoded), where `\` rides doubled and `<`/`>`/`&` as `\u003c`-class escapes; a verbatim needle can match only after the same escaping. Invisible on `/`-path platforms: `/` and CJK need no escaping (the old "/bind usage" test hand-avoided `<` for this reason).
- **Fix**: `containsFrameText` (webfrontend_cmd_test.go) tries the verbatim needle, then its `json.Marshal`-escaped form (quotes stripped); `TestContainsFrameText` builds a Windows-shaped frame with the same Marshal so `/`-path lanes exercise it; card c_45npoi.
- **Lesson**: substring assertions on marshalled-JSON wire text are portable only via an escaping-aware matcher — or decode the frame first; new raw-frame helpers must go through `containsFrameText`, not bare `strings.Contains`.
