### 断点一换，方位文案就说谎——静态字符串钉永远抓不到
- **Saw**: W6 换骨架后，三处空态/提示仍写「点左栏的『新建』」「点侧栏头的『新建』」。桌面上勉强对（侧栏在、只是没有「新建」二字），390px 下侧栏是 56px 图标轨：`.lbl` 与 `#sess-list` 都 `display:none`，页面上既没有「左栏」也没有「新建」。
- **Why**: 文案是常量字符串，布局是媒体查询。`webPageSHA256` 与 `strings.Contains` 这类钉只能证明「这串字在文件里」，证明不了「它指的位置在这个宽度显示成这串字」。W6-2 把侧栏头改成「＋ 新会话」+ 三枚图标钮时，没人重新读一遍引用旧词的那几行。
- **Fix**: 去掉方位词，指向两种侧栏态下都在的图标（文件夹加号）：「未绑定——点文件夹加号图标选一个目录」。断言改成正反两面：新文案在场 + `点左栏` / `侧栏头的「新建」` 一类词不许再出现（`TestWeb_PageCopyFollowsLayout`，c_b6chn5）。
- **Lesson**: 文案里每个方位词/按钮字都是一条「布局契约」。布局卡动到断点时，grep 一遍旧词；要钉就钉**否定**（这个词不许出现），比钉新句子更能防回潮。
- **Refs**: `internal/controlplane/webfrontend.html`（`refreshState` / `renderSessRows` / `loadAgents` / `renderChatEmpty`）；`internal/controlplane/webfrontend_test.go`。

### 窄屏下拉截断：放宽 select 会把标题和计数吃掉——该改的是选项文案
- **Saw**: 记忆面板项目下拉在 390px 显示「f1eb7d5f · 3 条 · 1 ▾」——日期「11-22」被裁成「1」，读起来像条数。卡面建议「≤480px 放宽到 100%」。
- **Why**: 选项文案「id · N 条 · 日期」自然宽 182px，而 ≤480px 的 `.pane-bar select` 上限是 `38vw`（390px 下 148px）。放宽到 `max-width: none` 实测 184px：面板头里「记忆」标题 + 「3 条记忆」计数（右缘 161）会被 select（左缘 184→151）挤成 0–20px 宽、`.ch-l` 变可滚裁切；超长选项（3 位条数 + 跨年日期，235px）还会把面板头撑出横向溢出。
- **Fix**: 不动 CSS 上限，改文案：窄屏选项去掉日期（「id · N 条」= 131px，320/360/390 都装得下），宽屏照旧带日期；`matchMedia('(max-width: 480px)')` 的 `change` 就地重排同一份已取数据，不重拉 `memory/projects`（`TestWeb_PageMemoryPickerNarrow`，c_b6chn5）。
- **Lesson**: 截断类缺陷先量自然宽，再量容器让出来的那份空间属于谁——`38vw` 不是随手写的，是标题+计数+关闭钮之后的余额。能缩短文案就别抢别人的宽度。
- **Refs**: `internal/controlplane/webfrontend.html`（`memOptLabel` / `renderMemOpts`）；`docs/pitfalls/web-frontend-asset-plane/tolocalestring-是环境态…`（同族：文案/格式在窄容器的可见面）。
