### Explicit bash bans in prompts underperform tool-description guidance — measured
- **Saw**: on Windows cmd.exe the model built ONE bash command with `;` separators (`git log ...; echo ---; git log ...`) — cmd has no `;` separator: `fatal: ambiguous argument 'echo'`; it also duplicated the subcommand into git's `args[0]` (`{"subcommand":"show","args":["show","-s",...]}`).
- **Why**: the model transcribes shell lines wholesale; the tic surfaces as a git error, not a shell error — nothing to correct on. Prompt bans are instruction-following; descriptions ride the schema.
- **Fix**: git/bash descriptions mandate one query per call (no `;`/`&&` chains, no read-only git via bash, `--` before pathspecs); AGENTS.md rule 6 mirrors it. Metrics `bash_chains`/`bash_git_calls` + `git-multi-query-no-bash` case; measured (10+10): git-via-bash 6/10→1/10, chains 5/10→1/10, PASS 4/10→9/10.
- **Lesson**: a prompt-level ban still leaked a chained bash git call — the description moved the rate; a tic failing with an unrelated-looking error belongs in the tool description, not the prompt.
