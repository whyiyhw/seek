### Default-depth `list_dir` answers nothing about a tree — and its output never said so (bash-overreach alternation)
- **Saw**: `bash-overreach` red-green ALTERNATING on identical binaries since 11-13 (4 PASS / 7 FAIL; FAILs `list_dir ≤ 1, bash ≥ 1`, PASSes `list_dir=1, bash=0`) — misread by two cards as regression.
- **Why**: the prompt asks a recursive question; `list_dir` defaults `depth=1`, listing the 24 package dirs — neither count nor size, no `depth` re-call pointer, `bash find | wc` the visible recovery. Not drift (descriptions byte-stable since `f99707f`), not regression (born 2026-05-28 with EMPTY stubs, no green baseline).
- **Fix**: default-depth listings with subdirs now end `… N subdirectories not expanded at depth=1 — re-call with depth=2 (max 3) …` (`internal/tools/listdir/listdir.go`, card `c_lrilqc`). 2026-11-18: hint read, 2/5 green on `11b2366`, all 5 `list_dir` FIRST — residual is recovery-after-dedicated; recalibrated `max_bash_calls 0→1` + `max_bash_before_dedicated: 0` (`list_dir` = dedicated).
- **Lesson**: a `max_bash_calls=0` case answerable only with a NON-DEFAULT dedicated-tool argument is stochastic unless the default output names it. Read "failing since" against per-run rows on the SAME binary — alternation is flakiness, not regression.
