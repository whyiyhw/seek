### Eval prompts that demand verbatim quoting silently break when the target line crosses read's 1024-byte cap
- **Saw**: `tool-selection` (quote `const description` verbatim) failed `bash_calls 1–4` 3 months after last pass (grep×3→read×3, then bash); `bash-overreach` failed `bash_calls=2, list_dir=0`.
- **Why**: fixture drift: `bash.go`'s `const description` grew 384→1059 B, crossing `read`'s `maxLineBytes=1024` elision (`grep` truncates at 240) — no dedicated tool returns that line verbatim, so shell recovery is CORRECT. `bash-overreach`'s "fewest lines" question had no dedicated answer (`list_dir` prints bytes) → `find -exec wc|sort`.
- **Fix**: `tool-selection`: `max_bash_calls 0→4` (1 extraction + ≤3 word counts) + `bash_before_dedicated` 0 (ordering only); `bash-overreach`: second question → "smallest in bytes" (one `list_dir`) + clauses steering count-/size-questions off `find/wc/stat` (bash 2→1→0, `list_dir` 0→1).
- **Lesson**: a case quoting repo content is coupled to its SIZE: when `max_*_calls=0` breaks later, check whether a dedicated tool can answer (line caps, truncation) before blaming drift; prefer order-sensitive bounds over loosened totals.
