### A Tool decorator silently drops the optional interfaces the agent upcasts to
- **Saw**: the obvious decorator (one struct embedding `tools.Tool`, overriding `Execute`) compiles and passes its own tests while breaking two subsystems: `read`/`grep`/`list_dir` stop dispatching concurrently, `think` stops streaming — no error, just slower.
- **Why**: `pkg/agent` upcasts: `agent.go:915` to `tools.StreamingTool` (prefer `ExecuteStream`), `agent.go:996` to `tools.ReadOnlyTool` (parallel batch). Go has no delegation: a wrapper implements only its own methods, the embedded type erased at the interface boundary.
- **Fix**: `tools.WithRepeatGuard` returns one of FOUR concrete types by which optional interfaces the wrapped tool implements (plain / +ReadOnly / +Streaming / +both), tested per combination, including that a plain tool gains no `ReadOnlyTool` (which would let `write`/`bash` into the concurrent batch).
- **Lesson**: before writing a decorator, grep `.(tools.` for the union of upcasts — that, not the base interface, is the contract; prefer a capability-switching constructor over one wrapper type.
- **Refs**: `internal/tools/repeatguard.go:WithRepeatGuard`, `internal/tools/repeatguard_test.go:TestWithRepeatGuard_PreservesReadOnly`, `pkg/agent/agent.go:915,996`
