### POST /files 响应里没有 page_count / expires_at——按页计费与过期重传都拿不到数据
- **Saw**: F4 真 API 上传（2026-11-18）返回体只有 `{id, object, bytes, created_at, filename, purpose}`：`page_count`、`expires_at` 文档里写了、实际不发（`text_recognition` 与 `rich_layout_recognition` 两种 purpose 各传一次，同一 2 页 PDF，均缺）。后果：F3 的 `pricing.ParseCost(fo.PageCount)` 恒记 $0；F4 的过期重传因 `expires_at=0`（= 未声明过期）永不主动触发。
- **Why**: 上传响应是 FileObject 的最小子集，解析产物（页数）与生命周期（过期时间）都不在其中；也没有别的查询接口可用——原始文件与解析结果均不支持下载/回读。
- **Fix**: 语义不改：`0 = 未声明过期 = 不主动重传` 是有意的保守选择（宁可一个死 id 在发送时报错，也不要每轮重上传、重复计解析费）。烟测把字段缺失记为**读数**而不是失败，并在日志里点明后果（`files_smoke_test.go`）。**计费兜底（2026-11-19，卡 c_y2akdi）**：F3 路由缺 page_count 时改记 `pricing.EstimateParsePages(bytes)`（口径：`ceil(bytes÷104857)`，上限 1000 页——除数与上限都是 API 公布限制 100 MiB/1000 页推出的，不引入外部数据；上取整本身保证非空文件至少 1 页，故无下界 clamp；舍入在 int64 里做，MaxInt64 也不溢出——误差方向随格式漂，密文本 PDF 低估、扫描件高估），不再恒 $0；估算双面打旗（marker `~N pages·估` + `FilePart.PagesEstimated`）。没有读口可校正：`GET /files/{id}`（[检索文件](https://api-docs.deepseek.com/zh-cn/api/retrieve-file)）返回的 FileObject 同样只有 `id/object/bytes/created_at/filename/purpose[+expires_at]`，`GET /files`（[列出文件](https://api-docs.deepseek.com/zh-cn/api/list-files)）也是同一份字段表。F5「维持现状」决定就此作废——当时否决的是本地数页的脆弱解析，字节估算不是数页。resolve.go 复传路径仍不记费（expires_at 永不返回 → 路径休眠；API 补字段时需一并补 sink）。
- **Lesson**: 文档字段 ≠ 实际响应字段；凡是拿返回字段算钱的，真 API 首跑必须把原始响应体打出来核对。真页数拿不到时，第三条路不是只有「本地数页 / 等 API」——按官方自己公布的大小-页数上限做字节估算、并把「这是估算」打在每一个出口上，比记 $0 更接近账单（c_y2akdi 的选择）。
