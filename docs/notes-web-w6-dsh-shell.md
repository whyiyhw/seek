## 0. 为什么前两轮没把页面带对

W5（14 卡）按「能力映射」拆：markdown、侧栏、主题、审批卡、计量条……每张卡都在**旧骨架上叠一个能力**；11-22 的四张修复卡修的是渲染/响应式/图标/文案的**局部 bug**。骨架从来没换过，所以每张卡都通过了自己的验收，整页仍然不像 dsh。2026-11-25 用同一套沙盒截图对照（seek：`scripts/web-page-review.sh`；dsh：本机 clone `dsh --profile web`），差距全在骨架层：

| # | dsh（参考图） | seek 现状（main @ b5b38ec1） | 后果 |
|---|---|---|---|
| ① 字体 | 系统无衬线栈（PingFang SC），等宽只给代码 | `body { font: 14px/1.5 ui-monospace… }`——全页等宽 | 一眼像终端日志，这一条的观感影响最大 |
| ② 顶部 | **没有顶栏**；侧栏贴顶，主区只有一条会话头（标题 + 模式 + tab） | 三层横栏：`#status`（绑定路径/连接/计量）+ `#bar`（记忆/统计/后台/设置/审计）+ 面板头 | 内容下沉 80px，视觉重心散 |
| ③ 导航 | 侧栏：品牌 → 新会话 → 工作区树 → 底部「设置」；设置是**模态框** | 功能入口在右上角按钮，点了整块替换中栏，「聊天」按钮切回来 | 页面像几个工具拼起来的，不是一个应用 |
| ④ 会话 | 点会话 = 进入该对话，历史 + 输入框同一屏 | 点会话 = 只读浏览器（`#browser`），还要点「继续此会话」；实时流和历史各有一套渲染器（`addMsg/runBubble/onTool` vs `appendMsg*`） | 同一条消息两种长相，操作多一步 |
| ⑤ 对话流 | 768px 居中阅读列；用户消息是右侧浅蓝气泡；助手无框；工具调用是一行图标 + 名称 + 摘要 | 满宽灰底块，每条带 `user`/`assistant`/`tool · call_id` 角色标签，工具结果重复出现两次 | 信息密度高但难读 |
| ⑥ 输入区 | 居中圆角卡片（r=22）：输入框在上，底行 ＋ / 权限芯片 / 模型 / 圆形发送；卡片下一行「N 轮 · N 步」；空态时卡片居中配 Hero | 满宽单行输入框 + 三个独立按钮；未绑定时顶部黄条 | 没有焦点，空态不知道该干嘛 |

**本组的验收逻辑因此改变**：不只是「功能断言绿」，而是「换完骨架后截图和参考图摆在一起，结构一致」。每张卡都要**删掉被替代的旧标记和旧 CSS**——这一组是替换，不是叠加。

## 5. 每张卡共用的验收底线

- **动工前必读**：本文 + `notes-dsh-ui-spec.md` §a/§b + `feature-web-frontend.md` §13.6 两份设计规范（`.seek/skills/frontend-design.md`、`.seek/skills/ui-ux-pro-max/SKILL.md`），以及本卡点名的参考图（直接用读图工具看 PNG）。
- **截图对照**：`OUT_DIR=out/w6-<卡号> bash scripts/web-page-review.sh` 拍齐 32 张；与本卡点名的 dsh 参考图逐项比对，把比对结论（结构/间距/字号/颜色各一句）写进收工记录。「看着顺眼」不算过，按 §2 数值和 §1 骨架判。
- **零回归**：`go test -race ./...` 绿；被本卡改动影响的 `scripts/web-*-headless.mjs` 跑一遍（Chrome + node≥22 在本机可用）；改了哪个断言、为什么，写进 commit body。
- **体积**：本组是替换，**被替代的旧标记/旧 CSS 同卡删除**；`webfrontend.html` 单卡净增 ≤8KB（W6-2/W6-5 ≤12KB），超了在 `scripts/web-size-baseline.txt` 按既有格式记账；`bash scripts/web-gate.sh` 绿。
- **纪律不变**：纯 stdlib + go:embed、无构建链、无 vendor 新依赖、DOM 只用 createElement/textContent（§5.5 无 innerHTML sink）；人可读文案走现有中文；不新增常驻机制。
- **静态断言**：每张卡在 `internal/controlplane/webfrontend_test.go`（或同包新 `_test.go`）加对本卡骨架的字符串级断言（例：body 规则不含 `monospace`、`<nav id="bar"` 不存在、`#mem-btn` 位于 `#side-foot` 内），防止后续卡把骨架改回去。

## 6. 非目标

不抄 React / Cordis / 构建链；不做右侧 details 栏与拖拽调宽；不做「轨迹」tab；模型芯片只显示、不切换模型（切模型要动执行器，另立卡）；不改 SSE/RPC/鉴权协议——本组只动页面（W6-5 的懒 resume 复用现有 `/resume` 指令，不加服务端接口）。
