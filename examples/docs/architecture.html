Architecture & Design

设计与架构

How seek works under the hood.

seek 的底层工作原理。

1

Three-Tier Memory (L / M / S)

三层记忆 (L / M / S)

seek doesn't start from zero every session. Three layers of persistence capture knowledge at different timescales:

seek 不会每次会话从零开始。三层持久化以不同时间尺度捕捉知识：

  • Soul (L) — ~/.seek/soul.md. Cross-project user preferences and thinking habits. ~500 token hard cap, resident in system prompt. Written by seek -dream → user review.
  • Project (M) — ~/.seek/projects/<hash>/memory.jsonl. Key decisions and rationale per project. Index injected into every prompt; full content fetched on demand via memory_recall.
  • Session (S) — ~/.local/share/seek/sessions/<id>.jsonl. Full message history with auto-save. /distill at session end extracts reusable decisions into M.
📁 pkg/agent/memory/ · internal/memory/ · docs/guide-memory.md
2

Permission System

权限系统

Three modes control what the agent can do. Set at startup or toggled mid-session with /yolo or /plan:

三种模式控制 agent 的权限范围。可在启动时设置，也可在会话中通过 /yolo 或 /plan 切换：

  • ask (default) — Every filesystem write and shell command prompts for confirmation. Granular path whitelists available.
  • yolo (--yolo) — Bypass all permission prompts. Use in trusted environments or CI.
  • plan (--plan) — Read-only. Writes and shell commands are denied. Use for exploration.

Permission denials are tool results, not errors — the agent sees the denial message and asks the user, rather than crashing the loop.

权限拒绝是工具结果，而非错误——agent 看到拒绝消息后会询问用户，而非中断循环。

📁 internal/permission/
3

Tool System

工具系统

seek exposes tools to the LLM as JSON schema definitions. Current tools:

seek 以 JSON schema 定义向 LLM 暴露工具。当前工具列表：

  • read / grep / list_dir — filesystem exploration (grep first, read offset-limited segments)
  • write / edit — file mutation (edit requires exact old_string, unique match)
  • bash — shell execution (denied without --yolo)
  • fim_complete — DeepSeek-specific fill-in-the-middle (cheaper than chat for small gaps)
  • think — DeepSeek reasoning mode for planning and self-review
  • Skill — fetch a named skill's instructions and follow them
  • memory_observe / memory_recall / memory_amend / memory_archive / memory_remember — M-layer read/write

Key constraint: Tool schemas are []byte constants at package level (built once at init, not at call time). This ensures identical bytes across turns → DeepSeek's prefix cache hits.

关键约束：工具 schema 是包级别的 []byte 常量（在 init 时构建一次，而非每次调用）。这确保跨轮次的字节一致性，从而命中 DeepSeek 的前缀缓存。

📁 internal/tools/ · each tool in its own package with a New(...) constructor
4

Prefix Cache Optimization

前缀缓存优化

DeepSeek charges ~10× less per token on cache hits. The cache key is an exact byte sequence of the entire prior message history. This drives several architecture decisions:

DeepSeek 对缓存命中收取约 1/10 的价格。缓存键是完整历史消息的精确字节序列。这驱动了以下架构决策：

  • System prompt is immutable within a session — changing it invalidates the prefix cache for the entire history.
  • No in-transit message mutation — even "compression" of old tool results would break byte identity.
  • Token optimisation happens at write-time (tool output size limits), not at send-time.
  • Status bar shows real-time cache hit ratio + saved tokens, making cache-friendly prompts an observable optimisation target.
  • Off-peak countdown — 50% discount during 00:30–08:30 Beijing time, shown in the status bar.
📁 internal/pricing/ · pkg/deepseek/ (cache stats in API response)
5

Multi-Provider Layer

多 Provider 层

seek is DeepSeek-first but provider-agnostic. The architecture splits into two tiers:

seek 以 DeepSeek 为第一优先，但与 Provider 无关。架构分为两层：

  • pkg/deepseek — first-class client with DeepSeek-specific fields: cache metadata, FIM endpoint, reasoner content. Zero external dependencies.
  • pkg/llm — thin generic interface for Anthropic, OpenAI, Gemini, and OpenAI-compatible endpoints.

Critical rule (CI-enforced): pkg/deepseek must not import pkg/llm. DeepSeek-specific optimisations must never be lowered into a generic interface.

关键规则（CI 强制）：pkg/deepseek 不能导入 pkg/llm。DeepSeek 专属优化绝不能被降级到通用接口中。

📁 pkg/deepseek/ · pkg/llm/ · pkg/agent/ (type switch between tiers)
6

Session Persistence

会话持久化

Sessions are stored as JSONL files (schema_version=2):

会话以 JSONL 格式存储（schema_version=2）：

  • Line 1 — header with all scalar metadata (model, timestamps, token counts). loadMeta() reads only this line — no need to load the full file for the session list.
  • Lines 2..N — one deepseek.Message per line in JSON.
  • Auto-save after every turn. /branch forks to a new file; /compact summarises old history.
  • Durability: write-tmp-rename pattern with f.Sync() before f.Close().
