Autopilot — Unattended Orchestration

Autopilot — 无人值守编排

Decompose goals → parallel worktree agents → aggregate → local commit. Works while you sleep.

接收一个目标，分解为子任务，并行 spawn 隔离 worktree 子代理，聚合结果。

Quick Start

快速开始

$ seek autopilot run "重构 User 模型，添加邮箱验证字段"
→ [autopilot] 4/4 tasks succeeded
  User model: 添加 email_verified 字段 (abc1234)
  Service: 添加 verifyEmail 方法 (def5678)
  Tests: User + Service 单元测试 (ghi9012)
  Docs: 更新字段文档 (jkl3456)

How It Works

工作原理

目标
  └─→ Decomposer (DeepSeek) ──→ 任务列表
       ├─ 1. User model 字段
       ├─ 2. Service 方法
       ├─ 3. Test 用例
       └─ 4. 文档更新
       └─→ Fleet (并行 worktree 子代理)
            ├─ worktree-1 → edit → 本地 commit
            ├─ worktree-2 → edit → 本地 commit
            └─ ... → 报告: 摘要 + commit SHA

Safety Boundaries

安全边界

  • Read-only decompose — the decomposer step only reads files. No edits before user approval.
  • 只读分解——分解步骤只读文件，不写。
  • Worktree isolation — each sub-agent works in its own ephemeral git worktree. No cross-contamination.
  • Worktree 隔离——每个子代理在独立的 ephemeral git worktree 中工作。
  • No remote push — sub-agents cannot push / create PRs.
  • 禁止远程推送——子代理不能 push 或创建 PR。
  • OS level sandbox — when available, sub-agent bash is confined by the kernel sandbox (macOS Seatbelt / Linux Landlock).
  • OS 级沙箱——子代理 bash 受内核沙箱约束（macOS Seatbelt / Linux Landlock）。

CLI Reference

CLI 参考

$ seek autopilot run "<goal>"    # Full pipeline
$ seek autopilot run --dry-run "<goal>"  # Decompose only, review before execution
